# Source Map

This skill is a synthesis. No upstream source text or skill directory is
vendored here.

## Dice: The Hidden Cost of Vibe Coding

Source:
https://www.dice.com/career-advice/the-hidden-cost-of-vibe-coding-what-junior-developers-stop-learning

Ideas carried forward:
- AI can remove productive learning friction while still producing plausible code.
- Owning code means explaining the change, its rationale, its assumptions, its
  edge cases, and its failure behavior.
- Passing tests does not replace understanding the requirement and the system.
- Debugging, architecture reasoning, requirements interpretation, and judgment
  are skills worth keeping.

## Anthropic: How AI Is Transforming Work at Anthropic

Source:
https://www.anthropic.com/research/how-ai-is-transforming-work-at-anthropic

Ideas carried forward:
- AI can shift engineers from writing code toward reviewing and supervising it.
- Safe supervision still depends on experienced engineering judgment.
- Plausible generated solutions can be clever while still carrying hidden risk.

## Anthropic: Agentic Coding and Persistent Returns to Expertise

Source:
https://www.anthropic.com/research/claude-code-expertise

Ideas carried forward:
- Expertise stays visible in framing, verification, and correction.
- The skill therefore stresses precise questions, explicit evidence, and
  correcting unsupported assumptions.

## gstack

Source:
https://github.com/garrytan/gstack

Ideas carried forward conceptually:
- Ask one forcing question at a time.
- Push vague answers rather than accepting a fluent first response.
- Skip questions the available context already answers.
- Challenge the strongest important claim, not a weak strawman.

No gstack runtime, telemetry, prompts, or source files are copied into this
skill.

## BMad Method

Source:
https://github.com/bmad-code-org/BMAD-METHOD

Ideas carried forward conceptually:
- Structured elicitation can draw on first-principles reasoning, Socratic
  questioning, assumption audits, pre-mortems, failure analysis, and boundary
  sweeps.
- Refinement should be explicit rather than silently rewriting the person's
  work.

No BMad runtime or catalog is copied into this skill.

## GitHub Spec Kit

Source:
https://github.com/github/spec-kit

Relationship:
- Clarification asks what is ambiguous or underspecified.
- Cross-artifact analysis checks consistency across the artifacts produced.
- The plan walkthrough has a different role: it asks the plan owner to explain
  the consequential reasoning in their own plan or change.
