## Findings

WARNING tests/test_install_config.py:L307-309 — the assertion's failure message
tells a future fixer to run `uv run wfctl install-config github --force`, which
`wfctl/cli.py`'s `install_config_cmd` implements as bundle → repo-root only
(`shutil.copy2(item, dest)` where `dest = repo_root / item.relative_to(src)`, `src`
under `_bundle.BUNDLE_ROOT`). That overwrites the repo-root file with the bundle's
content. But the divergence this very test exists to catch (commit `77ea0c5`, cited
two lines above in the same docstring) went the other way: the repo-root copy — "the
one people actually edit" per the docstring itself — carried the newer text while the
bundle was stale. Following the message's own suggested command in that scenario
would silently discard the newer root edit and reintroduce exactly the bug #174
fixes, and the docstring already says as much ("re-seeding here would have replaced
the newer text with the older") without the message downstream heeding it. → Fix:
change the message to something direction-neutral, e.g. "`{rel}` has drifted between
the bundle and the copy wfctl ships — diff them, decide which is newer, and copy that
one over the other by hand (`install-config --force` only overwrites the repo-root
copy from the bundle, which is the wrong direction if the repo-root copy is the newer
one)."

No BLOCKER or NIT findings.
