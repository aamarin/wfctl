WARNING  wfctl/_pipeline.py:133 — the key is searched anywhere in the `Issue` cell, so a placeholder that happens to contain a digit reads as a created issue. Under the default `key_pattern` `\d+`, measured against the shipped helper: `| _(TBD)_ (Issue 1) |` → 0 unkeyed, `| TBD #1 |` → 0 unkeyed. Both are the exact state this check exists to catch, and no skill defines the placeholder spelling — `speckit-delivery-plan/SKILL.md` and `assets/delivery-plan-template.md` state only that the cell *"must lead with the tracker's native key"*; the observed `_(TBD)_` is a convention of one repo, not a documented one. The template's own row label suffix is `(Issue A)`, one keystroke from `(Issue 1)`. → match the cell's leading token, which is the contract the template already publishes: `cell = row.split("|")[1]; lead = (cell.split() or [""])[0]` then `key.search(lead)`. Checked against every case the tests pin: `#251 (Issue A)` ✓ keyed, `PROJ-4` ✓ keyed, `{issue-key} (Issue A)` ✓ unkeyed, and the two above flip to correctly unkeyed.

WARNING  wfctl/_pipeline.py:306-322 — the new gate keeps firing after the feature is finished, so a story can never report complete. `in_progress` at decompose makes `_current_step_name` return `decompose` for *any* downstream state.
