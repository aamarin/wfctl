### Findings

**BLOCKER**  `wfctl/agents/skills/opening-a-change/SKILL.md:47-51` — the rule this
change exists to install ("the panel's reconciled disposition table goes in the
PR body") ships as prose with nothing observing it, which
`a-rule-is-expressed-as-a-check` forbids.

That record is `status: accepted` and was accepted two commits earlier on *this
branch* (657c0f6, sharpened by d725770). Its test is one question: *is a violation
visible in an artifact the work already produces?* The record answers it for this
exact artifact — *"it includes the reply, the PR body, the diff and the tree."*
The body is a file on disk before `gh pr create` reads it, and `wfctl check-body
<path>` (`wfctl/cli.py:2895`) already runs over that file in Step 5, one step
after the section is filled. So the rule sits on the record's `yes` branch, and
the record's own words for what shipped instead are:

> Stating it correctly and delivering it reliably, with nothing observing what
> was written, is not a partial implementation of the rule — it is the rule's
> absence, documented.

The four new tests are precisely the *delivering it reliably* half. They assert
that wfctl ships the sentence and ships the section. None of them, and nothing
else in the tree, observes a single PR body.

Why this is a BLOCKER rather than a purity complaint: it reproduces #187. An
unattended run that skips Step 1 and writes `N/A` under `## Review Panel` (Step 4
explicitly permits that — see WARNING 3) reaches a PR, passes `check-body`, and
reports success. That is the same silence in a new place, which is the failure
mode the commit message itself names and claims to have closed.

Fix: express it. Extend `check-body` (or add a sibling check it calls) to require a
`## Review Panel` section carrying at least one non-blank table row and a
non-empty `roster:` line, and add a test that the check exits 1 on a body without
it. `check-body`'s docstring scopes it to "only the drawing rules" — that is a
statement of what it does today, not a constraint the record honours, and the
record deliberately leaves *which mechanism carries a check* undecided. What it
does not leave open is shipping none.

**WARNING**  `wfctl/agents/skills/opening-a-change/SKILL.md:47-48` and `:98-109` —
the mechanism only holds in a repo running wfctl's own template.

Step 1 says the table *"goes in the description under the section the template
gives it."* Only the template seeded by `wfctl install-config github` has that
section, and `install-config` is a separate seed-once command from
`install-skills` — the skill installs into repos that never run it. In any such
repo, Step 2 finds a template with no Review Panel section, Step 3's fallback
shape (`Summary · What changed · How it was tested · Issue links`) has none
either, and Step 1's instruction resolves to nowhere. The panel then runs and its
table is dropped on the floor, which is #187's visibility failure surviving the
fix one repo over.

Fix: Step 1 says where the table goes when the template has no section for it
(append a `## Review Panel` section), and Step 3's fallback shape gains it as a
fifth. Both are one line, and neither restates the project's section list — the
guard in `test_the_change_description_skill_does_not_restate_the_template` is not
in tension with this.

**WARNING**  `wfctl/agents/configs/github/.github/pull_request_template.md:152-156`
(and the identical `.github/` copy) — the scaffolding renders as an answer.

Two problems with the shipped block:

- The pre-filled empty row `|   |          |         |             |` and the bare
  `roster:` render on github.com as a structured table with one blank row and a
  dangling label. Left untouched that reads as *the panel produced nothing* —
  the ambiguity this section was added to remove. Every other section in this
  template uses one of two conventions Step 4 knows how to act on: a comment block
  (answered, then deleted) or a bracketed placeholder (replaced, not left). An
  empty markdown row is neither, so Step 4's rules do not reach it. Fix: bracketed
  placeholders — `| 1 | [r1] | [finding] | [applied / accepted / rejected — reason] |`
  and `roster: [r1 ✓ r2 ✓ r3 ✓]`.
- The panel skill's Step 6 output has a heading line above the table —
  `## Review panel: <target> — 3 reviewers, 4 findings` — and the template drops
  it. That count is what makes the panel skill's own last red flag ("a disposition
  table shorter than the number of findings collected") checkable by a reader.
  Give it somewhere to land.

**NIT**  `tests/test_opening_a_change_panel.py:42-44` — `next(i for i, t in ...)`
with no default raises `StopIteration` when a step title is renamed, so pytest
reports an error with a bare traceback instead of a failure naming the missing
step. Since this is the test that fails when the change is reverted, that is the
message the next reader gets. Fix:

```python
panel = next((i for i, t in enumerate(titles) if "review panel" in t), None)
assert panel is not None, titles
```

and the same for `body`.

duplicated scaffolding. `tests/test_skill_cross_references.py` is the established
home for "skill X names skill Y by path" and already carries the sibling
assertion for this same file
(`test_the_change_description_skill_defers_to_the_finishing_skill`) plus a
template-heading guard over the same template. The new module re-derives the
`files("wfctl")` root and re-imports `re`/`files`/`Path` to assert the same

still correct. Fix: move `test_opening_a_change_names_the_panel_skill_by_path`
beside its sibling and use `_REFERENCE`. The ordering and numbering tests are
genuinely new invariants and are fine where they are.
