## Findings

BLOCKER  `wfctl/agents/skills/start-session/SKILL.md:66-68` — the workflow layer still says
"delete it", and the change inverted which list it points at.

The surviving text is:

> `--prune` also clears paths a past install left behind when they were renamed upstream. It reaches
> only paths still on record; anything doctor lists **separately as no longer shipped** is a
> hand-delete it will name.

Before this diff that was accurate: both halves printed under the `no longer shipped` heading, and
the second remedy line was literally "Delete the rest by hand". After it, `no longer shipped` names
*exactly* the prune-reachable set, and the separately-listed set is the new dim `ℹ … not on record`
block whose own line says **"Left alone"**. So the sentence now (a) points at the wrong heading and
(b) is the last instruction in the repo telling an agent to hand-delete the paths #183 was filed to
stop naming as deletable. `/start-session` runs this step unattended (`--yes`), so an agent
resolving "listed separately" against the rendered output lands on the `ℹ` block — a user's
hand-placed skill — and deletes it. That is the exact loss the change exists to prevent, reinstated
one layer up.

Fix: rewrite the clause as two, one per block — `--prune` reaches the `⚠ … no longer shipped` list;
the dim `ℹ … not on record` list is not a finding, has no remedy, and is not to be deleted.
`CLAUDE.md` binds the verification here: a change touching `wfctl/agents/` "is not verified by the
test suite alone" — run `uv run wfctl install-skills` and read the rendered step.

WARNING  `wfctl/cli.py:3644-3672` — the mirror root *does* have evidence, and the new code spends it
anyway.

The docstring's own argument is "under `.agents/` there is nothing further to ask" — true there, and
the reason the fix is right for #183. But `scanned_only` is not scoped to `.agents/`. It also holds
`.claude/skills/<n>` paths, and there `_scan_owns` has already established ownership positively: it
returns True only when the base-layer twin `.agents/skills/<n>` exists, which its own docstring calls
"never the shape of a skill someone wrote themselves" and which
`test_doctor_does_not_report_a_claude_skill_the_user_wrote_themselves` (`tests/…:1063`) pins from the
negative side. A pre-flag mirror leftover — #110's case, un-mirrored by a wfctl ≤ v0.15.0 so the
record dropped it — now prints `Left alone — wfctl cannot tell yours from an old leftover`, which is
false for that specific path, and exits 0.

The docstring makes this worse rather than covering it: it says `_scan_owns` "filters where evidence
exists — the mirror root, where a base-layer twin settles ownership", and then discards the settled
answer three lines later.

Fix, either: partition `scanned_only` on `scanned == _CLAUDE_NATIVE_SKILL_ROOT` and keep the mirror
half in the warning/exit-1 branch — it is not on record, so it needs the hand-delete line rather than
`--prune`, and a hand-delete line is safe *there* because the twin is the proof; or, if the
simplification is a deliberate trade, say so in the paragraph that currently argues the opposite.

WARNING  `tests/test_install_skills.py` — the mixed case is untested, and it is the case the deleted
code existed for.

The diff removes branching whose only job was the both-halves run ("Remove the recorded one(s) …" /
"Delete the rest …"). Nothing replaces it with a test. Each half is now pinned alone
