## Findings

WARNING  wfctl/agents/skills/start-session/SKILL.md:68 — the skill still tells the
session agent that "anything doctor lists separately as no longer shipped is a
hand-delete it will name". That sentence described the removed
`"Delete the rest by hand once you've checked nothing needs them."` line. After this
change doctor lists nothing separately as a hand-delete; the only separate listing is
the new dim "not on record … Left alone" block, whose paths are the user's own files.
`/start-session` runs this step unattended, so the stale sentence points an
unsupervised agent at exactly the deletion #183 exists to prevent. → rewrite the
sentence: doctor now lists unrecorded paths informationally, they are not wfctl's to
delete, and `--prune` reaches only flagged records. CLAUDE.md notes changes under
`wfctl/agents/` are not covered by the suite, and nothing here caught it.

WARNING  wfctl/cli.py:3684 — the flagged half's repair line prints a bare
`wfctl install-skills --prune`, which cannot reach a flagged path in an agent layer.
`install_skills_cmd` computes orphans as `for layer in items` (cli.py:2268) and `items`
holds only the layers this run installs; with `--agent` omitted that is `base` only
(cli.py:1775, "Omit to install .agents/ only"). So for a flagged
`.claude/commands/test-cmd.md` — the exact path the new test at
tests/test_install_skills.py:1174 asserts on — the printed remedy is a no-op and doctor
keeps exiting 1 forever. The new test asserts the *string* is printed but never that
running it clears the finding; the mirror test at tests/test_install_skills.py:1157
passes only because it runs `--agent claude --prune` by hand. Pre-existing, but the diff
rewrites this line, `_agent_flag` (cli.py:1184) exists for precisely this ("The
`--agent` a repair command needs to reach this layer"), the stale-skills branch already
uses it with a comment about `/start-session` running the line unattended, and the
skill instructs "once per reported layer" — a layer the line never names. → group the
flagged paths by layer and print `wfctl install-skills{_agent_flag(layer)} --prune` per
layer.

WARNING  wfctl/cli.py:3655-3665, 3682 — paths are interpolated into rich markup
unescaped, and the new dim block wraps them in `[dim]…[/dim]`. This repo already fixed
this bug and documented it twice: cli.py:3823 ("Bracketed directory names are legal and
parse as rich style tags, so an unescaped `/x/[old]/wfctl` prints as `/x//wfctl` — a
different path, with nothing said about it") and the neighbouring
`_check_managed_hooks` escapes every path it prints (cli.py:3520). A directory named
`.agents/skills/[draft]-thing` prints as `.agents/skills/-thing`, and inside the dim
block a stray tag also breaks the styling that is the only signal separating the two
verdicts. Naming the path is the entire job of this block. → `from rich.markup import
escape` at the top of the function (the file's local-import convention) and wrap both
path prints, and the flagged one while the lines are being touched.

WARNING  wfctl/cli.py:3556 — the docstring summary still reads "Report entries wfctl
installed and no longer records." That is now true of only one half; the scanned half is
explicitly the half wfctl *cannot* claim it installed, which is the whole change. The
