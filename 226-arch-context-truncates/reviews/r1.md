## Findings

WARNING  wfctl/_arch.py:302 — an unclosed fence projects the whole rest of the record → bound the body to a real closer

`takewhile(lambda ln: not ln.strip().startswith(fence), rest[1:])` runs to end of
file when no closer is found, and the comment on 303-304 then re-emits a synthetic
one. Measured, on a record whose Decision fence is left open:

```
'Env:\n\n```\nX\n\n## Considered\n\nlots of\nreasoning here\n\n## Log\n\n- a\n```'
```

`## Considered` and `## Log` are projected as the decision. That is exactly the
"buries the ten records around it" outcome the docstring rejects option (c) for,
reachable from one missing backtick, and nothing detects it — the corpus test
passes (the text no longer ends in `:`) and no assertion bounds the length. The
comment claims to handle "a record whose fence runs to end of file"; it handles
the *rendering* of that case and not the case.

Fix, and it is `_pointed_at`'s own stated policy ("Empty otherwise, and that is
the finding") applied to one more shape:

```python
    if fence in ("```", "~~~"):
        body = list(takewhile(lambda ln: not ln.strip().startswith(fence), rest[1:]))
        if len(body) == len(rest) - 1:
            # No closer: a typo, not a block. The colon stays dangling, which is
            # what the corpus check is for.
            return []
        return [rest[0], *body, fence]
```

The comment three lines up says filling the block "would reflow the alignment
that is its content", and the sibling comment at 794-797 already records that
