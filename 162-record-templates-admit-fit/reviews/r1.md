## Findings

**WARNING** `wfctl/agents/skills/architecture-decisions/SKILL.md:129-134` — the
grandfather clause is phrased more broadly than the rule it claims to derive
from, and silently leaves 6 pre-existing `proposed` records unaddressed.

The clause reads: *"a record written before a section existed does not carry
it, and is not backfilled."* That's introduced as a consequence of the
immutability rule ("That rule outranks the section list") — but the
immutability rule (`status: accepted → superseded|retired`, body frozen) only
governs **accepted** records. `docs/architecture/` currently has 6 records at
`status: proposed`
(`brainstorm-is-one-step-with-addressable-levels.md`,
`drift-is-measured-against-the-recorded-source.md`,
`io-owns-durability-not-domain-files.md`,
`mirror-supersedes-the-wrapper.md`,
`the-underscore-is-the-module-contract.md`,
`tracker-owns-the-issue-key-shape.md`) that also predate `Direct baseline` and
also lack it — verified by grep. Proposed records are *not* frozen; nothing
stops them from being edited before acceptance, so the immutability argument
doesn't reach them. As written, the general sentence reads as if they're
grandfathered too, which means one of them could clear the Verification
checklist's "`Direct baseline` describes the no-new-structure option…" item on
a technicality and go straight to `accepted` without ever having one — the
exact defect this issue exists to close, reappearing through the loophole meant
to handle old records.

This is a scope gap relative to what the issue asked for, not a bug the issue
described: #162's own "Not just a template edit" section and DoD only mention
"eight accepted records," so the diff satisfies the issue's literal ask.
Flagging as WARNING because the fix, as worded, has follow-on room to be
misread by exactly the kind of agent this skill governs. Concrete fix: scope
the sentence to accepted records explicitly (e.g. "*an accepted* record written
before a section existed…") and add one line saying a `proposed` record still
picks up `Direct baseline` before it can be moved to `accepted`, since a
`proposed` record's body isn't frozen the way an accepted one's is.

**NIT** `wfctl/agents/skills/architecture-decisions/SKILL.md:150-151` — "the
true reason it was not chosen — fit counts, and beats a fault the alternative
lacks" is a hard sentence to parse on first read (what beats what?). The
template's own prose two lines below states the same point more clearly
("`equally good`... is truer than a weakness it does not have"). Consider
mirroring that phrasing in the checklist item instead of the compressed form.
Author's call — matches the file's existing dense style elsewhere.
