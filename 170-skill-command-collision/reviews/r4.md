## Findings

WARNING  wfctl/cli.py:L1287-1291 — the reworded `opening-a-change` comment ends
"and the wrapper that used to carry the typed route has to be written back with
it." That is false. The wrapper was never removed: `wfctl/agents/commands/opening-a-change.md`
still ships, and suppression is keyed on set membership, so dropping the name
from `_MIRRORED_SKILLS` un-suppresses the wrapper on the very same run — nothing
has to be written back. The sentence reads as a leftover from the
delete-the-wrappers version of this change, and it points a future maintainer at
a restore step that does not exist. → replace the clause with something like
"…and the wrapper that carries that route comes back to the Claude layer on its
own, because suppression is keyed on this set."

WARNING  tests/test_install_skills.py:L360-363 — `test_bob_keeps_the_wrapper_for_a_mirrored_skill`'s
docstring says "This is the test that fails if someone 'simplifies' the
suppression by deleting the seven wrappers from the bundle instead. Three
reviewers found that regression by reading the diff; nothing in the suite caught
it." The first sentence is not true and I proved it: conftest's autouse `bundle`
fixture repoints `_bundle.BUNDLE_ROOT` at a synthetic tree, and this test writes
its own `native-skill.md` into it, so the real `wfctl/agents/commands/` is never
read. I deleted `fanning-out-code-review.md`, `opening-a-change.md`,
`receiving-code-review.md` and `worktree-handoff.md` from the real bundle and all
838 tests still passed. Only `i-have-adhd` and `conversation-response-shape` are
protected, by `test_each_output_style_skill_is_typeable_on_every_layer` in
tests/test_skill_cross_references.py — 2 of the 7. So the diff's headline
regression is still 4/7 uncovered while a docstring asserts it is closed, which
is the same shape of silent gap that let the first version through. The test
itself is fine (it pins the `agent in _AGENT_SKILL_EXTRAS` guard, and fails
without it) — the claim is what is wrong. → either correct the docstring to say
what it really pins, **or** add the real-bundle assertion. Cheapest durable
form, beside the existing `test_every_declared_mirror_names_a_shipped_skill`
which already reads the installed package rather than the fixture:

```python
_MIRRORED_SKILLS_WITH_WRAPPERS = frozenset({
    "conversation-response-shape", "fanning-out-code-review", "i-have-adhd",
    "opening-a-change", "receiving-code-review",
```

NIT  wfctl/cli.py:L1971 and L1376-1404 — `layer == agent` is load-bearing (the
mutation table above: without it the seven wrappers vanish from
`.agents/commands/` too, which is the canonical layer codex reads and the one
every wrapper body points at), but it sits at the call site while the docstring
that states the contract sits in the function and never names the precondition.
The function's first line claims to answer "should this agent's *own* command
layer skip `item`?" and it cannot — the caller answers half of it. → take the
layer: `def _mirror_supersedes_wrapper(layer: str, agent: str, src_rel: str,
item: Path) -> bool: return layer == agent and src_rel == "agents/commands" and
…`. One argument, and the guard can no longer be dropped by a second caller.

NIT  wfctl/cli.py:L1401 — `src_rel == "agents/commands"` cannot discriminate

Keep it — it is what makes the docstring's forward-compat promise safe — but
nothing pins it, and a test that adds a fake agent to both `_AGENT_TARGETS` (with
a skills *and* a commands target) and `_AGENT_SKILL_EXTRAS` would.

NIT  wfctl/cli.py:L1396-1398 — "An agent added to that table later inherits the

## Things I checked and found clean

- **Scope of the predicate.** Correct in both directions. All seven suppressed
  files are pure five-line wrappers with no content of their own (I read all
  seven); no substantive command shares a mirrored name.
- **`--agent none` / `codex` / `copilot` / `bob`.** `none` and `codex` have empty
  `_AGENT_TARGETS`, so no agent entry ever reaches `layered` and `layer == agent`
  is never true; `copilot` has no commands target at all; `bob` is excluded by
  `agent in _AGENT_SKILL_EXTRAS` and verified by real install. `agent` defaults
  to `"none"` and is validated against `_AGENT_TARGETS`, so it can never equal
  `_BASE_LAYER`.
- **Manifest / prune / uninstall / backup attribution.** The suppressed paths
  fall out of `installed_paths`, become `orphans` of the `claude` layer, are
  kept on record with `{**item, "orphaned": True}` — which carries the `backup`
  pointer forward — reported by name, deleted by `--prune` with the user's
  original restored, and reachable by `uninstall-skills` (it iterates `items`
  with no `orphaned` filter). Exercised end to end, including the backup restore.
- **Doctor.** `.claude/commands` is not in `_scanned_dirs`, so the scan half is
  untouched; the seven arrive through the `flagged` half exactly as the new
  paragraph in `_scanned_dirs`'s docstring says. That paragraph is accurate.
- **Behavioral loss from dropping the wrapper on Claude.** None: both
  output-style skills carry their own `## Persistence` section, so the wrapper's
  "apply for the rest of the session" is not the only place that rule lives, and
  `start-session` loads both by path rather than by slash command.
- **Architecture records.** No conflict. `layer-model`'s "Everything else reaches
  the agent as a slash command only" is about *non*-mirrored skills and stays
  true; `vendor-upstream-skills` is respected (nothing edits `i-have-adhd`); the
  new record's "Owns truth" restates `layer-model`'s "`install-skills` owns what
  lands in each layer" rather than contradicting it. `_check_arch_records` only

  where a skill is not typeable as `/name` — is stated in the record, has no

  recorded observation rather than adding a check.
- **Style.** Comments explain *why this shape*, matching the project's density
  rule; test names are sentences and docstrings name the failure — the two
  docstring defects above are factual, not stylistic. `ruff` and `mypy` clean;
  no new untyped defs.
