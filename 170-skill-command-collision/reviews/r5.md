## Findings

### BLOCKER — cli.py:3618–3646 (`doctor_cmd`) — the fix does not reach any existing install, and doctor reports green while the collision is still on disk

`doctor`'s staleness check is `entry["content_hash"] == _bundle.content_hash(BUNDLE_ROOT)`, and `content_hash` covers the bundle tree (`wfctl/agents/`, `wfctl/specify/`). **This diff changes no bundle file.** So a repo that ran `install-skills --agent claude` with a pre-fix wfctl and then upgrades to the fixed one gets an identical bundle hash, and doctor says nothing:

```
$ WFCTL_REPO_ROOT=<repo with .claude/commands/worktree-handoff.md on disk and on record> uv run wfctl doctor
✓ wfctl 0.16.0 — latest
✓ base: skills current (wfctl 0.16.0)
✓ claude: skills current (wfctl 0.16.0)
EXIT=0
```

`_check_abandoned_entries` cannot cover it either: its `flagged` half only reports items already carrying `orphaned: True` (a flag *an install run* writes), and its scan half deliberately excludes `.claude/commands` (`_scanned_dirs`). So the seven wrappers are invisible to every read-only check.

That closes the only loop that would repair an existing repo. `start-session/SKILL.md:40–46` gates the repair on a doctor finding — "**If it reports any layer's skills behind or drifted**, bring them level now … `wfctl install-skills --prune --yes --agent claude`". No finding, no run, no prune. A fresh worktree is fine (nothing pre-existing to orphan); the affected population is exactly the long-lived checkout where #170 was observed.

Two artifacts assert this case is handled, and both are only true *given* an install run that nothing schedules:

- `cli.py:3221` — "A name it suppresses leaves `.claude/commands/<name>.md` behind on the install that adds it, and that one is caught as a recorded path this wfctl no longer ships."
- `docs/architecture/mirror-supersedes-the-wrapper.md:79` — "keeps it until the next run, which reports it … and offers `--prune`; `/start-session` already passes that flag."

Fix (any of, cheapest first):
1. Add a targeted check to `_check_abandoned_entries`: for each recorded item whose path is under an `_AGENT_TARGETS` command destination for a layer in `_AGENT_SKILL_EXTRAS`, report it when `Path(path).stem in _MIRRORED_SKILLS`. This meets that function's own evidence standard — "Being in the record is what makes a path wfctl's" — and needs no scan of shared ground.
2. Failing that, make the release that carries this fix also change a bundle byte, and say in the record that the repair depends on it. This is implicit coupling and I'd not ship it as the plan.

Do not "fix" it by pruning unconditionally in `install-skills`: that breaks the report-then-prune contract the surrounding comments defend at length.

### WARNING — tests/test_install_skills.py:317–345 — the test that claims to be the guard against the earlier wrong fix cannot detect it

`test_bob_keeps_the_wrapper_for_a_mirrored_skill`'s docstring:

> This is the test that fails if someone "simplifies" the suppression by deleting the seven wrappers from the bundle instead.

It cannot. The autouse `bundle` fixture repoints `_bundle.BUNDLE_ROOT` at a fake tree, and the test then *writes its own* `native-skill.md` into it. Deleting `wfctl/agents/commands/{worktree-handoff,opening-a-change,…}.md` from the real package leaves this test green.

What actually guards the real tree is `test_each_output_style_skill_is_typeable_on_every_layer`, and it covers **2 of the 7** names (`i-have-adhd`, `conversation-response-shape`). `fanning-out-code-review`, `opening-a-change`, `receiving-code-review`, `verification-before-completion` and `worktree-handoff` have no test asserting their wrapper still ships — `test_every_referenced_skill_ships` only walks references *out of* files, so deleting a wrapper does not trip it either.

CLAUDE.md: "docstrings say *why the test exists*, usually naming the failure it caught." This one names a failure it does not catch.

Fix: in `tests/test_skill_cross_references.py` (which reads the real tree through `files("wfctl")`), pin the set:

    from wfctl.cli import _MIRRORED_SKILLS

### WARNING — no test covers the upgrade path, which is the only path any existing repo takes

Three new tests cover a *fresh* install. Nothing covers: a recorded `.claude/commands/<mirrored>.md` from a prior install → orphan report → `--prune` → backup restore. That path is where every real user meets this change, and it is where the backup bookkeeping can go wrong (the layer entry is *replaced* wholesale each run, so a lost `backup` pointer would strand a user's overwritten file under `.wf-skills-backup/` forever).

I exercised it by hand and **it is correct today** — recording the evidence so the finding is scoped to the missing test, not to a live defect:

| step | result |
|---|---|
| install, then hand-add `.claude/commands/worktree-handoff.md` to disk + claude manifest with a `backup` pointer, then re-install | `⚠ 1 path a previous install recorded is no longer shipped … .claude/commands/worktree-handoff.md` — file left on disk, entry re-recorded with `orphaned: true`, **`backup` pointer preserved** |
| `doctor` after that install | `⚠ 1 installed path is no longer shipped … Remove it with wfctl install-skills --prune` |
| re-install ×3 without `--prune` | claude items stay at 31 (30 + 1 orphan) — no duplication, pointer intact |
| `install-skills --prune` | `ℹ Pruned 1 path(s) … 1 of them held a pre-existing file wfctl had overwritten, and it was put back`; file on disk is the user's original |
| `uninstall-skills --agent claude` on the un-pruned repo | `✓ Removed 30 item(s), restored 1 pre-existing file(s)`; user's original back at `.claude/commands/worktree-handoff.md` |

Fix: one test in `tests/test_install_skills.py` that installs for claude with a wrapper name *not yet* in `_MIRRORED_SKILLS`, adds it to the monkeypatched set, re-installs, and asserts (a) the path is reported and stays recorded with its `backup` carried forward, (b) `--prune` removes it and restores the backup. This is the new orphan *shape* — the existing orphan tests all rename the base source too, so the base twin disappears with the agent copy; here the base twin survives, which is what the `_scanned_dirs` edit is arguing about.

### NIT — cli.py:1376 / cli.py:1971 — half the rule lives at the call site

```python
if layer == agent and _mirror_supersedes_wrapper(agent, src_rel, item):
```

`layer == agent` is load-bearing: without it the base layer's `agents/commands` → `.agents/commands` copy matches `src_rel == "agents/commands"` and every wrapper would vanish from `.agents/` too — the failure `test_the_mirror_suppresses_the_wrapper_it_collides_with`'s `.agents/` assertion exists to catch. But the function's docstring says it decides ("Whether **this agent's own command layer** should skip `item`") while it never sees `layer`. A future second caller gets a predicate that silently means something broader.

Fix: `def _mirror_supersedes_wrapper(layer: str, agent: str, src_rel: str, item: Path) -> bool:` with `layer == agent` as the first clause; call site becomes `if _mirror_supersedes_wrapper(layer, agent, src_rel, item): continue`.

### NIT — cli.py:1400–1404 — suppression and mirroring are keyed on different predicates

Suppression fires on `item.stem in _MIRRORED_SKILLS`. The mirror only materialises when `_claude_native_skill_mirror` also finds `agents/skills/<name>` on disk as a directory. A name in the set with a shipped wrapper but no shipped skill directory would therefore lose the wrapper and gain nothing — unreachable on the Claude layer. Today `test_every_declared_mirror_names_a_shipped_skill` makes that unreachable, so this is latent, not live. Worth one clause in the docstring naming that test as the thing holding the two predicates together, since the function's own text argues the keying is what makes it correct.
