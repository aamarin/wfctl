### WARNING — `tests/test_install_skills.py:L360`: the bob test does not catch the regression its docstring claims

The docstring says:

> This is the test that fails if someone "simplifies" the suppression by deleting the seven wrappers from the bundle instead. Three reviewers found that regression by reading the diff; nothing in the suite caught it.

It still doesn't. The test writes its own `native-skill.md` into the `bundle`
fixture tree (`wfctl._bundle.BUNDLE_ROOT` is monkeypatched away by the autouse
`bundle` fixture), so `wfctl/agents/commands/*.md` — the files the rejected fix
would have deleted — are never read by it.

Measured, in a `mktemp -d` copy of the repo:

| Mutation | Result |
|---|---|
| `rm wfctl/agents/commands/{fanning-out-code-review,opening-a-change,receiving-code-review,verification-before-completion,worktree-handoff}.md` | **838 passed** |
| additionally `rm wfctl/agents/commands/{i-have-adhd,conversation-response-shape}.md` | 1 failed — `test_each_output_style_skill_is_typeable_on_every_layer` |

So five of the seven wrappers can be deleted from the bundle, taking bob's only
typed route to those skills with them, and the suite is green. Only the two
output-style names are protected, and by a *different* test in a different file.

The docstring is the load-bearing part here: this repo's convention is that a
docstring names the failure the test caught, and a reader who trusts this one
will believe the rejected fix is fenced off when it is fenced off for 2 of 7.

Fix — either correct the prose, or add the shipped-tree assertion next to the
one that already exists (`tests/test_skill_cross_references.py`, which reads the
real `_AGENTS` tree for exactly this reason):

```python
def test_every_mirrored_skill_that_ships_a_wrapper_still_ships_it() -> None:
    """The wrapper is the typed route on every layer that gets no mirror — bob's
    only one, since `.bob/skills/` keeps `disable-model-invocation` and
    `.bob/commands/` is where it is stripped. #170's first fix deleted these
    seven from the bundle; the suppression tests all build their own wrapper in
    the fixture bundle, so nothing else here reads the shipped files."""
    from wfctl.cli import _MIRRORED_SKILLS
    # Three mirrored skills ship no wrapper and never did; the rest must.
    expected = _MIRRORED_SKILLS - {
        "architecture-decisions", "design-levels", "using-superpowers",
    }
    missing = sorted(n for n in expected if not (_AGENTS / "commands" / f"{n}.md").exists())
    assert missing == []
```

A frozen exclusion list is the right shape here rather than a derived one: the
asymmetry (three mirrored skills with no wrapper) is a fact about the tree that
nothing else records, and deriving it from the tree would make the test assert
whatever the tree happens to say.

### WARNING — `wfctl/cli.py:L1376`: the predicate is content-blind, and a future `_MIRRORED_SKILLS` entry can drop a wrapper that carries more than a pointer

`_mirror_supersedes_wrapper` suppresses on name alone. That is safe today
because all seven suppressed wrappers are pure pointers whose frontmatter is
only `description` + `disable-model-invocation` — I read all seven. It is not
safe as a rule, and the diff adds no guard.

`wfctl/agents/commands/start-session.md` and `end-session.md` carry an
`allowed-tools:` pre-approval list. Neither
`wfctl/agents/skills/start-session/SKILL.md` nor its sibling carries one.
Adding `"start-session"` to `_MIRRORED_SKILLS` — an obviously reasonable future
change, given it is the most-typed command in the tree — suppresses
`.claude/commands/start-session.md` and takes the pre-approval with it. Every
`wfctl status` / `git log` call in that skill then prompts.

Verified: with `"start-session"` added to the set in a scratch copy, **838
passed**. `test_every_declared_mirror_names_a_shipped_skill` is satisfied (the
skill directory exists), and nothing else looks.

This is the diff's answer to "can someone add a name and break something
silently", and right now it is yes. Fix — one test, in
`tests/test_skill_cross_references.py`, that pins the precondition the
suppression relies on:

```python
def test_a_suppressed_wrapper_carries_nothing_its_skill_lacks() -> None:
    """`_mirror_supersedes_wrapper` drops a wrapper on name alone, so a mirrored
    name whose wrapper carries frontmatter the SKILL.md does not — `allowed-tools`
    is the live case, on start-session and end-session — would lose it on the
    Claude layer with no error. Every suppressed wrapper must be a pure pointer."""
    from wfctl.cli import _MIRRORED_SKILLS
    allowed = {"description", "disable-model-invocation"}
    for name in sorted(_MIRRORED_SKILLS):
        wrapper = _AGENTS / "commands" / f"{name}.md"
        if not wrapper.exists():
            continue
        keys = {ln.split(":", 1)[0].strip()
                for ln in wrapper.read_text().split("---")[1].splitlines() if ":" in ln}
        assert keys <= allowed, f"{name}: {sorted(keys - allowed)}"
```

Alternative, if you'd rather the code refuse than a test warn: have the
predicate return False when the wrapper's frontmatter carries a key outside that
set. I'd take the test — the installer refusing silently is how #170 happened.

### NIT — `wfctl/cli.py:L1387`: the docstring's guarantee lives at the call site

> Suppressed per layer, never from the bundle, and that distinction is the whole
> correctness of this function.

The distinction is not in this function. The function returns True for the base
layer's `agents/commands` too; only `layer == agent` at L1971 keeps the base
copy. A caller who reads the docstring and trusts it gets the worst available
outcome: I reproduced it, and with `--prune` the base wrappers are *deleted* —
`base 33 skills · 20 commands`, `.agents/commands/worktree-handoff.md` gone,
which is every layer's route at once.

The suite does catch that exact mutation (the `.agents/` assertion in
`test_the_mirror_suppresses_the_wrapper_it_collides_with` fails), so this is
clarity, not a defect. Fix: fold it in, so the function means what it says.

```python
def _mirror_supersedes_wrapper(layer: str, agent: str, src_rel: str, item: Path) -> bool:
    return (
        layer == agent
        and src_rel == "agents/commands"
        and agent in _AGENT_SKILL_EXTRAS
        and item.stem in _MIRRORED_SKILLS
    )
```

### NIT — `tests/test_skill_cross_references.py:L73`: the second assertion guards a different property than the test's name

`assert name in _MIRRORED_SKILLS` does not protect typeability. Drop a name from
`_MIRRORED_SKILLS` and its wrapper stops being suppressed, so `/name` stays
typeable on the Claude layer — the route changes, the property doesn't. What
that assertion actually protects is *model* discoverability (#99 for
`conversation-response-shape`, #124's shape generally), which is worth pinning
and is a different thing from what the test is named for.

The docstring's "every layer needs a route to it… Both halves asserted" reads as
if removing the mirror half would cost a layer its typed route. It wouldn't.
Both assertions do earn their place — I confirmed the wrapper half fails when
either output-style wrapper is deleted — so keep them; name the second one's
reason honestly.

### NIT — `docs/architecture/layer-model.md` still describes the old shape
