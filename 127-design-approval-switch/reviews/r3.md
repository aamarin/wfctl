## Findings

### BLOCKER `wfctl/_session.py:80` — a valid-JSON non-object crashes every command for the branch

`auto_approve()` catches `(OSError, json.JSONDecodeError)` and then calls
`data.get(...)`. Any JSON that parses to something other than a dict raises an
uncaught `AttributeError`:

```
'true' -> RAISES AttributeError 'bool' object has no attribute 'get'
'null' -> RAISES AttributeError 'NoneType' object has no attribute 'get'
'5'    -> RAISES AttributeError 'int' object has no attribute 'get'
'[]'   -> RAISES AttributeError 'list' object has no attribute 'get'
```

Reproduced end to end — with `mode.json` containing `true`, `wfctl status` exits
with a rich traceback pointing at line 84. `auto_approve()` is called from
`build_report`, which every one of `start`, `status`, `resume`, `next` and `end`
runs, so one bad byte takes the whole CLI out for that branch.

This falsifies the function's own docstring — *"Absent, malformed or unreadable
reads as `False`, never as granted"* — and the test written to pin exactly that
claim (`test_a_lost_or_damaged_mode_file_reads_as_attended`) covers only the
`JSONDecodeError` shape and the missing-file shape, so it passes over the hole.
The reachable path is the one the docstring names: a human editing the file to
flip the switch by hand writes `true`, which is the single most likely hand-edit.

Fix:

```python
return isinstance(data, dict) and data.get("auto_approve") is True
```

and extend the existing test with `"true"` and `"null"` bodies beside `"{not json"`.

Note for context, not as a second finding: `session_started` (`_session.py:59`)
has the same shape and the same latent flaw. It makes a weaker promise, so this
is a family the author may want to fix in one place — but the new code is where
the contract is explicit.

## Passes with no findings

**Security.** `mode.json` is read from a state dir the invoking user owns; JSON
only, no shell, no interpolation into a command, no secret. The value comparison
is `is True`, so `"true"`, `1` and truthy junk all read `False` — the correct
direction. No new external input crosses a boundary. The one security-adjacent
property is that `wfctl start*` is in `/start-session`'s allowlist and the glob
admits any flag, so an agent can grant itself the mode; the record confronts this
head-on under **Owns truth**, rejects prevention with a specific argument (every
verb is equally reachable under `Bash(wfctl *)`), and substitutes evidence in
#100's shape. I accept that call. Its one weakness is NIT 9 above: the evidence
is a log line nothing highlights.

**Performance.** `build_report` gains one `read_text` of a ~30-byte file per
call, on commands that already stat the whole spec tree. Not measurable.

**Over-engineering.** Nothing speculative. `_AUTO_APPROVE_NOTICE` as a single
constant shared by `status` and `resume` is the right call and its comment says
why. The tri-state `typer.Option(None, ...)` under a `bool` annotation is a type
the annotation doesn't tell the truth about — but `state_dir_cmd`'s
`branch: str = typer.Option(None, ...)` at `cli.py:503` is the same shape, so it
is house style rather than a new pattern, and mypy is clean. Only two lines are
removable (NIT 7, and the `_events` helper's `if log.exists()` guard for a file
that always exists by the time it is read).

**net: −2 lines possible.** Lean already.

**Architecture.** Fits. `MODE_NAME` living in `_session` rather than `_io` is the
direction `io-owns-durability-not-domain-files` (proposed) is already heading,
and `verify.json` is a real precedent, not an invented one. I verified the new
record's characterisation of `session-state-is-re-derived` against the accepted
text: the quote is exact and the "names exactly one occupant of that carve-out"
reading is correct. The record's claim that two tests construct `PipelineReport`
directly is also correct (`tests/test_pipeline_state_names.py:237,250`).
