### BLOCKER — the printed remedy is unquoted

`wfctl/cli.py:L3745-3750`:

```python
console.print(
    f"    update: wfctl install-skills{_agent_flag(agent)} "
    f"--from {recorded_source}",
```

Reproduced with a source at `…/scratchpad/my src`:

```
⬆ base: source changed since install — …/scratchpad/my src
    update: wfctl install-skills --from …/scratchpad/my src
```

Run verbatim, that resolves `--from …/scratchpad/my` with a stray positional
`src`; typer exits 2 and nothing is repaired. The architecture record for this
feature rests on one sentence — *"the printed command is what gets run"* — and
`/start-session` runs it unattended. This is the one place where that sentence is
false, and paths with spaces are ordinary on macOS.

It fails loudly rather than doing the wrong thing, which is why I note it: a
reviewer could reasonably downgrade it. I do not, because the recovery an agent
reaches for after a failed printed command is the bare example beside it in
`start-session` step 2 — the exact substitution FR-013 exists to prevent. The fix
is `shlex.quote(recorded_source)` and leaves every existing assertion passing.

The same value is also read back out of `.wf-skills-manifest.json`, a file wfctl
does not own the write history of, and printed into something a person pastes
into a shell. Quoting is the right treatment on that ground alone.

### WARNING — `except FileNotFoundError` is too narrow for FR-009

`wfctl/cli.py:L3716-3727` catches only `FileNotFoundError`. Deleted and renamed
checkouts land there, and an unmounted macOS volume does too (the path simply
stops existing) — so the three cases FR-009 names are covered. An *unreadable*
source is not. Reproduced by `chmod 000` on one file in a recorded source:

```
PermissionError: [Errno 13] Permission denied: …/src/agents/skills/demo/SKILL.md
```

A rich traceback at session start, from the command whose docstring promises that
"every applicable check runs before exiting, so one run reports everything wrong
at once". `--from` is what widens this: the wheel is well-formed by construction,
a checkout someone else owns is not. `except OSError` is a one-word fix and needs
no new test to keep passing.

## Pass 2 — Security

No secrets, no injection surface in the copy itself: `resolve_root` does

### WARNING — the inverted comment at L1862

```python
# Scoped to the layers this run rewrites — an agent install leaves base's
# record, and its source with it.
if source is None:
    rewritten = {_BASE_LAYER, agent} & set(_layer_keys(manifest))
```

`layered` always includes `_BASE_TARGETS`, so `items` always carries a `base`
entry and `manifest["base"]` is always replaced. Verified end to end: after
`install-skills --from <src>` then `install-skills --agent claude --yes`, the
notice fires for base and the manifest goes from `{'base': '<src>'}` to
`{'base': None, 'claude': None}`.

The code is right — `_BASE_LAYER` belongs in that set unconditionally. The
comment states the opposite of what it does, and the true case is the mirror
image: a *bare* install leaves an *agent* layer's record, and its source with it.
`AGENTS.md` makes comments load-bearing ("explain *why this shape*"), so a
comment that would mislead the next reader into thinking base is exempt is worth
a WARNING rather than a NIT.

### WARNING — the misattributed missing-tree message at L2002-2010

Reproduced with `--from` at a tree holding only `agents/`:

```
⚠ Expected 'specify/scripts' missing from this wfctl install (…/scratchpad/src) — skipping
⚠ Expected 'specify/templates' missing from this wfctl install (…/scratchpad/src) — skipping
```

Two problems. The message blames "this wfctl install" for a tree the caller
named, and the comment above it — kept verbatim from before the change — now
asserts something false:

> Reachable only from a broken install — the bundle ships with the package, so a
> missing source means the wheel lost files rather than that the user asked for
> something that does not exist.

`resolve_root` accepts a root when *any* one of `TREES` is present, so a partial
named source is now an ordinary reachable state, not a broken wheel. The comment
even records that the current wording exists because *"'not found in
wf-skills@main' used to send people to look upstream for a problem on their own
disk"* — the same misdirection, now pointing the other way. This is also the one
seam where FR-010's spirit leaks: the source contains *some* expected content, so
it is not rejected; it half-installs and reports success.

Fix: branch the wording on `source is not None`, and rewrite the comment.

### WARNING — remedy flags vs the contract vs the new prose

`contracts/cli.md` specifies `update: wfctl install-skills --prune --yes --from ../116-pr`
for this state and explicitly contrasts it with the default-source remedy, which
"stays `update: wfctl install-skills`". The implementation prints neither flag.

On its own that is defensible consistency with the existing default remedy. What
makes it a finding is the new `start-session` paragraph, which says **"The command
doctor printed governs; these two are only its common shapes."** Step 2's standing
instruction is "run what it printed … adding `--prune`" — it never says to add
`--yes`, because until now the two literal examples carried it. An agent that
takes the printed line and adds `--prune` therefore drops `--yes`, and
`install-skills` calls `typer.confirm("Proceed?", abort=True)` on a foreign
overwrite regardless of interactivity — an unattended abort in the one flow this
prose was written for.

Resolve it in one place or the other: print `--prune --yes --from …` per the
contract, or say "adding `--prune --yes`" in the prose.

## Pass 5 — Performance

`doctor` now walks up to one tree per distinct recorded source instead of exactly
one. In practice one or two, a few hundred small files, at session start — the
plan's estimate is accurate and the `digest_of` cache is the right shape. No N+1,
no unbounded fetch, nothing sync that should be async.

One NIT: `bundle_hash = digest_of(_bundle.BUNDLE_ROOT)` at L3689 runs
unconditionally, so a repo whose every layer names a source still walks the wheel
— and still hard-exits 1 with "reinstall the package" if the wheel's bundle is
missing, on a question no layer asked. Computing it lazily inside the
default-source branch costs nothing and removes a failure mode that has no bearing
on the answer.

## Pass 6 — Over-engineering

Nothing to `delete:`, `stdlib:`, `native:` or `yagni:`. `resolve_root` is eight
lines of code under a twenty-line docstring, which is this repo's documented house
style and not bloat. `digest_of` is a four-line closure earning its keep. The two
`shrink:` candidates are the L2147 splat and the L2313 nested f-string, about a
line each.

The tests are the strongest part of the diff: eleven new cases, docstrings that
name the failure each exists to catch, assertions on behavior (installed *content*,
not the summary line — the docstring for
`test_install_from_a_named_source_copies_that_source` says exactly why), and the
remedy test asserting the whole set of `update:` lines so `--from` leaking onto a
default layer is caught. Two gaps: no case for `--from` naming the running wheel
(see the NIT below), and none for a source path containing a space (the BLOCKER).

### NIT — the running-tool edge case

`spec.md` Edge Cases: *"The named source is the running tool. Naming the same
location the default would have used must behave exactly as the default does,
including its output."* It does not. Verified:

```
$ wfctl install-skills --from …/146-install-skills-source/wfctl --yes
$ wfctl doctor
✓ base: skills current (from /Users/…/146-install-skills-source/wfctl)
```

Default output would be `✓ base: skills current (wfctl 0.16.0)`, and the manifest
would carry no `source`. Because the key *is* written here, a later `uv tool`
upgrade rewrites that path's contents and `doctor` reports "source changed since
install" — which is precisely the failure the architecture record cites as the
reason the default is recorded by absence. A user has to type the wheel path to
reach it, so it is a NIT rather than a WARNING, but it is a stated spec bullet
with no implementation and no test. Either normalize (`if resolved ==
_bundle.BUNDLE_ROOT.resolve(): source = None`) or strike the bullet from the spec.

**Verdict: Request changes** (1 blocker, 5 warnings)

The design is right and the record justifying it is the best-argued part of the
