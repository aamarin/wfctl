# Phase 0 Research: Judgment rules section for conversation-response-shape

No `NEEDS CLARIFICATION` markers remained in Technical Context — both items
below were investigated anyway because they change where/how the edit lands.

## Decision: Edit target is `wfctl/agents/skills/conversation-response-shape/SKILL.md`

- **Rationale**: `AGENTS.md`'s layer model states `.agents/` is installed
  output (gitignored, regenerated by `wfctl install-skills`) while
  `wfctl/agents/` is the committed source — "editing them [the dotted dirs]
  changes nothing that ships." Confirmed by diffing the two copies (identical)
  and by `git status` showing the source path clean before any edits.
- **Alternatives considered**: Editing `.agents/skills/.../SKILL.md` directly —
  rejected, would ship nothing and get silently overwritten on the next
  `wfctl install-skills`.

## Decision: No new/changed test file needed

- **Rationale**: `tests/test_skill_cross_references.py` is the only test
  referencing `conversation-response-shape`; it asserts the skill loads and is
  cross-referenced with `i-have-adhd`, not any specific section title or rule
  wording (checked via `grep -n` against the retitled/added text). The rename
  in FR-006 and the new section in FR-001–003 don't intersect what it pins.
- **Alternatives considered**: Adding a new assertion pinning section names —
  rejected as unnecessary scope; nothing in the spec requires enforcing exact
  section titles beyond what a human read-through already validates (spec's
  Validation Strategy).

## Phase 1 outputs skipped

`data-model.md` and `contracts/` are not generated: this feature introduces no
data entities, no state, and no external interface — it edits prose rules in an
existing document. The template's own guidance ("skip if project is purely
internal") applies a fortiori to a content-only change. `quickstart.md` is
likewise skipped — the spec's Validation Strategy section already states the
verification steps in full; a separate quickstart would only restate it.
