## The central premise checks out

The one thing that could have made this change a no-op is a semantic difference
between `allowed-tools` on a command and `allowed-tools` on a SKILL.md — if the
skill form were a *restriction* rather than a *grant*, moving the line would have
silently narrowed the session's tool set instead of preserving a pre-approval.
I checked this against current Claude Code documentation rather than assuming:

- `allowed-tools` is **one feature**, not two — `code.claude.com/docs/en/skills.md`
  states command files support the same frontmatter as skills, minus `name` and
  `paths`.
- In both places it is a **grant**, not a restriction: tools listed run without a
  permission prompt for the turn that invoked the skill; unlisted tools stay
  callable under normal permission settings.
- Both space-separated values and `Bash(cmd*)` scope patterns are supported in a
  SKILL.md.

So the moved line is behaviour-preserving. No BLOCKER here, and the commit
message's claim about it is accurate.
