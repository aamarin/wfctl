### Findings

BLOCKER  wfctl/_archive.py:L315 — a listed symlink is now saved as the bare link, never its target. `declared_paths` already rejects any entry that resolves outside the repository, so every listed link that survives points *inside the worktree*, at content the removal deletes. When that target is ignored (the exact case `save_on_remove` exists for), only a dangling link reaches `unsaved/` and the content is lost. This is a regression: main's `_listed_folders` saw `is_dir()` through the link and `copytree` copied the target's files. Reproduced through the hook: `save_on_remove: ["research"]`, `research -> .venv/research` holding `findings.md`; branch prints `saved 1 file → … research` and `unsaved/` holds only the link; main's `_archive.py` on the same tree saves `research/findings.md`. The docstring at L297–298 cites the FR-019 rationale ("may be outside the worktree"), which is true for untracked links but cannot apply to a listed one, since `declared_paths` has already confined it to the repo. → For a listed entry, test `path.is_dir()` before the link branch (restores main's behaviour for folder links); for a link to a file, add the resolved target's worktree-relative path to `listed_files` beside the link. Add a test that a listed link to an ignored folder saves the folder's files, named for the content it lost.
