### Findings

BLOCKER  wfctl/_archive.py:L315 (with L297-298, L366-367) — A listed entry that is a symlink is now saved only as the link, and its target is lost when the worktree is deleted. `declared_paths` already rejects any entry that resolves outside the repository, so every symlink that reaches this branch points inside the worktree being removed. The docstring's reason, "its target is never copied in", protects against nothing. When the target is gitignored, which is the usual case for `save_on_remove`, no other path saves it. This is a regression for folders. Before this change, a listed `notes/` that linked to `.local/notes` passed `is_dir()` and was copied whole, because `copytree` follows a symlink at its root. I reproduced it with `.gitignore` = `.local/` and `notes`, `notes -> .local/notes`, `save_on_remove: ["notes/"]`, and `.local/notes/idea.md`:

| | `origin/main` | this branch |
|---|---|---|
| saved | `notes/idea.md` | `notes`, a link to `.local/notes` |
| `idea.md` after the worktree is deleted | survives | lost, because the saved link dangles |

A listed symlink to a file has the same problem, since `_copy_into` copies a symlink as a link. That case is not a regression, because listed files were dropped before, but it means #611's fix is incomplete for links.
→ Fix: drop `path.is_symlink() or` so that a listed link to a folder goes to `folders` again and `copytree` follows it. For a listed link to a file, save what it points at, either by recording `path.resolve().relative_to(worktree.resolve())` as the entry or by copying with `shutil.copy2(src, dest)` for listed files, which follows the link. Keep link-as-link only for untracked files from git. Add a test, `a_listed_symlink_to_an_ignored_folder_saves_its_files`, and remove the docstring paragraph at L297-298.
