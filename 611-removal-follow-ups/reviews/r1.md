## Review: origin/main..HEAD (e1e4355), reviewer r1

The change mostly does what its four issues ask for. A listed file is now saved, a listed `specs/` keeps everything apart from the spec dir, the stop block for differing spec files is built from fields instead of trimmed output, and the record now matches the code on a failed untracked listing. There is one data-loss regression, though. A listed entry that is a symlink to a folder used to save the folder's contents, and now it saves only the link. The link points at a folder that is deleted along with the worktree.

## Findings

BLOCKER  wfctl/_archive.py:L315 — A listed entry that is a symlink to a folder is now saved as the link alone, so the folder's contents are deleted with the worktree. Previously, `path.is_dir()` followed the link and `copytree` copied what it pointed at. The new docstring borrows FR-019's rule for untracked symlinks, but FR-019's reason was that "the target isn't deleted with the worktree anyway". That reason doesn't hold here, because `declared_paths` rejects any entry that resolves outside the repository. As a result, every listed symlink points inside the worktree, at something the removal deletes.

I confirmed this with a probe. The worktree has `notes -> .scratch/notes`, `.scratch/` is ignored, and `save_on_remove` is `["notes"]` (also tried `["notes/"]`). On `origin/main`, the save holds `notes/idea.md` with its contents. On HEAD, it holds only `notes`, a link to a folder that no longer exists after the removal. The hook prints a green "saved 1 file" either way.

A listed symlink to a file has the same gap: `_copy_into` recreates the link and never copies the content. That case was never saved before this change, so it isn't a regression, but it's the same defect.

→ Classify a listed entry by what it resolves to. The simplest version resolves the entry first (`rel = (worktree / entry).resolve().relative_to(worktree.resolve())`, which `declared_paths` has already shown is inside the worktree) and then checks `is_dir()` and `is_file()` on that path. This also makes the spec dir comparison resolved on both sides, the way `spec_rel` already is. Leave a dangling link alone, since there's nothing behind it to lose. Delete the symlink paragraph in the docstring at L297-298, and add a test that lists a link to an ignored folder and asserts the folder's file is in `unsaved/`.

WARNING  tests/test_archive_unsaved.py:L716 — `test_a_listed_file_git_does_not_ignore_is_saved_once` can't catch the regression its docstring names. The docstring says copying the file twice "would fail on the existing destination", but `shutil.copy2` overwrites a regular file without an error. A second copy still leaves one file, so "saved 1 file" passes with the dedup at L410 removed. The duplicate copy only fails for a symlink: `os.symlink` raises `FileExistsError`, `save` turns that into `SaveFailed`, and every removal in the repository stops. I confirmed both behaviours with a probe that calls `_copy_into` with the same path twice. → Make the listed entry an un-ignored symlink, so the test fails without the dedup.

WARNING  docs/architecture/removal-copy-destinations.md:L48 — Item 3 still says "Ignored folders that the repository lists in `wfctl.json` are copied", followed by "Every other ignored file is left alone". After this change, a listed file is copied too, so the record now contradicts the code. The commit amends the other proposed record for #613 but not this one for #611. → Change item 3 to "files and folders" and add a log line for #611.

NIT  docs/architecture/worktree-removal-requires-saved-work.md:L56 — There's a blank line between item 3 and item 4 of the numbered list, which makes the list loose and sets item 4 apart from the rest in the rendered page. → Remove the blank line.

NIT  wfctl/_archive.py:L312 — When the entry is the spec dir itself (`rel == spec_rel`), the warning still says it "is inside the spec dir". → Say "is the spec dir or inside it", or use two messages.

NIT  wfctl/_archive.py:L39-40 — The `UnsavedCheck` docstring says the folder's copy "leaves out what the spec store already saves". For a spec dir inside the worktree, the copy-out to the main checkout saves it, not the spec store. The commit message draws this same distinction for #610. → "what the copy-out already saves", or "what is saved separately".

NIT  wfctl/cli.py:L1542 — `entries, shown = saved.shown, 20` uses `shown` for two different things: the list on `SavedResult` and the local limit of 20. → Name the local `limit`, on its own line.

NIT  wfctl/_archive.py:L51 — `excluded` is a list, but only one value can ever go into it (the spec dir), and the same value is appended again for each listed folder that holds it. → `excluded: str | None`, or leave it as is. Either is fine.
