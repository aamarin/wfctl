WARNING  wfctl/_archive.py:L321 — A listed link to a folder is never checked against the spec dir, so spec files are saved a second time in `unsaved/`. The file branch checks the link's target with `in_spec_dir(target)`, but the folder branch checks only the link's own name. I confirmed two cases. With `save_on_remove: ["notes"]` and `notes -> specs`, the save prints `notes/40-feature/spec.md`. With `notes -> specs/40-feature`, it prints `notes/spec.md`. The docstring says spec files "are never saved here twice (FR-018)". Nothing is lost, and `origin/main` behaves the same way, but this commit is what makes the two branches disagree. → In the folder branch, resolve the link once (`target = path.resolve().relative_to(worktree.resolve())`). Skip the entry with the existing warning when `in_spec_dir(target)` is true. If the target holds the spec dir, either skip the link with a warning or exclude the spec dir relative to the link. Add a test for `notes -> specs/<branch>`.
