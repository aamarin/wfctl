### Findings

**WARNING  tests/ (new file or `test_skill_cross_references.py`) — the defect #361
names is fixed for one step and expressed nowhere as a check.**
`a-rule-is-expressed-as-a-check` asks one question of the rule: is a violation
visible in an artifact the work already produces? Here it is — the shipped bundle
is the artifact, and the rule is "every `_STEPS` command resolves to a skill an
agent can invoke". Today all eight comply, but only by hand; the next step added
to `_pipeline._STEPS` can reintroduce #361 with the suite green, exactly as
brainstorm did. This repo already writes this shape of check next door
(`test_every_referenced_skill_ships`). Fix — one test, ~8 lines:

```python
def test_every_pipeline_step_names_a_skill_that_ships() -> None:
    from wfctl._pipeline import _STEPS
    missing = {}
    for step, spec in _STEPS.items():
        wrapper = _AGENTS / "commands" / f"{spec.command.lstrip('/')}.md"
        named = _REFERENCE.findall(wrapper.read_text()) if wrapper.exists() else []
        if not named:
            missing[step] = spec.command
    assert missing == {}, f"next_command with nothing to invoke: {missing}"
```

(`test_every_referenced_skill_ships` already covers the second half — that the
name found actually ships.)

**WARNING  tests/test_skill_cross_references.py:178-203 — the anti-drift check
covers 5 of the 11 grants it claims to guard.**
The docstring's argument is "a copy is what drifts — so the loop asserts the same
five entries on each". The two `allowed-tools` lines are byte-identical today (11
grants each), and the loop pins five. What the check does not hold, on either
surface: `Bash(wfctl status*)`, `Bash(wfctl feature-paths*)`, `Bash(mkdir*)`,
`Write`, `Read`, `Glob`. `grep -rn "wfctl status\*" tests/*.py` returns nothing —
no test anywhere pins that grant, and it is the one the skill's own first
instruction depends on (`SKILL.md:17-24`, `wfctl status --json # read
auto_approve`). Drop it from the skill's copy and the read fails, the file's own
rule converts an inconclusive read to `false`, and the entire `auto_approve`
override table goes silently inert on the model-initiated route — green suite,
and `approval-mode-is-stored-intent` says that grant is exactly what the file
"must gain". The change created the second copy, so this is in scope for it. Fix:
assert the two lines are equal —

```python
lines = {where: _allowed_line(path) for where, path in surfaces.items()}
assert lines["wrapper"] == lines["skill"], "the two grants have drifted"
```

— keeping the five-entry loop as the statement of *why* those five matter.
