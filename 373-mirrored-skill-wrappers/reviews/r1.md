### WARNING `wfctl/cli.py:L2366` and `wfctl/cli.py:L2408` — rationale comments inside `_MIRRORED_SKILLS` assert "no wrapper under `agents/commands/`", which this commit falsified

The commit message says "`_MIRRORED_SKILLS` and `_mirror_supersedes_wrapper` are
untouched." True of the names; false of the prose beside them.

`L2366` (the `architecture-design` entry): "Same case as
`software-design-decisions` below — no wrapper under `agents/commands/` — but it
earns the entry for `start-session`'s reason rather than #124's."

`L2408` (the `software-design-decisions` entry): "No wrapper under
`agents/commands/`, so the mirror is the only route: a skill absent from both is
reachable only by an agent already reading `design-levels` as text…"

Both now describe a tree that no longer exists — `wfctl/agents/commands/`
contains both files as of this commit. The second is the sharper problem, because
that sentence *is* that entry's entire justification for membership. A reader
who checks the claim, finds a wrapper, and concludes the ground expired will
drop `software-design-decisions` from the set — and the commit message itself
records what that costs ("Dropping a name would un-suppress its wrapper on claude
and stop `design-levels` §4's pointer resolving, which is #150 restored"). The
comment now argues for the exact action the commit message warns against.

CLAUDE.md § Code style makes this the project's own standard: "Existing comments
are dense with rationale — match that." A comment that states a false fact about
the tree it sits in is the failure mode that convention exists to prevent.

Fix (≈4 lines, no behaviour change): amend both to say the wrapper exists and is
suppressed, e.g. at `L2408` — "Its wrapper (#373) is suppressed on exactly this
layer, so the mirror is still the only route here; a skill absent from both is
reachable only by an agent already reading `design-levels` as text." The diff
already wrote precisely this sentence into
`tests/test_skill_cross_references.py:L437-438`; the constant deserves the same
correction.

### WARNING `tests/test_skill_cross_references.py:L436-448` — `test_the_design_record_skill_is_model_invocable` is down to one assertion and its name now overreaches it

The change deleted `assert not (_AGENTS / "commands" /
"software-design-decisions.md").exists()`, correctly — that assertion was
invalidated. What it left is a test whose whole body is
`assert "software-design-decisions" in _MIRRORED_SKILLS`.

The repo has already argued why that is not enough. Its sibling four hundred
lines up, `test_the_design_method_skill_is_model_invocable` (L145-152, prose
retained by this very diff), says: "Membership alone does not settle it, and the
name of this test is the claim that overreaches if it stands alone…
`disable-model-invocation` on this SKILL.md would refuse the skill on the
discovery path membership just put it on, leaving no route at all. `i-have-adhd`
is mirrored and refused for exactly that reason, so this is a live failure mode
rather than a hypothetical, and the key is a plausible copy-paste from any of the
wrappers carrying it." The record says the same thing normatively: "Membership
decides reachability; the file decides invocability."

And the docstring's own reference is now false. It claims "Same shape as
`test_the_panel_skill_is_model_invocable`" — that test
(`tests/test_review_fanout_skill.py:L287-299`) carries *both* the membership
assertion and `assert "disable-model-invocation" not in
_arch._frontmatter(_SKILL.read_text())`. After this diff the two tests do not
have the same shape.

The practical loss: `disable-model-invocation` landing on
`wfctl/agents/skills/software-design-decisions/SKILL.md` — the copy-paste the
sibling calls plausible — would now leave that skill with no route on any layer
and the suite green. That guard existed as one of two assertions before this
change; the change removed one and did not replace the coverage.

Fix (3 lines, mirrors the sibling exactly):

```python
    from wfctl import _arch
    from wfctl.cli import _MIRRORED_SKILLS

    assert "software-design-decisions" in _MIRRORED_SKILLS

    front = _arch._frontmatter(
        (_AGENTS / "skills" / "software-design-decisions" / "SKILL.md").read_text()
    )
    assert "disable-model-invocation" not in front
```

`test_the_design_method_skill_is_model_invocable` does **not** have this problem —
it lost the absence assertion but kept the frontmatter one, and its docstring's
"Both assertions" is accurate. Only the L436 test is left thin.
