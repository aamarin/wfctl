### Findings

WARNING  wfctl/cli.py:L1680-1690 (`worktree_remove_cmd`) and L1404-1425 (`_print_removal_stop`) — the hook inlines the same "removal stopped" header, group loop and manual route that `_print_removal_stop` already prints, so the two stop blocks can drift. The helper's `keep_route` parameter is never passed by its only caller, and the hook is the one that needs it. → have the hook call `_print_removal_stop(repo_root, branch, groups, keep)` and delete the inline copy.

WARNING  wfctl/cli.py:L1596-1608 (`_remove_stop_groups`) — builds the stop block by editing the store's display strings: `lines[0].removeprefix("✗ ")`, `.replace(f" for {branch}", "")`, `lines[1:-1]` to drop the hint, and `removeprefix("    ")`. Reordering or adding a line in `_spec_store.store` silently drops a diff row or leaves the hint in the block; the `differs` test pins today's shape only. → give `StoreResult` structured fields (for example `title: str`, `detail: list[str]`, `hint: str | None`) and have `lines` be derived from them.

WARNING  wfctl/_archive.py:L96-117 (`_uncommitted_edits`) — a failed `git status` is a warning and the removal goes ahead, while a failed `ls-files` fails closed. Uncommitted edits are the most valuable, least recoverable class, so the asymmetry is backwards. The same fail-open applies to `merge-tree` on git older than 2.38 (exit 129), which would make `_unmerged_commits` a permanent no-op there. This is the spec's FR-013 choice, so the call is yours. If you keep it, I'd at least fail closed on `status`, since there is no benign reason for it to fail inside a healthy worktree.

WARNING  /Users/andremarin/Development/wfctl/wt/40-save-uncommitted-on-remove/.workmux.yaml:L108-113 — the repo's own hook still calls `wfctl archive-specs` while the template ships `wfctl hook worktree-remove`. `archive-specs` prints no notice (the test `test_archive_specs_prints_no_notice` pins that). So the ponytail end condition ("delete once the notice stops appearing") can never trigger for that alias. The repo's own hook also uses a bare `wfctl`, which AGENTS.md says is not the working tree. → switch this file to `uv run wfctl hook worktree-remove`, or give `archive-specs` the same one-line notice so the alias can be retired.

NIT  wfctl/_spec_store.py:L100-107 — an existing but empty spec dir yields "already_copied", printing "✓ spec files already in <dest>", which is untrue when the worktree has none. → a `no_files` outcome, or reuse `no_spec_dir`.

NIT  wfctl/_archive.py:L27 — a single blank line before `@dataclass` (E302 is outside the project's ruff set, so only a style note).

NIT  wfctl/_archive.py:L295-300 — the inner `try/except Exception: pass` around `rmtree(ignore_errors=True)` can never raise (`ignore_errors=True`), so the inner `try` is dead. → drop it.
