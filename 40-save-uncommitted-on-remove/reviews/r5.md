### Findings

WARNING  wfctl/_copy_out.py:L73, L102 — The plan only checks whether the destination entry is a regular file, so in three cases a copy goes somewhere other than the spec dir. I confirmed each one with a probe against `_copy_out.plan` and `apply`:
  1. The main checkout has a symlink where the worktree has a regular file, and you run `store specs --overwrite`. `shutil.copy2` writes through the link, so a file outside the spec dir (`outside/victim.md` in the probe) is overwritten, and `spec.md` is still a link afterwards.
  2. The main checkout has a dangling symlink at that name. The plan reports the file as missing, and `apply` creates the file at the link's target, outside the spec dir, without `--overwrite`.
  3. The main checkout has a folder at that name. The plan reports the file as missing, and `apply` writes it to `tasks.md/tasks.md`, while the store reports "copied".
  → In `plan`, when `os.path.lexists(target)` is true and the target is a symlink or not a regular file, put the file in `different` with a one-line reason such as "the main checkout has a link (or a folder) here". In `apply`, unlink a symlink target before `copy2`. Commit b48dd2f already applies this rule on the source side, and the destination side needs the same rule.

WARNING  wfctl/_archive.py:L142, L157, L167 — `git log HEAD --not --remotes` lists the commits shown in the stop block, and it is never limited by trunk. In a repository with no remote, `--remotes` matches nothing, so a stop prints the branch's entire history. My probe printed 6 commits for a branch holding 1, and a real repository would print thousands. The same happens on a smaller scale when the branch was cut from a local `main` that is ahead of `origin/main`: the stop then lists main's unpushed commits as if they belonged to the branch, even though they survive in `main`. The decision itself is correct, since it comes from `merge-tree`. Only the list is wrong. → After resolving trunk, build the displayed list with `git log --format=%h %s HEAD --not --remotes <trunk>`. A refusal always has at least one such commit, because if every commit were reachable from trunk, the merge would return trunk's own tree. Add a test using a fixture with no remote.

WARNING  wfctl/cli.py:L1673 — The hook decides whether to stop from `if groups:`, not from `found.refuses or planned.stops_removal`, while `archive unsaved` decides from `found.refuses`. `_remove_stop_groups` copies the three `refuses` conditions by hand. If someone later adds a fourth refusal to `UnsavedCheck.refuses` without adding a group for it, `archive unsaved` stops and the hook lets the removal go ahead. The hook is the path that deletes the worktree. → Decide with `found.refuses or planned.stops_removal`, and build the display groups from one `_unsaved_groups(found)` helper that both commands call (see the over-engineering list).
