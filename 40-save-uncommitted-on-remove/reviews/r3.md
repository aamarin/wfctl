## Findings

WARNING  wfctl/cli.py:L1516 — fail-open hole on the one path that must fail
closed. `resolve_agent_dir(repo_root, branch)` runs `mkdir` and is evaluated
outside `save`'s `try`; only `SaveFailed` is converted to a stop. An `OSError`
here (unwritable state dir, `WFCTL_STATE_DIR` pointing at a file) reaches the
hook's catch-all (L1697), which prints "continuing so the removal is not
blocked" and exits 0, so the untracked files are deleted with nothing saved.
This contradicts the stated design that a failed save refuses the removal. Fix:
compute the state dir inside the `try`, or catch `OSError` around it and raise
`SaveFailed`. Add a test that makes the state dir unusable and expects exit 1.

WARNING  wfctl/_copy_out.py:L61 and wfctl/_archive.py:L242 — a symlink inside
the spec dir is silently lost. `_copy_out.plan` skips symlinks on purpose, and
`_untracked_files` drops everything under the spec dir because "it has its own
destination". Neither saves the link, so it is deleted with the worktree and
nothing is printed. It is low value, but FR-019 says untracked symlinks are
copied as links. Fix: let `plan` copy links as links (or list them under
`unsaved/`), or print a warning naming skipped links.

WARNING  wfctl/cli.py:L1581-1602 — the stop block is built by re-parsing the
store's display strings: `removeprefix("✗ ")`, `lines[1:-1]` to drop the hint,
`replace(f" for {branch}", "")`, `removeprefix("    ")`. A wording change in
`_spec_store.store` (L88-96) breaks the hook output with no type error and
probably no test. Fix: give `StoreResult` structured fields (`title`,
`rows`, `hint`) and have both the by-hand output and `_remove_stop_groups`
read those.

NIT  wfctl/_spec_store.py:L98-105 — `spec_dir` that does not exist (or is empty)
falls through to "already_copied" and prints "spec files already in <dest>,
nothing copied", which is a false statement. Add an `empty` outcome or a
distinct line.

NIT  wfctl/_archive.py:L305 — `shutil.copy2` on an untracked FIFO blocks
forever, hanging the removal; a socket raises and stops it. Rare, but a
hanging teardown hook is the worst failure mode here. Skip non-regular,
non-symlink files with a warning.

NIT  wfctl/_spec_store.py:L40 — `_is_inside` duplicates `_archive.is_inside`
(same resolve-both-sides containment). Reuse one.

NIT  Seeded-template migration: repos whose `.workmux.yaml` came from the
previous template carry `... archive-specs ... || true`, which swallows the
hook's exit 1, so stops never stop and nothing is saved (the hook exits before
any copy). I checked the two live repos on this machine (wfctl and pfms) and
neither has `|| true` on that line, so SC-005 holds for them. But
`pre_remove_wired` still reports such a line as wired. Consider a `doctor` or
`check config` finding for `pre_remove` lines ending in `|| true`.
