## Findings

WARNING  wfctl/_spec_store.py:L86 — `_copy_out.plan(spec_dir, dest)` runs outside the `try` that guards `apply`. An unreadable spec file (or a vanished one mid-walk) raises `OSError` from `read_bytes`/`rglob`, which escapes `store`, lands in the hook's catch-all, prints "continuing so the removal is not blocked", and the removal deletes the only copy. That is the failure FR-028 forbids (a failed copy is a refusal). No test covers it. → wrap `plan` in the same `try/except OSError` and return a `copy_failed` result (which `stops_removal`), and add a test with an unreadable file.

WARNING  .workmux.yaml rollout (SC-005) — the template that origin/main seeded ends `... wfctl archive-specs "$WM_WORKTREE_PATH" "$WM_HANDLE" || true` (removed in this diff, `wfctl/agents/configs/workmux/.workmux.yaml`). Any repo seeded from that template swallows the new exit 1, so the stop never stops anything. `pre_remove_wired` counts the old name as wired, so `install-config` and `doctor` stay quiet. SC-005 ("zero edits") holds only for repos whose hook already had no `|| true`. → have `_check_workmux_hook` warn when the live `pre_remove` line wiring wfctl ends in `|| true`, or state in the spec/PR that only the two known repos were verified and which form each has.

WARNING  wfctl/cli.py `_remove_stop_groups` (L~1560) — builds the stop block by string surgery on the store's display lines: `lines[0].removeprefix("✗ ")`, `lines[1:-1]` (drops the hint, assumes it is last), `.replace(f" for {branch}", "")`, `removeprefix("    ")`. Any rewording or an added line in `store` changes the stop block silently, and nothing pins the pairing. → give `StoreResult` structured fields (`title`, `detail`) or a `stop_group()` method that the store owns; keep `lines` for the by-hand output.

WARNING  wfctl/_copy_out.py:L61 / wfctl/_spec_store.py — a symlink inside the spec dir is skipped by `plan` (by design, to avoid following it out), and `_untracked_files` also drops everything under the spec dir. Net: a symlink in the spec dir is neither copied nor reported, and the worktree removal deletes it. Low likelihood, but the spec says untracked symlinks are copied as links (FR-019). → copy links as links in `apply` (recreate with `os.symlink`) or add them to a warning line.

NIT      wfctl/_archive.py:L260 and L343 — `save_on_remove` entries are not normalised. `a/../b` passes validation but `Path("a/../b")` never matches `_under`/parents checks, and `copytree` into `staging/a/../b` raises when `staging/a` does not exist, which becomes `SaveFailed` and stops every removal in that repo. → `os.path.normpath` the entry in `declared_folders`.

NIT      wfctl/_spec_store.py:L40 — `_is_inside` duplicates `_archive.is_inside` with the argument order swapped. Two near-identical predicates with opposite signatures invite a wrong call. → import and reuse one.

NIT      wfctl/_archive.py:L53 — `_unmerged_commits` fails open on any `merge-tree` error other than exit 1, including "refusing to merge unrelated histories" (exit 128), so a worktree on an orphan branch with local-only commits is removed after a warning. Matches FR-013 and the stated git >= 2.38 assumption; worth one line in the warning text so the person sees that commits were unchecked rather than checked and clean. No change required.
