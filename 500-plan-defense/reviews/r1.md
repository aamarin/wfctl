No bugs found. Specifically verified as correct:

- `wfctl/_pipeline.py:446-451` — the `needs_person` skip is only taken after
  `sub.reads(ev)` has already run and found the pass not `done`, so evidence a
  person already wrote (`test_evidence_counts_whichever_mode_is_on`) still
  wins over the mode. It also deliberately does not set `cascade`, so a pass
  declared after a skipped one is still read on its own evidence rather than
  reported `pending` — matches `test_a_skipped_pass_does_not_hold_back_the_pass_after_it`.

  `state == "in_progress"`, so a skipped needs-person pass correctly never
  becomes the thing `manual_pass_reason`/`next_step_content` treats as
  blocking — covered by `test_an_autonomous_run_moves_past_the_skipped_pass`.
- `wfctl/_pipeline.py:952-957` — the single `read_auto_approve(agent_dir)`
  call moved from after `_infer_steps` to before it, and the one value
  (`granted`) now feeds both pass inference and routing. It was one read
  before and is one read now; what changed is that the passes need it, and
  reading it once for both is what keeps them from disagreeing, as the new
  comment says.
- `wfctl/_declared.py:164-178` — the boolean-type check on `needs_person` runs
  before the `needs_person and manual` check, so a bad-type entry gets exactly

  `test_check_config_reports_both_needs_person_mistakes` test, which declares
  one of each kind and gets exactly one message per entry.

  bumped together, and `tests/test_status_contract.py::test_the_shipped_file_matches_the_union_in_both_directions`

  is a real, already-existing safety net for exactly this kind of change, not

- The console renderer (`wfctl/cli.py:714-718`) renders `sub["annotation"]`
  generically for any skipped pass, so the new
  `"needs a person; auto-approve is on"` string reaches `wfctl status`'s plain

## Over-engineering

Low. The functional diff to `wfctl/_declared.py` and `wfctl/_pipeline.py` is
small and tightly scoped: one new field on two existing structures, two new
validation branches, one new conditional in an existing loop, and one
refactor (`_read_pass`) that reduces duplication rather than adding
abstraction for its own sake. There is no new class hierarchy, no
configuration surface beyond the single `needs_person: bool` key, and no
speculative generalization (e.g., no attempt to generalize "needs a person"

The four new architecture records and the five-file `references/` tree under
