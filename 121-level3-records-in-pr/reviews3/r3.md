### BLOCKER

**BLOCKER  `wfctl/agents/commands/speckit.{plan,tasks,implement,analyze}.md` — the
consumer's parse rule does not match the producer's template or the only real
instance of the format, and no wrapper says what a listed path is relative to.**

All four wrappers state the rule as: *Every **list item** of the form
`- <path> — <text>` names a record; read each one.* Three things do not line up
with it, and each is independently reachable:

1. **Backticks.** The one real entry in the repository — this feature's own
   `design.md:112` — is `` - `docs/architecture/design/326-contradiction-is-a-seventh-pass.md` — ``.
   The path is fenced. A literal reading of `- <path> — <text>` makes the path
   `` `docs/...md` `` including the backticks, which opens nothing. The producer
   template in `wfctl/agents/commands/speckit.brainstorm.md:95-99` writes it
   *without* backticks, so the shipped template and the one artifact ever produced
   from it already disagree, and the consumer rule was written against neither.
2. **Line wrap.** In that same entry the em dash ends the line and `<text>` begins
   on the continuation line. `- <path> — <text>` describes a single line. Nothing
   says a wrapped entry still counts.
3. **The base — the sharp one.** `speckit.brainstorm.md:95-99` emits
   `- <arch-root>/design/<issue>-<decision>.md — …`, and immediately insists the
   root be taken from `wfctl arch-root` rather than written in, i.e. an
   **absolute** path. The real artifact instead carries a **repo-relative** path.
   No wrapper, and no line of `contracts/record-list.md`, says what a relative
   path is resolved against. Three bases are plausible to the agent following
   this instruction, and one of them is wrong on this very branch: the step has
   just run `wfctl feature-paths` and read `<FEATURE_DIR>/design.md`, so resolving
   a relative path against the document it came from is the natural reading —
   and `FEATURE_DIR` is `/Users/…/wfctl-specs/121-level3-records-in-pr`, where
   `docs/architecture/design/326-….md` does not exist.

   The failure that produces is `<path> — listed, not found` for a record that is
   present and readable. That is the feature reporting its own single test case
   as missing, and FR-004's three states then carry a false answer rather than a
   silent one — worse than the gap #326 was opened to close.

**Fix**, one clause per wrapper, no new mechanism: `wfctl feature-paths` already
prints `REPO_ROOT` on the line above `FEATURE_DIR`. Say *"a relative path is
resolved against `REPO_ROOT`; an absolute path is used as given; backticks around
the path are not part of it; an entry may wrap after the em dash."* Then make
`speckit.brainstorm.md`'s template emit that same shape — it is under
`wfctl/agents/commands/`, so FR-012 permits the edit, and the clarify scan's
rejection of *"tightening the section's format in the brainstorm wrapper"* was
about forbidding prose paths, not about the path's base. The producer and the
consumer of a format that four steps now depend on should be pinned by one test;
`required-sections-are-wfctls` is this repo's own precedent for exactly that
shape of check.

**WARNING  All four wrappers — `<path> — listed, not found` collapses two states
the spec deliberately separates, in the feature whose thesis is not collapsing
states.**

The wrappers say *"A listed path that will not read — missing, or outside the
working tree — gets its own line, `<path> — listed, not found`"*. The spec's own
Edge Cases distinguish them: a missing file is *"a broken reference, not an
absence"*; a path outside the repository is *"Reported as listed and out of tree"*,
and FR-013 names *"Two shapes"* explicitly.

A record that is present and readable but sits outside the working tree is
reported to the reader as "not found", which sends them looking for a file that
is right there. The remedy for the two cases is different — one is a moved file,
the other is `wfctl arch check`'s territory — so the reader needs to know which.

**Fix**: two strings, `— listed, not found` and `— listed, out of tree`. Same
line count. The test asserting `"listed, not found"` needs one more assertion.
