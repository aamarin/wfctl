## Review: b0a0a39 — "a report counts because it carries a verdict, not because it has bytes"

### Evidence gathered before the findings

The fence was executed rather than read. `grep -qs '^[^A-Za-z]*Verdict'` behaves
identically under `sh`, `zsh -f` and `bash`, and under BSD `/usr/bin/grep`, GNU
grep and `ugrep` (the grep actually first on PATH on this machine): match on
`Verdict:`, `**Verdict: Approve**`, `## Verdict`, `- Verdict:`; no match on `The
verdict stands.`; exit 2 and **no stderr** on a missing file, so the `RUNNING`
branch's input stays silent as the new prose claims. The pattern is plain BRE
with no GNU extension, so the portability claim holds.

The corpus claim in the commit message and in the skill was measured, not taken
on faith. Over the 247 report files under `*/reviews/*.md` in this project's
spec root:

| anchor | files matched |
|---|---|
| `^Verdict:` | 116 / 247 (47%) |
| `^[^A-Za-z]*Verdict` | 247 / 247 |
| carries `net:` or `Lean already` as well | 246 / 247 |

So "rejects about half the honest reports" is accurate to the point, and the
shipped anchor has **zero false negatives** against every report this project
has ever produced. That is the strongest thing in the change.

Both new behavior tests are genuine regressions, confirmed by running the
pre-change fence against the new fixtures: `[ -s ]` reports `looks good` and
`The verdict stands.` as `reported  r1` / `reported  r2`, which is exactly what
the new assertions reject. They exercise the fence through `_shell`, not a
sentence in the file.

`uv run --frozen --extra dev pytest -q` — 1586 passed. `ruff check wfctl/
tests/` — clean.

### Findings

**WARNING  wfctl/agents/skills/fanning-out-code-review/SKILL.md:L177 — the
skill names a pytest function that does not ship with the skill.** `.agents/` is
installed into arbitrary projects by `install-skills` (`layer-model`); `tests/`
is not. In every installed copy, `test_the_verdict_anchor_accepts_every_
spelling_reviewers_use` is a pointer to a file the reader cannot open, and
"Reports in **this project's** own spec root" reads as the consuming project,
whose spec root has no such corpus. The stated justification is also
contradicted by the text carrying it: the docstrings at
`tests/test_review_fanout_skill.py:L189` and `:L212` both say the skill "names
this test rather than restating the four" / "defers to a test by name instead of
restating the four spellings" — but L173-174 restates all four spellings
verbatim, two lines above the pointer. → Drop the clause naming the test (`and
\`test_...\` is what holds the four apart from prose that merely mentions the
word` → `and prose that merely mentions the word is not one of them`), and move
the corpus evidence into the test's own docstring, where an outside reader is
not being sent to look for it. Deleting the clause also removes the need for
`test_the_skill_still_names_the_test_that_holds_the_anchor_open`.

**WARNING  tests/test_review_fanout_skill.py:L211 —
`test_the_skill_still_names_the_test_that_holds_the_anchor_open` does not catch
the rename it exists to catch.** It compares two *string literals* — one in the
test, one in the skill — and says nothing about whether either names a test that
exists. Rename the `def` on L181 alone (the ordinary case: an editor rename of
the symbol, not a global find-and-replace over the repo) and both literals still
agree, the assertion still passes, and the skill points at a function that is
gone. That is precisely the dangling pointer the docstring says no other check
can see. → If the test is kept at all, derive the name instead of retyping it:

```python
assert (
    test_the_verdict_anchor_accepts_every_spelling_reviewers_use.__name__
    in _SKILL.read_text()
)
```

A `def`-only rename then fails at collection with `NameError`, which is the
behaviour the docstring claims. (Preferred fix: delete it with the clause, per
the finding above.)

**WARNING  wfctl/agents/skills/fanning-out-code-review/SKILL.md:L376 — "Three
dispositions, each requiring a reason on the line" now sits directly under a
table showing a fourth Disposition word with no reason on the line.** L371 adds
`| — | r3 | no findings — … | clean |`; L405-408 then establishes `clean` as
shipped vocabulary ("A `clean` row is the opposite of it"). The paragraph
introducing the row (L382-387) never says whether `clean` is a disposition, nor
that it is exempt from the reason rule. A reader who counts the words in the
column gets four and is told three — the same rule-and-artifact disagreement
this commit was filed to remove, one section further down. Nothing checks the
table (no test parses it, and the table is never written to disk), so
`a-rule-is-expressed-as-a-check` leaves this as prose — which makes internal
consistency the whole of the guarantee. → Reword L376 to scope the count to
findings and admit the fifth word, e.g. "Three dispositions for a finding, each
requiring a reason on the line: **applied** … — plus **clean**, for a reviewer
that had no finding to dispose of."

**WARNING  wfctl/agents/skills/fanning-out-code-review/SKILL.md:L155 — the check
keys on one of the two lines `code-review` Step 5 mandates, so a two-line report
still buys a clean row.** `Verdict: Approve` alone (16 bytes) passes. The
residual is narrower than `[ -s ]` and not nil: the skill's own rule on L167-169
says "no findings" is valid only when it says which passes ran, and the check
reaches nothing of that. Step 5 also mandates the over-engineering metric, and
the corpus says requiring it costs almost nothing — 246 of 247 real reports
carry `net:` or `Lean already`, so the second anchor would have rejected one
honest report in 247 while removing the one-line pass. → Ask for both lines:

```sh
  if grep -qs '^[^A-Za-z]*Verdict' "$REVIEWS/$id.md" &&
     grep -qsE '(^|[^A-Za-z])(net:|Lean already)' "$REVIEWS/$id.md"; then
```

I would not block on this — the issue asked for "a line `code-review` already
mandates" and one was chosen deliberately — but the tightening is cheap,
measured, and closes the same hole one turn further.

**NIT  wfctl/agents/skills/fanning-out-code-review/SKILL.md:L386 — "what the
third of three passes actually looked at" collides with the six passes this same
change cites three times.** `r3` is the third of three *reviewers*; `code-review`
Step 4's "passes" are the six lenses each reviewer runs, and L168 invokes them by
that name eighteen lines earlier. → "what the third of three reviewers actually
looked at".
