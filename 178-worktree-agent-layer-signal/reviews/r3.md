## Findings

**WARNING  wfctl/cli.py:4567 — a Codex user can never silence the notice, and
the printed remedy cannot help them.**

`_agent_keys` filters to layers with a *truthy* `_AGENT_TARGETS` entry. `codex`
maps to `[]` and — by design, per the comment at cli.py:2465 — writes no manifest
entry at all. So a developer who did exactly what this change is teaching, set
`WFCTL_AGENT=codex` in their profile, gets:

```
$ wfctl install-skills --agent codex
ℹ Codex has no repo-local command path … Installing the base layer only;
  Codex reads .agents/ and AGENTS.md directly.
…
$ wfctl doctor
✓ base: skills current (wfctl 0.18.0)
ℹ no agent layer — .agents/ only, which every agent reads.
  `wfctl install-skills --agent <name>`, and WFCTL_AGENT=<name> in your shell
  profile so `workmux add` installs it in new worktrees too.
```

(reproduced verbatim in a scratch repo). No value of `--agent` clears it, because
the only agents that write a key are the ones with paths. This is precisely the
failure `test_doctor_is_silent_once_an_agent_layer_is_installed` exists to
prevent — "telling a developer who already made the choice to make it, on every
session start, forever" — and the guard it installs covers claude/bob/copilot
only.

`_resolve_config_agent` (cli.py:2981) uses `_agent_keys` with the same semantics,
and there it is harmless: a commented-out key costs nothing. A line printed at
every session start is not the same consumer, and reusing the predicate carried
the wrong meaning across.

→ Fix: gate on *a choice having been made*, not on *a layer having paths*. The
cheapest honest form is to record the requested agent as a non-layer manifest key
(`manifest["agent"] = agent` alongside `tracker`/`spec_root`, added to
`_NON_LAYER_KEYS`) and suppress when it is present. Whatever the mechanism, add a
third test: `--agent codex` installs no layer and `doctor` still says nothing.

**WARNING  wfctl/agents/skills/start-session/SKILL.md:72 — the one consumer this
change was built for is told to ignore the new line.**

The commit's own argument is that `doctor` is "the one command a session start
always reads". Step 2 of `start-session` currently reads:

> `wfctl doctor` reports green ✓ current · cyan ⬆ upgrade available.
> …
> It reaches only paths still on record. **Doctor's dim `ℹ` block** is the other
> thing entirely: paths in wfctl's destinations that it cannot show are its own…
> **Delete nothing on the strength of that block** — it does not affect the exit
> code, and its own line says wfctl is leaving the path alone.

That prose assumes there is exactly one dim `ℹ` block (the #183 unknown-paths
one). There are now two, with opposite intent: one says "ignore, not yours", the
new one says "act, set a variable". An agent running `/start-session` unattended
maps the new line onto that paragraph, reads "does not affect the exit code",
and moves on — which is the same silence #178 opened with, one layer up. Nothing
under `wfctl/agents/` was touched, and per AGENTS.md the suite would not catch
this ("checks that skills ship and cross-reference correctly, not that they read
well").

→ Fix: amend that paragraph to name both dim `ℹ` blocks and what each means, and
say what the session should do with the agent-layer one — surface it once in the
report, do **not** install an agent unattended, because per `no-hardcoded-agent`
the choice is the developer's and `--yes` would not make it theirs.

**WARNING  README.md:379 — the inserted block orphans a pronoun in shipped docs.**

Before: `…workmux then resolves <agent> from ~/.config/workmux/config.yaml.` /
`It refuses to overwrite an existing file unless you pass --force…` — "It" was
`install-config`. Three paragraphs and a fenced block now sit between them, and
the nearest antecedents are `wfctl doctor` and `WFCTL_AGENT`, so the sentence
reads as though *doctor* refuses to overwrite.

→ Fix: `install-config` refuses to overwrite an existing file… (name the
subject), or move the new block below the `--force` paragraph.

**WARNING  README.md:670 — the Environment Variables table still omits
`WFCTL_AGENT`.**

The change exists to make this variable discoverable and closes the gap in two
places, then misses the section literally named "Environment Variables". A reader
who scans that table concludes wfctl has no agent variable.

The nuance worth stating in the row: wfctl never reads `WFCTL_AGENT` itself —
`grep -rn WFCTL_AGENT wfctl/` finds only the `${WFCTL_AGENT:+…}` string wfctl
*writes* into `.workmux.yaml`, plus the two new hint strings. So the row should
say it is read by the seeded `post_create` hook, not by wfctl, and that it
selects the layer new worktrees install. Half the reason #178 happened is that
this distinction was nowhere.

**NIT  wfctl/cli.py:4569 — `ℹ` where the file uses the literal glyph.**

Every other symbol in `cli.py` is written as itself: `ℹ` at 2636, 3083, 4290,
`✓`/`⚠`/`⬆`/`✗` throughout, and the `—`/`·` in this very string are literal.
The escape is the only one in the file and reads as if the character needed
protecting.

**NIT  wfctl/cli.py:4557-4566 — four of the nine comment lines narrate the
incident rather than inform the next reader.**

AGENTS.md: "Comments inform the next reader of the file; they do not narrate the
change to a reviewer. If a comment only makes sense beside the diff, it belongs
in the commit message." Lines 4560-4564 ("What #178 observed is a different
silence. A worktree came up with `.agents/` and no `.claude/`, and the only thing
that had said so was one dim line… that had already scrolled past…") are the
commit message's second paragraph, and the same story is now also in the arch
record's Log and Consequences. What the next reader of `doctor_cmd` needs is the
first sentence and the last: dim because the record's "Silence here is intended"
governs the flag and not the report, so the exit code is left alone. Keep those,
drop the retelling. `shrink: −4`.

**NIT  wfctl/cli.py:4567 — inline, where doctor's other never-a-finding warning
is a named helper.**

`_warn_missing_bootstrap` (cli.py:3752) is the established shape for exactly this
— warns, returns, never touches the exit code, docstring states why — and it is
called from `doctor_cmd` with a one-line comment saying it is deliberately not in
the `any([...])` list. A sibling `_warn_missing_agent_layer(manifest)` would put
the rationale in a docstring where the next reader looks for it, shorten
`doctor_cmd` (already ~180 lines), and make the pair legible as a pair.

**NIT  wfctl/cli.py:4569 — the line reassures where the reader needs the
consequence.**

"`.agents/` only, which every agent reads" is true and is the existing phrasing
from `.workmux.yaml`, but it is also the phrasing that had already failed to
communicate: the base-only tree is exactly what made a session's first `/`-command
fail in #170, because `.claude/commands/` and the `_MIRRORED_SKILLS` mirror under
`.claude/skills/` are agent-layer output. A reader is told the absent thing is
covered, one line after being told it is absent. A neutral form that still names
no agent: `no agent layer — .agents/ only; an agent that needs native command or
skill paths will not find them here.`

**NIT  README.md:300-341 — the `doctor` section enumerates doctor's verdicts and
does not mention the new one.**

"Seven verdicts per layer" is still correct (this is not per-layer), so nothing
is wrong; but a reader looking up what doctor prints will not find it, because
the only description lives under `install-config`. One clause in the doctor
section, or a cross-reference, closes it.
