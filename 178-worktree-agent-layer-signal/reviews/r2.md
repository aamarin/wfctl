# Review: 7ee6a05 `fix(doctor): name an agent layer that was never installed` (r2)

Target: `git show HEAD` on `178-worktree-agent-layer-signal` — 5 files, +103/-0.

## Findings

WARNING  wfctl/cli.py:L4567 — the guard is `not _agent_keys(manifest)`, and an agent
that legitimately installs no layer (`codex`, `none`) writes no manifest entry by
design (cli.py:L2468 "An agent with no layer of its own (none, or a notice-only
agent) writes no entry"). So a developer who has explicitly chosen codex and set
`WFCTL_AGENT=codex` gets the notice on **every** `doctor` — i.e. every
`/start-session` — telling them to pick an agent, and `install-skills --agent
codex` cannot silence it. Reproduced in a scratch repo:

```
$ wfctl install-skills --agent codex --yes
ℹ Codex has no repo-local command path — ... Installing the base layer only
$ WFCTL_AGENT=codex wfctl doctor
✓ base: skills current (wfctl 0.18.0)
ℹ no agent layer — .agents/ only, which every agent reads.
  `wfctl install-skills --agent <name>`, and WFCTL_AGENT=<name> in your shell
  profile so `workmux add` installs it in new worktrees too.
```

This is the exact failure `test_doctor_is_silent_once_an_agent_layer_is_installed`'s
docstring says the guard exists to prevent — "telling a developer who already made
the choice to make it, on every session start, forever" — and the guard misses the
one supported agent for which "made the choice" and "has no layer" coincide.
→ Fix: distinguish *unset* from *chosen-and-layerless*. Either record a marker entry
for notice-only agents so `_agent_keys` can see the choice, or gate the notice on
`os.environ.get("WFCTL_AGENT")` not naming a `_AGENT_TARGETS` key with an empty
target list. Cover it with a test — there is currently none for `--agent codex`
or `--agent none`. (Note: `install-skills`' hint block has the same blind spot at
cli.py:L2710, but that is pre-existing and occasional; this change is what makes it
recur at every session start.)

WARNING  wfctl/agents/skills/start-session/SKILL.md:L73 — the change's whole premise
is that `doctor` is "the one command a session start always reads", but the skill
that reads it was not updated. It currently says, singular and definite: "Doctor's
dim `ℹ` block is the other thing entirely: paths in wfctl's destinations that it
cannot show are its own … **Delete nothing on the strength of that block** — it does
not affect the exit code". There are now two dim `ℹ` blocks in `doctor` output with
opposite advice: #183's (inert, act on nothing) and this one (actionable, run a
command). An agent applying the skill's rule to the new block ignores it; an agent
applying step 2's "check it is green" plus its worked example shapes
(`wfctl install-skills --prune --yes --agent claude`) may install `.claude/` into a
repo whose developer chose otherwise — which is what `no-hardcoded-agent` forbids
("nothing wfctl prints picks one"). The printed line itself is correctly neutral
(`<name>`, not `claude`); the gap is that nothing tells the unattended reader so.
→ Fix: amend step 2 of `start-session/SKILL.md` to name the two dim blocks
separately, and state that the agent-layer line is the user's call and is never
acted on unattended. Per AGENTS.md this is a `wfctl/agents/` change that the suite
does not verify — exercise it with `uv run wfctl install-skills`.

WARNING  README.md:L366-378 — the inserted block orphans the paragraph that follows
it. "It refuses to overwrite an existing file unless you pass `--force`" refers to
`install-config`, but its nearest antecedent is now `wfctl doctor`, four paragraphs
and a code fence away, so it reads as doctor refusing to overwrite.
→ Fix: move the new `WFCTL_AGENT` block *below* the `--force` paragraph and its
example, or open that sentence with `install-config` by name.

NIT  wfctl/cli.py:L4569 — `"ℹ no agent layer …"` uses an escape where all eight

NIT  tests/test_install_skills.py:L779 —

## Passes run

1. **Correctness** — traced `_agent_keys` (L1389), `_layer_keys` (L1315),
   `_AGENT_TARGETS` (L1195), `_AGENT_NOTICES` (L1211) and the manifest-write loop
   (L2482-2500). The notice sits before `raise typer.Exit(exit_code)` and touches
   nothing, so the "does not change the exit code" claim is structural, not
   incidental — confirmed. Every early return in `doctor_cmd` (not-a-git-repo,
   `Nothing installed`, missing-bundle) precedes it, correctly: on an empty manifest
   the notice would be noise beside "Nothing installed". The one real defect is the
   notice-only-agent case above; reproduced live rather than reasoned about.
   `install-skills`' new paragraph fires under the pre-existing
   `not any(layer != _BASE_LAYER for layer in summary)` guard and is correct for
   every case that guard was already right about.
2. **Security** — the notice string is a constant with no manifest- or
   user-derived interpolation, so it needs neither `escape()` nor `shlex.quote()`,
   unlike the recorded-source lines above it. `_agent_keys` reads only manifest
   *keys* against a literal dict, so a hand-edited manifest holding a non-dict value
   cannot raise here. No secrets, no paths printed. Clean.
3. **Architecture** — the change fits the existing precedent exactly: #183 already
   established the "dim, last, not a finding, exit code untouched" shape in this same
   command, and the new block matches it. The `no-hardcoded-agent` amendment
   separates "no error" from "no mention" without weakening anything the record
   decided, and the changelog line matches the file's existing format. The one
   architectural gap is that the consumer of this output — `start-session/SKILL.md` —
   was not amended alongside (WARNING 2).
4. **Readability** — comments explain *why this shape* rather than narrating the
   diff, per AGENTS.md; the doctor comment's "governs the *flag* … a different
   silence" is the reasoning a later reader would otherwise have to reconstruct.
   Test names are sentences and every docstring names the failure it holds against
   (#178's worktree, the every-session nag, the `--agent` vs `WFCTL_AGENT` half).
   The single blank line after the section-header comment matches the file's
   existing convention (L790, L857, L1362), not a deviation. Prose findings above.
5. **Performance** — one extra dict comprehension over ≤4 manifest keys, once per
   `doctor`. Nothing measurable.
6. **Over-engineering** — nothing speculative: no new flag, no config, no
   abstraction, no dependency. The only shrink available is the duplicated prose
   noted as a NIT.
