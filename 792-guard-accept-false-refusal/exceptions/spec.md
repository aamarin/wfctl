# `spec` does not apply

One behavior a user relies on changes, and the user chose it: text that spells out all three words of the accept command is refused again, as it was before #769, unless a commit, a search, or a release note on a line of its own only reads it as text. The accept-check-threat-model record lists those three as forms the guard must let through. Eleven security rounds each found a new way to hide the literal command, so the guard refuses the words wherever they appear. The rest is a fix: the guard stops refusing commands that only name wfctl, and closes literal forms the guard-catches-literal-accept record already requires it to refuse. No significant design decision beyond those two records, which state the rules this enforces. No ownership change: the guard still makes the same decision from the same input.
