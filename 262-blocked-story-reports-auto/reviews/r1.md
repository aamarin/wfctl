### Passes run

**1. Correctness.** Traced both call sites by hand against the pre-diff code:

- `_infer_steps`: `tasks_open = _tasks_open(spec_dir)` reproduces the removed
  inline expression byte-for-byte (same two `_has_open_checkboxes` /
  `_file_exists` calls, same order). No behavior change here — confirmed by
  reading the three consumers of the `tasks_open` local (implement state,
  decompose block-while-open, decompose skip) at lines 372/374/382, all
  unchanged.
- `next_step_content`: old guard was `if tasks_text and not
  _has_open_checkboxes(tasks_text)`; new guard is `if _file_exists(spec_dir /
  "tasks.md") and not _tasks_open(spec_dir)`. I initially suspected a widened
  edge case here (an existing-but-empty `tasks.md`: old code's `tasks_text`
  truthiness check vs. new code's `_file_exists`), but `_file_exists` is defined
  as `path.exists() and path.stat().st_size > 0` — it already treats a
  zero-byte file as not-existing, so `_file_exists(tasks_md)` and
  `bool(tasks_text)` are equivalent. No regression. The only real behavior
  change is exactly the intended one: the sentinel now also closes the routing
  path, matching `_infer_steps`.
- Verified the reproduction from issue #262 is exactly what the new test
  exercises: sentinel present + one open checkbox + a configured definition of
  done → `next` now prints `wfctl verify` and writes `auto: false`, where
  before the fix it would have printed `/speckit.implement` with `auto: true`.
- Checked `_STEP_NAMES`/`_current_step_name` to confirm `next_step_content` is
  always called with a step name that agrees with `_infer_steps`'s own state
  table (so the `implement`-branch guard can't fire out of sync with `state`
  elsewhere) — no edge case there either.
