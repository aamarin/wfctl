("three callers need this answer and a local reaches only the two inside
`_infer_steps`") reads as a miscount on first pass — there are two call sites of
the *function* (`_infer_steps` line 248, `next_step_content` line 503), not
three. It only resolves once you count the three *use sites of the boolean
value* (two inline reads of the `tasks_open` local at lines 372/382, plus
`next_step_content`'s independent one) rather than call sites of `_tasks_open`
itself. Given AGENTS.md's "comments inform the next reader" standard and that
this file's comments are otherwise unusually precise, this one clause is worth
a rewrite for clarity → e.g. "a local variable would answer the two reads
inside `_infer_steps` but can't reach `next_step_content`'s".

NIT `wfctl/_pipeline.py:243-248` — `_infer_steps` now reads `tasks.md` twice per
call (once into `tasks_text` for its own use, again inside `_tasks_open(spec_dir)`
for the same file). Before this extraction it was read once and the text reused
inline. Harmless at this file size and call frequency (not a loop), but if it's
worth avoiding, `_tasks_open` could take `tasks_text: str` instead of `spec_dir`
and let both callers pass what they already have (`next_step_content` would need
one extra `_file_exists`+`read_text` call itself, so this is a wash rather than a
clear win — noting it, not asking for a change).

net: no lines worth cutting — the diff is already lean for what it fixes.
