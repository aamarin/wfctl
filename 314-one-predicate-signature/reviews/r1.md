## What I checked and found clean

- **Payload shape.** `Reading.renders()` reproduces the old name-branch exactly:
  `annotation` unset for the seven steps that had none, and `implement`'s
  `f"{tally}  {blocked}"` composed inside the predicate rather than in the walk.
  `_PipelineStep.reason` still carries the unrendered half, so
  `build_report`'s `blocked` lookup and `_design_remedy`'s keying on
  `DESIGN_BLOCK_REASON` are untouched. The empty-annotation case
  (`Reading("done", "because", "")` → `""`, not `"because"`) is pinned by a test.
- **The AST test at `test_predicates.py:94`.** It is a real property test, not
  decoration — it scans `_predicates.py` for functions naming `"inconclusive"`
  and requires each to call `blocks`, and it fails loudly if the scan finds
  nothing. Its limits are honest: it is per-function-name, so a function that
  constructs a verdict and calls `blocks` on a *different* value would pass, and
  it only guards this one module. Both are acceptable for what it costs.
- **`assert unkeyed is not None` at `_predicates.py:509`** — production `assert`
  used for mypy narrowing, stripped under `-O`. It is unreachable-if-false by the
  case analysis above, and `cli.py:4308` is the same shape with the same
  comment style, so it matches the existing precedent rather than setting one.
- **The lazy `from wfctl import _tracker` inside `decompose`** — `_tracker` does
  not import `_pipeline`, so this is not cycle-avoidance; it keeps `rich` off
  `_pipeline`'s import path, which main did not. Fine either way.
- **`cli.py`** — one import line moved to `_predicates`; `verification_block` is
  public and reached at exactly one call site, unchanged.
- **`_STEP_NAMES`** is still `list(_STEPS)`, so the walk's new
  `for name, step in _STEPS.items()` cannot disagree with it about order.
- **Test conventions (AGENTS.md).** Names are sentences, docstrings say why the
  test exists and name the failure caught (`test_the_matrix_reaches_every_
  decompose_arm` names the fixture bug that put the tracker in the wrong file).
  Snapshot regeneration is documented in the module docstring with the command
  and the instruction to say which verdict moved.
- **Release safety.** `pyproject.toml` `version` untouched — no accidental
  release.

net: −6 lines possible (both NIT deletions; the rest are corrections, not cuts).
The diff's growth is a 1800-line snapshot and 386 lines of tests, all of which
