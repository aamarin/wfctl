## What each pass checked

**1. Correctness — behaviour is byte-identical, verified two ways rather than
argued.**

*(a) The committed snapshot is an honest pre-image.* `tests/pipeline_payload_snapshot.json`
has one commit in its history (7a9bffd, before the refactor) and is untouched
since. I extracted that tree read-only (`git archive 7a9bffd | tar -x`, no git
writes) and ran the committed snapshot test against it with `PYTHONPATH`
shadowing the editable install — confirmed the import resolved to the 892-line
pre-#314 `_pipeline.py` with no `_predicates.py` present. 5 passed. So the same
29-row × 8-step payload holds before and after.

*(b) An independent matrix over the arms the snapshot cannot reach.* The
committed matrix writes no `wfctl.json`, so `verification_block` returns `None`
for every row and all seven of its blocking arms are unexercised — exactly where
the refactor recomposes a string (`f"{tally}  {blocked}"`). I built a second
harness (9 repo shapes × 3 task states = 27 rows) covering no-dod, malformed
config, unverified, inconclusive, failed, stale-command, stale-sha, dirty-tree
and passing records, and dumped `state/annotation/reason/remedy` from both trees.
Identical after normalising the per-run git SHAs. All six `verification_block`
reason strings and the two-space tally join reproduce exactly.

Hand-traced the two arms most at risk, and both hold:
- `decompose` routed through `blocks(verdict, "ambient")`. `unkeyed is None` →
  inconclusive → ambient not in `_PROMISED` → proceeds, matching the old
  `if unkeyed:` falsy branch; `unkeyed == 0` → satisfied → proceeds; `unkeyed > 0`
  → unsatisfied → blocks, then `in_progress if tasks_open else done`, and the
  reason is set in both. Byte-identical, and `ambient` is the honest label:
  `_unkeyed_issues` returns `None` only where no tracker is configured or the map
  has no rows, neither of which anyone promised.
- `Reading.renders()` reproduces the old annotation dispatch. Seven steps leave
  `annotation=None` and render the reason (old: `brainstorm`/`decompose`
  annotation *was* the reason string); `implement` sets it explicitly.

Also checked: `next_step_content`'s missing-step default (`_STEPS.get` with a
2-tuple fallback → explicit `None` check) is equivalent; continuation flags are
unchanged for all eight steps (FR-007); `spec_dir is None` still returns eight
`pending` steps before any predicate or file read; `Evidence` removes one
redundant stat of `implement-complete.md` (old code computed `_tasks_open` twice)
— a consistency improvement, not a behaviour change.

Against the spec: FR-001 through FR-010 and SC-001 through SC-006 are all met.
SC-005 holds — `_infer_steps` has no branch on a step name; the surviving
`step == "implement"` in `next_step_content` is routing, not the walk.

**2. Security.** Nothing new crosses a trust boundary. `re.compile(key_pattern)`
on repo config, the `_ISSUE_MAP_SECTION` / `_TABLE_SEPARATOR` regexes and the
fence-blanking substitution all moved verbatim, character for character. No new
subprocess, no new file write, no new network read. `verification_block` and
`design_block` keep the same lazy imports and the same argument shapes.

**3. Architecture.** `_predicates` sits in the domain band; imports run
`_predicates → _paths` (downward), `→ _tracker`, `→ _verify` (same band), and
`_pipeline → _predicates` one way only. `tests/test_architecture_view.py` walks
the full AST including function-level imports, so the lazy `_tracker` import is
counted, not hidden. Private crossings into `_pipeline` are still the two `cli`
makes; the four the view draws are unchanged, and the test asserting that passes.
The split lines up with the pressure the record names (#308, #309, #240, #299 each
touch one predicate and none touch the walk). The `NamedTuple`-over-frozen-
dataclass choice is correct: the three positional unpacks of `_STEPS` keep
working, which is why the call-site sweep is 3 lines and not 30. No new pattern
that isn't argued in the record.

**4. Readability.** `_infer_steps` goes from 201 lines with eleven `if name ==`
arms to ~18 lines of body with none. Names describe content (`Evidence`,
`Reading`, `Predicate`, `renders()`); no nested ternaries introduced; no function
over 50 lines in the new module. The `assert unkeyed is not None` in `decompose`
is a type-narrowing self-check with the narrowing stated in its own trailing
comment — the skill explicitly says not to flag that. Findings in this pass are
the two comment-drift WARNINGs above.

**5. Performance.** No new I/O. `build_evidence` performs exactly the reads the
old prologue performed, one time each, and `_tasks_open` is now computed once
instead of twice. `Evidence` is eager for all eight steps, which the record's
Consequences section names as the failure mode to watch — correct today, since
all six values are cheap reads the old loop made unconditionally. The two new
test files add 1.6s to a 131s suite (measured); `test_the_matrix_reaches_every_
decompose_arm` and `test_the_matrix_reaches_both_design_states` each rebuild the
whole payload, which triples the git-repo setup, but at 0.55s a piece that is not
worth trading for shared state.

**6. Over-engineering.** Every new construct has a job and one argument for it:
`Evidence` (six fields, all read by at least one predicate — checked), `Reading`
(three fields; the third exists solely because `implement`'s annotation is not
its reason, which is the branch it removed from the walk), `State` (turns four
hand-written names into a type mypy checks), `Predicate` (the `_STEPS` field
type). The 1800-line snapshot JSON is diff-noise for future changes, but it is
the artifact that makes SC-001 checkable and its regeneration procedure is in the
test's docstring. No dead flexibility, no speculative config, no registry — the
record explicitly rejects the `gate: str` + name-map shape and the parallel-dict
shape, and the reasons given (mypy catches a missing third tuple element and does
*not* catch a missing dict key) are correct.
