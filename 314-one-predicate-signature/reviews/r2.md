## What each pass checked

**1. Correctness (adversarial).** Traced all eight predicates against the arms they replace,
statement by statement.

- `brainstorm`, `specify`, `clarify`, `plan`, `tasks`, `analyze`: arm-for-arm identical,
  including branch order and the `spec.md`-as-stand-in guard.
- `decompose`: the rewrite through `blocks` is equivalent. `unkeyed is None` →
  `inconclusive` → `blocks(_, "ambient")` False → `done`, matching the old `if unkeyed:`
  falling through with `state = "done"`. `unkeyed == 0` → `satisfied` → `done`. `unkeyed > 0`
  → `unsatisfied` → blocks → reason set, `in_progress` iff `tasks_open` — the old code's
  exact shape, including keeping the reason on the `done` branch. FR-006 holds at the one
  step whose routing changed.
- `implement`: `pending` / tally / `f"{tally}  {blocked}"` (two spaces) / `done` all match
  `_implement_verdict` + the old annotation block. The exact console string is pinned at
  `tests/test_pipeline_commands.py:1081`.
- The walk: cascade placement, `_design_remedy` applied to every non-cascaded step, and the
  `reason`/`annotation` split are unchanged. The old loop's `implement_reason` /
  `decompose_reason` / `design_reason` were loop-scoped and not reset per iteration, but the
  per-name `.get()` meant no leak — the new `Reading` cannot leak at all.
- `next_step_content`: `_STEPS.get(step, ("", _REVIEW_REQUIRED))` returned `("", False)` for
  an unknown step; the new explicit `None` branch returns the same.
- Callers of moved symbols: `cli.py` was the only production importer (`verification_block`)
  and was updated. `grep` finds no other reference to `blocks`, `design_block`,
  `verification_block`, `Verdict`, `Source`, `_tasks_open` or `_unkeyed_issues` outside
  `_predicates` and the tests. `wfctl/agents/` is untouched, so no `install-skills` exercise
  is owed.
- FR-003/FR-004 verified by hand, not assumed: on a scratchpad copy of HEAD, deleting the
  `plan` row's predicate and returning `Reading("finished")` from `analyze` gives
  `_pipeline.py:63: error: Missing positional argument "predicate" in call to "Step"
  [call-arg]` and `_predicates.py:460: error: Argument 1 to "Reading" has incompatible type
  "Literal['finished']" [arg-type]`.
- FR-007 verified by reading the table: all eight continuation values are unchanged.

**2. Security.** No new input boundary. `re.compile(key_pattern)` in `_unkeyed_issues` takes
a pattern from a repo-local tracker config — a pre-existing ReDoS surface, moved verbatim,
neither widened nor narrowed. No secrets, no shell interpolation, no new subprocess.

**3. Architecture.** The split respects `the-underscore-is-the-module-contract`:
`_pipeline → _predicates` crosses only public names (`brainstorm` … `implement`,
`build_evidence`, `Predicate`, `State`, `DESIGN_BLOCK_REASON`), so no fifth private crossing
— and `test_architecture_view.py` re-derives that from the AST and passes. The arrow points
one way; `_predicates` never imports `_pipeline`. `DESIGN_BLOCK_REASON` in `_predicates` and
`DESIGN_BLOCK_HELP` in `_pipeline` is the right cut (conclusion vs. rendering). The one
architectural miss is W2 — the rung table describing the predicates stayed in the walk.

**4. Readability.** Eight named predicates with docstrings beat eleven `elif name ==` arms;
the comments moved with their code and were adapted where they referred to `_infer_steps`.
The findings here are the four inaccurate rationales above.

**5. Performance.** `Evidence` is eager, but every field is a read the old prologue performed
unconditionally, so no path pays more (FR-009). The expensive reads stay lazy and stay behind
`cascade`: `verification_block`'s config-read-then-git and `_tracker.configured_key_pattern`
are reached only when their step is. Two or three extra `stat()` calls per inference because
`spec.md`/`plan.md` existence is not cached in `Evidence` — the old code had the same shape.
Suite runtime 139.5s with the new git-backed snapshot fixture in it.

**6. Over-engineering.** `Reading`, `Evidence`, `Predicate` and `Step` are each load-bearing:
`Reading` is what removes the last `if name ==` from the walk (SC-005), `Evidence` is the
existing prologue named, `Predicate` types the table column, `Step` is what makes an
incomplete row a mypy error (SC-003). No speculative flexibility, no registry, no new
dependency. The only surplus is the four lines in `next_step_content` and the size of the
snapshot JSON.
