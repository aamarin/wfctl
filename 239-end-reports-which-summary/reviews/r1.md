# Review: `origin/main...HEAD` — fix(end): say whether the summary was written or kept (#239)

Reviewer **r1**, `code-review` rubric, all six passes. Read-only: no file under
review was edited, no `wfctl verify`, no `install-skills`, no commit.

## Findings

WARNING  wfctl/cli.py:L408 — mtime is rendered in **local** time while everything else about that file is UTC → format it UTC and mark it, e.g. `datetime.fromtimestamp(..., tz=timezone.utc)` with `%Y-%m-%d %H:%M UTC`, or add `%Z` if local is intended.

Reproduced in a scratch repo on this machine (CDT, UTC−5):

```
  ⚠ kept — this session wrote nothing; last modified 2026-09-05 21:30.
# Session Summary: 2026-09-06 — 239-x
```

Both lines describe the same file. `_render_session_summary` stamps the heading
and `**End**:` from `_now_utc()` (`_session.py:L73-77`, ISO with a `Z`), so for
any summary written between 19:00 and midnight local the new line prints a date
**one day earlier than the date inside the file it is pointing at**. The mtime is
there so the reader "can decide whether the file belongs to this session's work
without opening it" (test docstring), and #239's reported failure is literally "a
file headed with the previous day's date" — this line can manufacture that
impression for a file written five hours ago. The two clocks have to agree, or
the offset has to be visible.

WARNING  tests/test_end_reports_which_summary.py:L64 — the load-bearing value is unpinned: the only assertion on the timestamp is `"last modified" in output` → set a known old mtime (`os.utime(path, (t, t))`) and assert the rendered `YYYY-MM-DD HH:MM`.

Nothing in the suite distinguishes `summary_path.stat().st_mtime` from
`time.time()` or from a hard-coded string; swap either in and all 1037 tests stay
green. The date is the entire discriminating content of the new line — the words
around it are constant — so the one thing a regression could break is the one
thing not asserted. (I verified the current behaviour is right by hand:
`touch -t 202601020304` on the summary prints `last modified 2026-01-02 03:04`.
That check belongs in the file, not in a reviewer's transcript.) It would also
have caught the local/UTC finding above.

WARNING  wfctl/agents/skills/end-session/SKILL.md:L70-73 — "the `**Step**` / `**Boundary**` / `**Tree**` lines in it belong to whoever wrote it, so replace them" is unactionable for a handoff, which has no such lines → say "if it carries them, set them to this session's readings; a handoff has none, so add them from the ✓ line."

`worktree-handoff/SKILL.md:L137-140` is explicit that what it copies to
`session-summary.md` is "the shape above, **not** `.agents/skills/end-session`'s
template". So in the kept case the file is either (a) a previous session's
summary, which has those three lines, or (b) a handoff, which does not. The
instruction covers (a) only, and (b) is the case this whole change was written to
protect. An agent that follows it literally greps for three headings that aren't
there.

NIT      wfctl/agents/skills/end-session/SKILL.md:L82-84 — step 4's template still reads `**Step**: {left as `wfctl end` wrote it}`, which is false in the kept case — `end` wrote nothing → `{this session's readings, from the ✓ line}`.

The new block ten lines earlier overrides this in prose ("rather than leaving
them alone"), and a sequential reader gets the correction first, which is why
this is a NIT and not the finding above. But #239 happened because an agent
followed step 4 mechanically, and step 4 still says the thing it followed.

NIT      wfctl/cli.py:L410 — `⚠` fires on *every* `end` on a long-lived branch, which the skill text itself calls "the normal case on a long-lived branch like `main`" → consider dropping the glyph/colour and letting the words carry it.

The change's own reasoning (test_a_written_scaffold_is_reported_without_a_caveat:
"a warning on every run would be as uninformative as the single line it replaces
— the caller would learn to skip it") argues against a constant marker. The test
pins that reasoning for the *written* arm, but on `main` every run is the kept
arm, so on that branch the ⚠ is exactly the always-on warning the docstring
rejects. The discriminating signal is the mtime, not the severity glyph. Author's
call — the two outcomes do differ in kind, so a marker is defensible.

NIT      tests/test_end_reports_which_summary.py:L28 — `_run_end(storyctl_dir)` never uses its parameter → `def _run_end() -> str:`, called as `_run_end()`.

The fixture is already requested by each test function, so passing it through is
inert. `test_end_reports_observations.py:L30` has the identical dead parameter,
so consistency cuts both ways; flagging it because a new file is the cheap place
to stop copying it. Same file L33: `_summary_path` has no return annotation while
its sibling `_summary` has `-> str` — mypy skips `tests.*` so nothing catches it.

## What each pass checked

**1. Correctness.** Traced `end_cmd` → `_session.end` → `write_md_atomic` /
`append_event`, and `_observe`. The write rule is genuinely unchanged: `written =
not summary_file.exists()` is the same predicate the old `if` used, and the
kept-file byte comparison is asserted in two tests. `append_event("end")` still
runs on both arms. Exercised both arms by hand in a scratch repo (write, keep,
keep-with-preexisting-handoff) — output matches the SKILL.md sample exactly.
Verified the premise that nothing rotates or archives `session-summary.md`
between sessions (`grep session-summary wfctl/*.py` → only `_session.py`), so the
kept arm is reachable exactly as described. Edge cases considered and dismissed:
`summary_path.stat()` after a between-call unlink is a TOCTOU window of
microseconds in a single-user CLI; the flag is not re-derivable at the call site,
so returning it is right rather than statting twice.

**2. Security.** Nothing new crosses a boundary. The added line interpolates only
a `datetime`, so unlike the `Summary:` line it carries no attacker-influenced text
into rich's markup parser. No secrets, no shelling out, no path built from input.

**3. Architecture.** `tuple[Path, bool]` for a two-outcome result is proportionate
— an enum for two states in one call site would be the yagni. The decision stays
where the knowledge is (`_session.end` knows; `cli` reports), which matches how
`_observe` already splits reading from printing. No new pattern.

**4. Readability.** Comments explain *why this shape* (second line not a suffix;
what the line may not claim), not what the code does — house style per
`CLAUDE.md`. `summary_written` names the fact, not the mechanism. Local
`from datetime import datetime` matches cli.py's deliberate lazy-import
convention (cf. L2043).

**5. Performance.** One extra `stat()` on a path already resolved, on a command
that shells out to git several times. Not measurable.

**6. Over-engineering.** 35 added lines of code+docs for a two-outcome report;
nothing speculative, no flag nobody sets, no abstraction with one implementation.
The only removable token is the dead `storyctl_dir` parameter above.
**net: −0 lines possible. Lean already.**
