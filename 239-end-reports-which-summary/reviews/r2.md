## Pass 1 — Correctness

The core fix is right and minimal. `_session.end` computes `written = not
summary_file.exists()` *before* the write and returns it, so the flag names the
branch actually taken rather than re-deriving it; `end_cmd` prints the caveat
only on the kept arm. The write rule is untouched — I confirmed by running `end`
twice against a scratch state dir and reading the file back; hand-written prose
survives, and test `L74` pins it.

**WARNING — the mtime is printed in local time, unlabelled.** This is the one
number the new line exists to supply, and it disagrees with every other
timestamp wfctl produces. Demonstrated on a scratch repo
(`WFCTL_STATE_DIR` redirected; nothing in this worktree touched):

```
  ⚠ kept — this session wrote nothing; last modified 2026-09-06 13:40.
```
```
$ head -3 <state>/session-summary.md
# Session Summary: 2026-09-06 — 239-demo

**End**: 2026-09-06T18:40:26Z
$ cat <state>/events.jsonl
{"ts": "2026-09-06T18:40:26Z", "event": "end", ...}
```

Same file, same write: `13:40` on the printed line, `18:40:26Z` inside the file
and in the event log. Neither the local stamp nor the reader carries a zone
marker. `wfctl/_session.py:32`, `wfctl/_io.py:52`, `wfctl/_verify.py:174` and
`wfctl/_archive.py:149` are all `%Y-%m-%dT%H:%M:%SZ`; `cli.py:408` is the only
naive-local timestamp in the package.

Why this matters more than a formatting quibble: the line's stated job (test
docstring, `L61-63`) is to let the reader "decide whether the file belongs to
this session's work without opening it". The only things they can compare it
against are the file's own `**End**: …Z` header and the `date -u` this very
skill hands them in step 1. In a UTC-behind zone a summary written at 20:00
local prints `last modified 2026-09-06 20:00` while its own header reads
`2026-09-07` — i.e. the printed mtime looks a day *older* than the file claims
to be, which is the "headed with the previous day's date" confusion #239 was
filed about, re-introduced by the fix for it.

Not a BLOCKER: the `kept` word alone already discriminates the two outcomes, so
the change is a net improvement as it stands. But the mtime is the half of the
line that misinforms, and it is untested — the only assertion is the literal
substring `"last modified"` (`L71`), so no test would notice the zone changing.

Fix: `datetime.fromtimestamp(summary_path.stat().st_mtime, timezone.utc)` with
`%Y-%m-%dT%H:%M:%SZ`, and update the SKILL.md sample at `L64` to match. If a
local stamp is deliberate for human readability, it must at least carry `%Z`.

Edge cases checked and clear: the stat cannot fail on the kept arm (the file was
observed to exist microseconds earlier in `_session.end`); the `⚠` line is not
`soft_wrap`ed but renders at 72 columns, under rich's 80-column non-tty default,
so the `"last modified"` assertion is not width-fragile; `test_the_path_line_stays
_a_path_and_nothing_else` correctly pins the caveat as a separate line rather
than a suffix, which is the right call — `Summary: <path>` is the machine-readable
line and an appended clause lands inside what a splitter takes to be the path.

## Pass 4 — Readability & the skill doc

**WARNING — `SKILL.md:L68`, "never happens in a fresh worktree", is false.**
`worktree-handoff/SKILL.md:L123` copies the handoff into
`$(wfctl state-dir --branch <branch>)/session-summary.md` at worktree-creation
time, so the *first* `wfctl end` in that fresh worktree takes the kept arm. This
diff's own fourth test
(`test_a_handoff_written_before_the_first_session_is_not_called_stale`) codifies
precisely that scenario, and the sentence two lines later ("it is either a
handoff written for the branch or the last session's prose") is undercut by the
absolute that precedes it. An agent that reads the false claim and then sees the
kept line in a fresh worktree has been told this cannot happen.

**WARNING — `SKILL.md:L72` contradicts the unchanged step 4 template at
`L82-84`.** The new block says the `**Step**`/`**Boundary**`/`**Tree**` lines in
a kept file "belong to whoever wrote it, so replace them with this session's
readings … rather than leaving them alone". Step 4's template still reads
`**Step**: {left as `wfctl end` wrote it}`, and step 3's own earlier paragraph
(`L55`) still says "leave those lines alone". Step 4 is the mandatory step and
the template is what gets copied; a reader in the kept case gets opposite
instructions from two places in the same file. One qualifying clause on the
step-4 placeholders resolves it.

**NIT — `L70-73` assumes the kept file follows end-session's template.**
`worktree-handoff/SKILL.md:L137-144` states outright that a handoff carries "the
shape above, not `.agents/skills/end-session`'s template". In that case there is
nothing to replace, and "replace them" leaves the agent without an instruction.
"Replace them if present, otherwise add them" covers both.

Otherwise the prose is good and matches house style — the code comments at
`cli.py:397-405` and the docstring at `_session.py:96-103` explain *why this
shape* (second line not a suffix; flag returned not re-derived; what the line is
forbidden to claim) rather than narrating the diff, per AGENTS.md.

**Test quality.** Above the bar. Names are sentences, docstrings name the failure
each test exists to catch, and the fourth test is the one that earns the review:
it pins the *constraint* (a pre-existing handoff must not be called stale) rather
than the implementation, via the `AUTHORSHIP_CLAIMS` tuple at `L26`, so a later
"helpful" rewording that adds "stale" fails. The first test pins the negative arm
so the fix cannot pay for itself by warning on every run. Two nits only:
`_run_end` (`L31`) never reads its `storyctl_dir` argument — the fixture is
already requested by each test — and `_summary_path` (`L38`) is missing its
`-> Path` return annotation.
