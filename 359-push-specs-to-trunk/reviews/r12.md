WARNING  wfctl/cli.py:L1689 — the removal hook now stops (exit 1) when it is run on the main checkout, where both parents exit 0. The dispatch sends the spec dir to `_spec_store.store` whenever `copy_out` says `not_applicable`. `copy_out` also says that when `repo_root` is the main checkout, because `_spec_copy.inside_worktree` leaves the main checkout out. `_spec_store.store` computes `inside` by path alone (`_spec_store.py:L518`), with no main-checkout exception, so a main checkout's `specs/<branch>` comes back `not_applicable` with `inside_worktree=True`. `stops_removal` (`_spec_store.py:L428`) is then true, and the hook exits 1 and prints `Remove anyway: git worktree remove --force <main> && git branch -D main`. I reproduced this with `wfctl hook worktree-remove <main> main` and with `… <main> 40-feature`. Both exit 1, printing `ℹ …/main/specs/main is inside the code repository — not committed, not backed up` and then that route. In #40, `store` returned `not_applicable` with `inside=False`, and in #359 the hook only stored a spec dir with `not _archive.is_inside(repo_root, spec_dir)`, so both went ahead. Within the hook, the main checkout is the only input that makes `stored.stops_removal` true. So the `stops = stored.stops_removal` line, and the comment above it, only ever fire in the wrong case. workmux never runs `pre_remove` on the main checkout, so this is reachable only by hand (`wfctl hook worktree-remove` with no argument from main, or the `archive-specs` alias). Nothing is lost, because `git worktree remove` refuses the main tree before `&&` gets to `branch -D`. Still, it wrongly blocks a run and prints a route that ends in deleting `main`. Fix: give the two modules one definition of "inside". Either have `_spec_store.store` take its `inside` from `_spec_copy.inside_worktree`, imported lazily to keep `_spec_store` stdlib-only at module scope, or gate the hook's store on the raw path check that #359 used. Then add a hook test that runs on the main checkout and asserts exit 0. The `StoreResult` docstring (`_spec_store.py:L395-396`) says "the rule lives in one place and the removal command cannot apply a second one", and after this merge that is no longer true.

WARNING  tests/test_worktree_remove.py:L431 — `test_removal_reads_stops_removal_and_not_the_exit_code` pins the state behind the finding above, not the one its docstring describes. WARNING  wfctl/cli.py:L1697 — an unexpected exception from `_spec_store.store` or `report_lines` reaches the hook's catch-all. The hook then exits 0 and never calls `_save_unsaved` (L1710). Untracked files in the worktree are not saved, and workmux goes on to delete them. The merge put a git-and-network code path in front of `_save_unsaved`. `store` catches only `OSError`/`CalledProcessError`, so a `UnicodeDecodeError` from `text=True` git output, or an `ImportError` for `fcntl`, falls through. Probe: with `_spec_store.store` monkeypatched to raise `UnicodeDecodeError` and an untracked `notes-untracked.md` in the worktree, the hook printed `⚠ worktree-remove failed (…) — continuing so the removal is not blocked`, exited 0, and the state dir held nothing. The dry-run comparison just above (L1662-1669) already guards against this exact failure ("Letting it reach the catch-all would throw away the refusals"), and the store is now the same hazard one step later. Fix: wrap the store call in `try/except Exception`, print the warning, and fall through to `_save_unsaved`. A failed store never stops a removal anyway, by the record. Add a test that monkeypatches `_spec_store.store` to raise and asserts the untracked file lands in `unsaved/`.

WARNING  wfctl/cli.py:L1599-1611 — the hook's docstring, which is also its `--help`, is still #40's. It says the hook "copies the spec files out and saves the untracked files", and never mentions that it now commits and pushes an outside spec dir. A push from a removal hook is the outward action the record singles out as ungated ("The push at removal runs from the removal hook in your own shell"), and it is the one thing a reader of `--help` would want named. Fix: add one sentence saying that a spec dir outside the worktree is committed and pushed in its spec store, and that a failed push warns without stopping the removal.
