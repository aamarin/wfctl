## BLOCKER — adding `views/` opens a hole in the level-2 design gate

`wfctl/cli.py:238-245`, triggered by `docs/architecture/views/current-state.md`

`_refuse_unless_boundary_answered` asks whether the branch touched anything
under the arch root, excluding exactly one subtree:

```python
lambda: touched_on_this_branch(repo_root, arch, exclude=arch / "design") is False,
```

`touched_on_this_branch` (`wfctl/_paths.py:306-351`) is recursive over the arch
root by construction — its own docstring says *"Asking about a directory is
recursive in git and cannot be made otherwise"* — and takes a single `exclude`.
`views/` is not excluded, so a branch that touches only the current-state view
satisfies the gate. Confirmed with the pathspec the gate actually builds:

```
$ git diff --name-only 24beb3e...0a02937 -- docs/architecture ':(exclude)docs/architecture/design'
docs/architecture/brainstorm-is-one-step-with-addressable-levels.md
docs/architecture/io-owns-durability-not-domain-files.md
docs/architecture/the-underscore-is-the-module-contract.md
docs/architecture/tracker-owns-the-issue-key-shape.md
docs/architecture/views/current-state.md        ← matches
```

`unanswered()` is `... is False`, so a `True` from the view alone makes
`design_gate` return `False` and the refusal never fires.

This is not hypothetical drift. The view *solicits* exactly this edit at line
145: *"a reader who finds them wrong should edit them."* A branch that fixes a
stale line count in the drawing then walks past the gate that exists to force a
level-2 answer.

The call site already names this failure for `design/`:

> `design/` is excluded, not counted. It holds level-3 records, which govern one
> feature and say nothing about ownership — the question this gate asks.
> Counting them would let a change that genuinely moves a boundary satisfy the
> gate with a record whose own format forbids it from drawing one.

A view is *weaker* evidence than a level-3 design record, not stronger: the view
opens by declaring *"It **describes**; it does not constrain"* (line 3). It has
a stronger claim to exclusion than `design/` does, and it got none.

**Fix:** `touched_on_this_branch` takes one `exclude`. Either widen it to accept
several and pass `design/` and `views/`, or move the view out from under
`arch_root` entirely (`docs/architecture-view.md`, or `docs/views/`) — which
also removes the dependence on `load_records`' glob depth that the placement
argument currently rests on. Whichever is chosen, this needs a regression test:
a branch touching only `views/` must still be refused.

Note the placement reasoning itself checks out — `_arch.load_records`
(`wfctl/_arch.py:145`) does glob `*.md` non-recursively, and
`tests/test_arch_records.py:467` and `:478` already guard that glob for
`declarations/` and `design/`. `arch context` correctly reports 7 accepted
records with the four new `proposed` ones excluded. The missed consumer is the
gate, not the loader.

## WARNING — the private-crossing check is blind to the import form `cli` mostly uses

`tests/test_architecture_view.py:44-72`

`_graph()` records a private crossing only in the branch where the module is
named in `node.module`:

```python
if (node.level and not node.module) or node.module == "wfctl":
    edges[src] |= {a.name for a in node.names if a.name in mods}
    continue            # ← `from wfctl import _paths` returns here
dst = (node.module or "").rsplit(".", 1)[-1]
if dst in mods:
    edges[src].add(dst)
    private |= {... for a in node.names if a.name.startswith("_")}
```

A crossing written as `from wfctl import _tracker` followed by
`_tracker._something` at the use site is an edge with no private crossing
recorded. That is not an exotic form: it is how `cli` imports 16 of its module
dependencies (`cli.py:14, 41, 206, 342, 343, 367, 548, 769, 1027, 1062, 2580,
2727, 3012, 3055, 3279, 3318`).

No such crossing exists today — I swept every `_<module>.<attr>` access in
`wfctl/*.py` and all 34 distinct attributes are public — so the "exactly four"
claim is true. The problem is the claim made *about the check*:

> `tests/test_architecture_view.py` fails on a fifth crossing
> — `the-underscore-is-the-module-contract.md:110`

It fails on a fifth crossing written as a `from wfctl._mod import _name`. Written
the other way, it passes, and the record has just declared the underscore to be
the contract — so the fifth crossing is exactly the event this check exists for.

**Fix:** either extend `_graph()` to record `ast.Attribute` accesses of the form
`<module>._<name>` where `<module>` is a wfctl module bound by a `from wfctl
import` (about eight lines), or soften the record's Consequences to say what the
check actually holds. The record already concedes the general point at
line 111 — *"It enforces the count, not the rule"* — so the narrower claim on
line 110 is the one to correct.

Two smaller notes on the same function, neither worth its own entry:
`dst = (node.module or "").rsplit(".", 1)[-1]` takes the last component, so a
literal `from _io import ...` (CPython ships a real `_io`) would record a false
edge; and `alias.name.startswith("wfctl")` is a prefix match, so a
hypothetical `wfctlx.foo` would too. Neither is reachable today.
