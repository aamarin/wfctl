### WARNING — `current-state.md:63`: `cli` does not hold every `console.print`

The surface/domain paragraph asserts:

> `cli` holds every `typer` decorator, every `console.print` and every
> `typer.Exit`; no domain module imports `typer`.

Two of the three clauses hold. The `console.print` clause does not:

```
wfctl/_tracker.py:16   from rich.console import Console
wfctl/_tracker.py:23   console = Console(highlight=False)
                       7 console.print calls (L180-223)

wfctl/_verify.py:19    from rich.console import Console
wfctl/_verify.py:25    console = Console(highlight=False)
                       10 console.print calls (L157-241)
```

Both emit rich markup (`[red]✗ …[/red]`) straight from the domain band. So the
argument built on the claim in the next sentence — "Move the line and the domain
modules become unusable from anything but a terminal … the pipeline inference
that `speckit-orchestrate` reads would come back wrapped in ANSI" — is
describing a failure two domain modules already have.

`typer.Exit` is clean only on a technicality: `_paths.py:49` raises
`SystemExit("wfctl: not a git repository")`, which is the same authority the
band table hands to surface ("argument parsing, console output, exit codes").

This matters more than a stray sentence because the view's own premise is that
it "describes the code as it stands, including the parts that are wrong." The
surface/domain boundary is the one place where the view stops describing and
starts claiming clean.

**Fix** — say what is true and let the exceptions be the finding, e.g.: *`cli`
holds every `typer` decorator and every `typer.Exit`; no domain module imports
`typer`. Two domain modules — `_tracker` and `_verify` — construct their own
`rich.Console` and print, and `_paths.py:49` raises `SystemExit` directly; those
are the surface leaks the band does not yet hold.* That is a fifth boundary
question, and it may deserve its own record rather than a sentence.

### WARNING — `test_architecture_view.py:59`: the private-crossing check misses the import form this repo already uses

`_graph()` collects private crossings only in the `from wfctl._mod import _name`
branch (L57-63). The branch above it — `from . import _mod` / `from wfctl import
_mod`, L52-56 — `continue`s before any private-name check, which is correct for
the module name itself but leaves attribute access invisible.

That is not a hypothetical form. It is the idiom `_paths.py:379` uses for the
lazy import the whole `tracker-owns-the-issue-key-shape` record is about:

```python
from wfctl import _tracker     # lazy: avoids import cycle at module load
...
_tracker.load_key_pattern(repo_root)
```

Probed against a copy of the tree (baseline: 3 passed):

| Mutation | Expected | Actual |
|---|---|---|
| A new module with no band | fail | **fail** ✓ |
| `_io` gains `from wfctl import _pipeline` (upward) | fail | **fail** ✓ |
| `cli` gains `from wfctl._archive import _x` (5th crossing) | fail | **fail** ✓ |
| a crossing renamed public (4th removed) | fail | **fail** ✓ |
| relative `from ._archive import _x` | fail | **fail** ✓ |
| **`_archive` gains `from wfctl import _paths` → `_paths._STATE_DIR_OVERRIDE`** | fail | **3 passed** ✗ |
| **`_archive` gains `import wfctl._paths as _p` → `_p._STATE_DIR_OVERRIDE`** | fail | **3 passed** ✗ |

The *edge* is caught in both silent cases (the band test would fire if it ran
upward); only the private-name claim is missed. Both the test docstring
(L104-108: "a fifth crossing is drift the drawing missed") and the view's
Staleness section (`:132-137`: "a fifth private crossing … turns the drawing red
rather than stale") assert coverage the pass does not have. The `the-underscore`
record then leans on it in Consequences: "`tests/test_architecture_view.py` fails
on a fifth crossing."

Given that the record's whole subject is which names may cross a module
boundary, a check that only sees one of the two spellings is the wrong half.

**Fix** — bind module aliases per file in the two module-import branches, then
walk `ast.Attribute` for `node.value` a `Name` in that alias set with
`node.attr.startswith("_")`. Roughly ten lines, no new dependency. If that is
deliberately deferred, the two docstrings and the record's Consequences all need
to say "in the `from X import _y` form" instead of claiming the general case.

### WARNING — `test_architecture_view.py:30,44`: the graph is top-level-only, and phase 2 is a package split

`_modules()` and `_graph()` both use `PKG.glob("*.py")`. That is exactly right
today — there are no `.py` files below `wfctl/` (`find wfctl -mindepth 2 -name
'*.py'` is empty) — but the stated phase 2 is splitting `cli.py`, and the
likeliest shape for that is `wfctl/commands/*.py`. On the day that lands, every
new module vanishes from `_modules()`, `test_every_module_has_a_band` still
passes because the set on both sides shrank consistently, and the drawing goes
silently stale in exactly the direction the test exists to prevent.

This is the failure the check is *for*, arriving through the change the check
was written in anticipation of.

**Fix** — `PKG.rglob("*.py")` with the module key as the path relative to `PKG`
(so `commands/arch` rather than `arch`), or, if flat-only is the intent, assert
it: `assert not [p for p in PKG.rglob("*.py") if p.parent != PKG], "the view's
graph is flat; a subpackage needs it re-derived"`. The second is one line and
turns a silent hole into a red test on the day it matters.
