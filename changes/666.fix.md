Renaming a branch no longer resets its review round count or drops its sign-off. wfctl now keeps the review runs, the last reviewed commit, and the sign-off under the issue the branch names. Previously, `git branch -m` gave a branch at the round cap an empty count and three more rounds. Two branches on the same issue now share one count, so a stacked PR starts with the rounds the first branch used. A branch already in review starts its count again once.
