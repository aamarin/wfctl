`wfctl status` now has a ninth step, `review`, after `implement`. Previously, a story read complete as soon as implement was done, so the review panel ran only when someone remembered it. The step reads done only once every review group has reviewed the newest commit or a person has signed off on it, and it reads the same state the PR guard checks. A commit after a review reopens it, and an unattended run starts the panel on its own. A group that has used all its review rounds stops the run and asks for a person's sign-off. A change that needs no spec can now say so with `wfctl spec none --reason "…"`, which skips brainstorm through decompose, judges implement by `wfctl verify` alone, and sends the branch on to review. `wfctl check-body` then requires the reason in the PR body. The `status --json` payload moves to 1.4, with a `no_spec` key.
