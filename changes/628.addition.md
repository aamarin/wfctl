Every change now runs the design passes before it is coded, including a bug fix or a copy edit that skips the spec pipeline. A new `design-passes` skill asks whether the change needs a spec, reads the accepted records and the domain model, and requires a failing test first. A repo can list PR sections under `change_sections` in `wfctl.json`, and `wfctl check-body` then reports a listed section that is missing, empty, N/A, or answered with only a yes or no. `wfctl check config` checks that the PR template carries each listed section.
