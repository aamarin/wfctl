Claude Code no longer warns at every session start that one of wfctl's auto-approve ask rules reads its `*` literally. The `uv run --project` rule now asks before that command with any arguments. The next `install-skills --agent claude` you run in your own terminal lists the old rule's removal and asks before it changes `.claude/settings.json`. Install now asks before any change to an existing settings file, and `--yes` doesn't answer that question. With nobody at a terminal, as in `post_create` or an agent's run, install leaves the file alone and prints the command to run. `wfctl doctor` lists the pending changes as warnings and no longer exits 1 over a missing or outdated hook. Under Claude Code, `wfctl start`, `wfctl auto-approve on`, `wfctl arch accept`, `wfctl review sign-off`, and `wfctl arch approve-imports` now refuse when `.claude/settings.json` lacks the worktree guard hook or one of wfctl's ask rules, and print the install command to run in your own terminal. Under Bob Shell, the same commands refuse when `.bob/settings.json` lacks the worktree guard hook. A wfctl release that adds an ask rule therefore stops new sessions until you run that install.
