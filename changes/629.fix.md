The check that stops a second conversation from taking over a branch now works under Claude Code with no shell profile line. wfctl reads the session id from the agent `WFCTL_AGENT` names, and `WFCTL_SESSION_ID` still overrides it. `wfctl start --session-id` now refuses an id that differs from the one the environment gives, since the commands after `start` read only the environment and would refuse your own conversation.

The first `wfctl start` on a branch after upgrading prints "this conversation now holds the branch", because earlier sessions recorded no id. Starting again after your own `wfctl end` prints "this conversation holds the branch again". Only a different conversation is told it took over.
