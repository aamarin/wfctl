In Claude Code, the agent can now run `wfctl arch accept`, `wfctl review sign-off`, and `wfctl arch approve-imports` for you. Claude Code asks you before each one runs, and your yes at that prompt replaces running the command in your own terminal. None of the three asks you to type a confirmation when the agent runs it, and `--agreed` is optional there. Instead, the agent has to name the commit for a sign-off or an import approval, as in `wfctl review sign-off --head e5e80be`, so the prompt shows which commit you're approving, and the command refuses if the branch has moved past it. At a terminal, all three behave as before.

`install-skills --agent claude` adds three `permissions.ask` rules for this, and `wfctl doctor` reports any that are missing. The worktree guard lets the agent run only the plain spelling those rules match, such as `wfctl arch accept <slug>`, and refuses every other form it refused before. That includes `uv run wfctl`, since it runs the branch's own copy, so all three always run the installed wfctl. It still refuses all three in Bob Shell and in a project missing the rules, and it refuses them unless Claude Code is in its default, accept-edits, or plan mode, since in auto mode Claude Code ran the accept without asking. It reads the rules from the folder Claude Code was launched in. The commands still need a terminal under a Codex agent started from Claude Code. While wfctl's auto-approve is on, the agent can still run them, and Claude Code's prompt waits for your yes.

`wfctl review sign-off --branch <name>` signs off on another branch's tip without checking it out, and refuses when the local branch doesn't match origin's. The release script now prints `wfctl review sign-off --branch release/v<version>` for the agent to run from `main`, in place of a `git switch` that left `main` on the release branch.

Sign-off and approve-imports are now read the same way as the accept, so a `grep` or a commit message that names them is no longer refused.

`wfctl arch check-accept <slug>` runs what `wfctl arch accept --dry-run` runs, without Claude Code asking. The dry run still works, and Claude Code asks before it, since its rule matches the accept.
