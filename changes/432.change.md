`/start-session` loads only the branch's own context. It runs `wfctl status --session`, which prints the branch's issue, its parent, its open PR, its newest commits, and the handoff without the sections the commits already show, and it no longer loads the repository's open issues and PRs. `wfctl doctor --session` leaves out claim notices about other issues. On an issue branch whose handoff names no first action, the session now starts from the branch's progress instead of asking. A repository that installed the GitHub tracker before this release should run `wfctl install-skills --tracker github`, or the report prints `Parent: unsupported` and `PR: unsupported`. The skill is shorter, since its reasoning moved to a reference file that a session opens only when the skill is being changed.
