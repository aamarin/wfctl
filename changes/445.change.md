Every `wfctl issue` verb, and every `wfctl change` verb except `check`, now checks its template against the same rules `wfctl tracker-check` uses before sending anything. A template that `tracker-check` rejects is now skipped with a warning and exit 0 instead of running. That includes a custom verb such as `reopen` and a template using a placeholder the verb doesn't allow, such as `comment` with `{title}`. A template using `{me}` with no `identity` set gets the same warning and exit 0, where it used to exit 1. Run `wfctl tracker-check <name>` to see what a skipped template needs.
