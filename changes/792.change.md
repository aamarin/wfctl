The worktree guard no longer refuses a command as if it ran the accept command when the command only names wfctl in its text. That covers a commit message, an issue body, or a review reply that formats a wfctl command or a file path in backticks, a file copied from a path that runs through a folder named wfctl, and a quoted jq filter that names wfctl. The guard now refuses the accept command's three words wherever they appear in a command, however they're quoted, unless it's a dry run on a line of its own, such as `wfctl arch accept <record> --dry-run` or the same behind `uv run`. A dry run chained with or piped to another command, one holding a heredoc, or a substitution such as `$(…)` or a backtick even inside quotes, one run by `xargs` or behind an assignment, or one where a redirection could take `--dry-run` as its file or comes right after `--agreed`, as in `--agreed >f --dry-run`, where wfctl reads the flag as the citation, or one with a `#` before `--dry-run` or a redirection such as `2>&1` anywhere, is refused too. A commit message, a `grep` search, or a `towncrier create` note can still name the full command, as long as it's the only command on the line, a commit or a search takes only short options such as `-m` or `-rn`, and the text holds no `$`, backtick, or backslash inside double quotes, and nothing outside quotes beyond letters, digits, and plain punctuation. Anywhere else, write "the accept command" or pass the text in a file.
