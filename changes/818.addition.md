A new `/threat-baseline` command builds your repository's whole-system threat model and commits it as `THREAT_MODEL.md` at the repository root. It runs Anthropic's `threat-model` skill, which now ships with wfctl, unedited apart from its credit line, and adds a line saying the file is a working map and a section listing fixes that were considered and rejected. With auto-approve off, it interviews you after reading the code. With it on, the agent answers the four threat-modeling questions itself and records what the code can't answer as open questions.

If a branch writes a `## Threat model` section in an architecture record and no `THREAT_MODEL.md` is committed, `wfctl status` now pauses brainstorm on a new `threat-baseline` pass and names `/threat-baseline` as the next command. A branch already past `spec.md` gets a warning instead. If your repository keeps its threat model somewhere else, run `wfctl step none brainstorm.threat-baseline --reason "…"` yourself, and put the reason in the PR body.

Run `wfctl install-skills --agent claude` to install the new skills. It also adds `.threat-model-state/` to `.gitignore`, since the threat-model skill writes its checkpoints there. Claude gets `/threat-baseline` but no `/threat-model`, because upstream's skill would approve any `git` or `gh api` command without asking. `/threat-baseline` reads upstream's files instead, so each command upstream runs goes through your usual permission check.
