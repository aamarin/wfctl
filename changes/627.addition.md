A new `review` check on GitHub fails a PR while a review group has commits it hasn't reviewed. When a review group completes a run, or a person signs off, wfctl now adds a git note to that commit and sends it to `origin`, and the check reads those notes. CI requires every group `main` lists, plus any group the PR adds, so a PR can't skip a review by removing its group. `wfctl check reviews` runs the same check locally, and `wfctl store reviews` resends notes that didn't reach GitHub. The worktree guard now blocks an agent from writing a git note or pushing a notes ref by hand.
