In a spec root that's a worktree of its own, such as a `specs-trunk` checkout, the worktree guard now asks you before a git command that syncs the store with `origin`, instead of refusing it. Those are `push` (a force push only as `--force-with-lease --force-if-includes`), `pull` (optionally `--rebase` or `--ff-only`), `fetch`, and `rebase` onto the spec root's own branch on `origin`, or its `--continue`, `--abort`, and `--skip`. Every other git command there is still refused, since it could act on another feature's worktree or branch, and the refusal lists the forms that ask. Claude Code shows the prompt in the default, accept-edits, and plan modes. Other modes and Bob Shell still get the refusal, which now says which mode would ask, or to run the command in your own terminal. A project that ran the guard through a wrapper script to get this prompt can go back to the plain `wfctl hook worktree-guard` entry, so `doctor` and `install-skills` stop asking to add the guard.
