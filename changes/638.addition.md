While any review group has commits it hasn't reviewed, the worktree guard now blocks `gh pr create` and `gh pr merge` and lists those commits under each group. On every branch, it blocks any form of those commands it can't read reliably, such as `gh pr create` chained after another command or run with an environment prefix. It also blocks any `gh` followed by a word that isn't one of `gh`'s commands, including text such as a commit message mentioning "the gh CLI". Each refusal says how to rewrite the command. To get past a review refusal, run the review groups with `wfctl review start` and `wfctl review check`, or have a person run `wfctl review sign-off` in their own terminal. The guard blocks that command when an agent runs it. The new `wfctl review groups` command lists the groups in the order they run. The `opening-a-change` skill now runs the security group before the code group on every change, and `fanning-out-code-review` runs each group through wfctl's review commands.
