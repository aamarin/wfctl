wfctl now stores the spec files of each branch for you. Previously, nothing committed or pushed them, so they could sit uncommitted for weeks. `wfctl store specs` commits one branch's spec files in the spec store, the separate git checkout that holds them, and pushes them. `wfctl check specs` lists every branch whose spec files are not stored yet. The implement step now ends with that store, and removing a worktree runs it first, going ahead with a warning if the push fails. Removal also no longer calls uncommitted spec files "durable".
