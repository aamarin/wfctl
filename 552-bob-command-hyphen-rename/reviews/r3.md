WARNING  wfctl/cli.py:L2985-2987, docs/reference.md:L279, docs/architecture/mirror-supersedes-the-wrapper.md:L120, tests/test_install_skills.py:L617-621. The stated mechanism is contradicted by Bob Shell's own source. The code change still stands, but the rationale written into a durable record, the user reference and a test docstring needs correcting.

What 2.0.4 does: `BobUserConfig.initialize()` runs `new CommandMigrator(fs).init([process.cwd()])` on every start. `_loadLocalCommands` globs `{.bob,.agents,.claude}/**/commands/*.md`. `_writeSkills` writes each one to `.bob/skills/<basename>/SKILL.md`, skips any whose `SKILL.md` already exists, and forces the metadata `user-invocable: true, disable-model-invocation: true`. The skill loader then validates names against `^[a-z0-9]+(-[a-z0-9]+)*$`.

That has three consequences:
- (a) `.agents/commands/` is installed by the base layer for every agent, and it feeds the same migrator. Deleting `.bob/commands/` changes nothing Bob sees. What goes is a redundant third copy, not the wrappers' path into Bob.
- (b) "Bob lists it beside the skill it points at" (test docstring) is false. Every hyphen-named wrapper has a same-named skill that wfctl installs into `.bob/skills/`, so the existence check skips it. Nothing is listed twice.
- (c) "never as a slash command / reaches no menu" is too strong. Bob's embedded skill-authoring guide says a `user-invocable` skill runs when the user types `/<skill-name>`. `wfctl.md` has a valid name and no same-named skill, so Bob turns it into `/wfctl`, from `.agents/commands/` both before and after this change. The dead ones are the twelve dotted `speckit.*` wrappers, which fail name validation, and that is what #552 originally observed.

The stripper was moot for the same reason: the migrator overwrites `disable-model-invocation` to `true` whatever the source file says.

→ Restate the reason as the mechanism. Bob migrates every `{.bob,.agents,.claude}/**/commands/*.md` into `.bob/skills/` at startup, so `.bob/commands/` duplicated what `.agents/commands/` already gives it, and the frontmatter strip was overwritten by the migration. Re-check against 2.0.5 before rewording, since my evidence is 2.0.4. The record's log line matters most, because it outlives the commit.
