### Findings

WARNING  wfctl/cli.py:L2985-2987, tests/test_install_skills.py:L617-621, docs/reference.md:L279 — These say a wrapper in `.bob/commands/` "only duplicates the skill it points at" and that "Bob lists it beside the skill it points at, so the layer ships skills only". That implies the duplication ends here, and it doesn't. Bob's migrator also reads the base layer's `.agents/commands/`, which every install writes. As a result, `speckit.clarify`, `speckit.analyze`, and the other dotted wrappers still become `.bob/skills/speckit.clarify/` and so on, next to `speckit-clarify`. Removing `.bob/commands/` removes a redundant second source for the same migration, and that is a better reason than the one given. A Bob user who reads the reference row will expect no wrapper entries and will still see them. → Reword all three to say that Bob migrates `{.bob,.agents,.claude}/**/commands/*.md` into skills, so `.bob/commands/` duplicated the base layer's copy and installed nothing new. If the dotted duplicates in Bob's skill list should go away too, that needs a separate mechanism, so file a follow-up issue rather than implying this change does it. The commit message makes the same claim and is worth correcting when the branch is next rewritten.
