## Findings

### BLOCKER `wfctl/agents/skills/speckit-{specify,plan,tasks,implement}/SKILL.md:L4` — four of the seven copied grants carry no `Write`, so the step still stalls at its own artifact

The commit's second paragraph states the failure it exists to prevent:

> the name would resolve, the workflow would start, and the first `Write` would
> be refused. That is further into a run before stopping than no route at all.

Then it copies, verbatim, four grants that contain no `Write` and no `Edit`:

| Step | Grant copied onto `SKILL.md` | What the skill body writes |
|---|---|---|
| `speckit-specify` | `Read Glob Bash(wfctl status*) Bash(wfctl issue view*) Bash(git branch --show-current*)` | `SKILL.md:129` — "Write the specification to SPEC_FILE"; then `FEATURE_DIR/checklists/requirements.md` |
| `speckit-plan` | `Read Glob Bash(wfctl feature-paths*)` | `SKILL.md:68-69` — `research.md`, `data-model.md`, `contracts/`, `quickstart.md`, and the filled `IMPL_PLAN` |
| `speckit-tasks` | `Read Glob Bash(.specify/…/check-prerequisites.sh*) Bash(wfctl feature-paths*)` | `SKILL.md:79` — "**Generate tasks.md**" |
| `speckit-implement` | `Read Glob Bash(…check-prerequisites.sh*) Bash(git rev-parse*) Bash(wfctl feature-paths*) Bash(wfctl arch context*) Bash(wfctl arch-root*) Bash(wfctl blocked*)` | the implementation itself, plus `SKILL.md:180` — the `implement-complete.md` sentinel |

The commit's opening scenario is `/speckit.specify` — the first step after
brainstorm, and the first row in that table. The route now resolves and the run
stops one tool call later at an unapproved `Write`, which unattended is the same
stall. #396's own text makes this part 2 of the fix ("or the mirrored skill runs
with no grant at all"), and the repo has already paid this exact bill once:
`test_decompose_allows_the_commands_its_notify_gate_needs` records #240 widening
decompose's `Read Glob` for precisely this reason — "an unwritten `delivery.md`
leaves decompose `pending` and unblocked, which is `auto: true` again".

"Verbatim rather than narrowed" is a sound rule and I am not asking to break it.
I am asking that it be applied in the direction the rule permits: widen the
*wrapper* and the mirror together, as #240 did, so the two entrances still agree.
`Write` on all four; `Edit` on `speckit-implement`, which changes existing files
by definition.

If the author's position is that grant sufficiency is out of scope, the minimum
is to drop `Closes #396` and file the follow-up — but the commit cannot both
argue that a grantless mirror is worse than no route and ship four of them.

### NIT `tests/test_skill_cross_references.py:L377-379`, `wfctl/cli.py:L2777` — `allowed-tools` is a pre-approval list, not a ceiling

The new docstring opens "`allowed-tools:` is a ceiling on the whole turn". The
published documentation says the opposite, for both surfaces:

> The `allowed-tools` field grants permission for the listed tools during the
> turn that invokes the skill, so Claude can use them without prompting you for
> approval. […] **It does not restrict which tools are available: every tool
> remains callable, and your permission settings still govern tools that are not
> listed.**
> — https://code.claude.com/docs/en/skills.md

Slash-command frontmatter takes the same fields with the same semantics, so the
verbatim copy is enforcement-neutral. The repo's own
`test_decompose_allows_the_commands_its_notify_gate_needs:L496` already states
it correctly — "Attended that cost a permission prompt someone answered" — so
the file now holds both readings a hundred lines apart.

This is a NIT only because unattended the two readings converge: an unanswered
prompt is a stall. It matters anyway, because the correct reading is what makes
finding 1 a defect rather than a preference — "copy it verbatim" is sufficient
under the ceiling reading and insufficient under the true one.
