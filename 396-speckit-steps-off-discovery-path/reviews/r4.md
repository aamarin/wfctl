**Three grants the workflow still needs and does not have.** Each is the exact

WARNING `wfctl/agents/commands/speckit.plan.md:L12` — **plan cannot reach the
`Write` this commit gave it.** `speckit-plan/SKILL.md:59` is Outline step 1: "Run

`Bash(.specify/scripts/bash/setup-plan.sh*)`.

WARNING `wfctl/agents/commands/speckit.implement.md:L4` — **implement cannot run
`wfctl verify`, which is the step's completion condition.**
`speckit-implement/SKILL.md:189` is step 9c, and `_predicates.verification_block`
(`wfctl/_predicates.py:487`) is what reads its record: with a definition of done
configured and no record, it returns `"unverified — run \`wfctl verify\`"` and

`test_decompose_allows_the_commands_its_unattended_run_needs` already documents
one step over — the predicate stays unsatisfied, the step stays unblocked,
`speckit-orchestrate` re-emits the command. → add `Bash(wfctl verify*)`.
Note the ordering this creates today: the commit makes the sentinel at 9b writable
unattended while 9c stays unreachable, so the run can now put on disk the file the
skill itself calls "not evidence" and still cannot produce the evidence. No
false-`done` results — `verification_block` holds the line — but it is the wrong
half to have unblocked first.

WARNING `wfctl/agents/commands/speckit.specify.md:L12` — **specify's `mkdir` is
still ungranted.** `speckit-specify/SKILL.md:94` is `mkdir -p

clarify, analyze, brief — and `test_each_review_wrapper_allows_the_commands_the_scan_file_needs`
pins `mkdir` by name for the review steps. specify is the outlier. The commit
message singles specify out as "the one an unattended run reaches first", which is
the reason to close this in the same change. → add `Bash(mkdir*)`.

WARNING `tests/test_skill_cross_references.py:L332-L336` — **the guard's message
fails in the case it is written for.** `next(...)` carries no default, so a wrapper
with no `allowed-tools:` line at all raises `StopIteration` instead of reaching the
assert. That is not a hypothetical shape: 21 of the 35 wrappers under
`wfctl/agents/commands/` carry no `allowed-tools:` line, so a ninth step whose
wrapper was copied from a neighbour lands in this path by default. Verified by
replaying the test's parser over synthetic frontmatter (worktree untouched):

| wrapper shape | result |
|---|---|
| grant present, no `Write` | `Write present: False` → asserts, names the step ✅ |
| no `allowed-tools:` line | `StopIteration`, test errors with no message ❌ |
| `---` horizontal rule later in the body | parses correctly ✅ |

The suite still goes red, so the net holds; what is lost is the docstring's
promise that the failure names which step. → `next((ln for ln in … ), "")`.

NIT `tests/test_skill_cross_references.py:L338,L341` — `"Write" not in allowed` is a
substring test, so a future `Bash(scripts/WriteReport.sh*)` entry would satisfy it
(confirmed in the same replay). Low likelihood, and the sibling tests share the
idiom; noting it rather than pressing it. A tighter form is
`"Write" in allowed.split()`.

**Does the test fail when it should?** Yes, for the case the commit is about —
removing `Write` from any of the eight produces the named-step assertion. The
`implement`/`Edit` arm is keyed on the step name, so it is an exception list of one
and a future step that edits an existing artifact in place gets no `Edit` check.
That is what the commit argues for and I agree with it; flagging only so the
limit is on record.

**Invariant wording.** The docstring says "every `_STEPS` row produces a file".
That reads slightly wide for `decompose`, whose step is partly `wfctl issue create`;
its artifact is `delivery.md` (`_predicates.decompose:1062`), so the claim survives,
but the sentence would be truer as "every row writes a file".

## Pass 2 — Security

Covered: what the widened grant actually exposes, and whether it is the minimum
the grammar allows.

`allowed-tools` has prefix scoping for `Bash(…*)` and **none** for `Write`/`Edit` —
there is no path-restricted form to grant instead. So `Write` on a wrapper
pre-approves writing anywhere the session can reach, not just `FEATURE_DIR`. That
is the real cost of this diff and it is unavoidable in the current grammar; the
minimum *available* is not the minimum *desirable*. It is also not a new exposure
class: `speckit.brainstorm`, `speckit.clarify`, `speckit.analyze` and
`speckit.decompose` already grant unscoped `Write`, and three of them grant `Edit`
too. `implement`'s `Edit` is squarely in scope — editing source is the step's whole
job. No secrets, no untrusted input, no new external surface. No finding.

- Placement in `tests/test_skill_cross_references.py` is consistent — that file

  (`test_skill_cross_references.py:334, 439, 472`, `test_scan_files.py:271`,

  See pass 6.
- Redundancy introduced: the walk subsumes the bare `assert "Write" in allowed` at

## Pass 4 — Readability & simplification

Covered: naming, the docstring, comment convention.

`unwritable` names its content. Appending the string `"implement (Edit)"` into a
list otherwise holding step names is mildly heterogeneous, but it buys a failure
message that says which of the two grants is missing, which is worth more. The
28-line docstring is long by general standards and correct by *this* repo's — the
convention is that a docstring says why the test exists and names the failure it
caught, and this one does, with the #240 precedent. No finding. No comment narrates
the diff to a reviewer.

## Pass 5 — Performance

Covered: cost of the new test. Eight `read_text()` calls on small files inside a

## Pass 6 — Over-engineering

- `tests/test_skill_cross_references.py:L332`: `shrink:` the `split("---")[1]` +
  `next(…)` frontmatter parse is now written three times in this file. A
  module-level `_allowed_tools(path: Path) -> str` collapses each site to one line
  and gives the `default=""` fix from pass 1 a single home.
- Nothing to `delete:` — the test is the minimum check for the rule, and the rubric
  says never to flag a single guard as bloat.
- No `stdlib:`, `native:` or `yagni:` findings. The four one-token wrapper edits are
  already the shortest form.

net: −4 lines possible

## Verdict

**Request changes** (0 blockers, 4 warnings).

The change is real and well-argued: the grants it adds are all used, none is
over-wide for what the grammar allows, the four widenings remove nothing anyone
chose to withhold, and turning #240's unwritten rule into a walk over `_STEPS` is
the right shape. Suite, lint and types are green.

It does not finish the job it names, and the remainder is small and on the same
lines. `speckit.plan` still stops at Outline step 1 before it can use the `Write`
this commit gave it; `speckit.implement` still cannot run the `wfctl verify` its own
predicate reads; `speckit.specify` still cannot `mkdir` the directory it writes
into. Add `Bash(.specify/scripts/bash/setup-plan.sh*)`, `Bash(wfctl verify*)` and
`Bash(mkdir*)` respectively, give the test's `next()` a default so a grant-less
wrapper fails by name rather than by `StopIteration`, and this is an approve.
