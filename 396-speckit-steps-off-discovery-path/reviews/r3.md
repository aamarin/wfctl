## Findings

### BLOCKER — `wfctl/cli.py:L2762-2810` — the mirror drops each wrapper's wfctl layer, not just its grant

The commit's own diagnosis is right and is applied to one line too few:

> a mirrored skill invoked by name never reads the wrapper

`allowed-tools:` is not the only thing on the wrapper. Six of the seven wrappers carry wfctl-specific *instruction* that the `SKILL.md` does not, and each of them says in its own text that it lives there because the skill is `github/spec-kit`-derived. `CLAUDE.md` states the same placement rule.

| Wrapper | Lines | What only the wrapper carries |
|---|---|---|
| `speckit.analyze.md` | 481 | Pass G (design-record contradiction), *Write the scan file* → `<arch-root>/scans/<issue>-analyze.md`, *When nobody answers* remediation policy, the filing gate, the `Acted on + Accepted = Findings` arithmetic, and two explicit overrides of the skill's own **STRICTLY READ-ONLY** rule |
| `speckit.clarify.md` | 324 | *When nobody answers*, *No marker survives the scan*, *Write the scan file*, the whole session-section shape |
| `speckit.implement.md` | 57 | `reading-design-records` before the first task; host-refusal reporting via `wfctl blocked <action>` |
| `speckit.plan.md` | 39 | `reading-design-records` before Outline step 3 |
| `speckit.tasks.md` | 37 | `reading-design-records` before generating tasks |
| `speckit.decompose.md` | 20 | honour a custom grouping instruction |
| `speckit.specify.md` | 15 | nothing — pure pointer |

No `SKILL.md` under `wfctl/agents/skills/speckit-*/` contains a back-pointer to its wrapper (grepped: only `speckit-brainstorm` names `reading-design-records`, and that is the one step whose wrapper is a pure pointer, which is why #361 was safe).

Concretely, after this commit an unattended agent that resolves `next_command: /speckit.analyze` to `Skill(speckit-analyze)` runs the upstream spec-kit workflow with `Write`, `Edit`, `git add` and `git commit` granted and **no instruction to write a scan file**. `_predicates.analyze` reads only that `FEATURE_DIR/checklists/analysis-report.md` exists — which upstream step 6b writes — so the step reports `done`, the pipeline advances, and the PR carries no scan. That is `CLAUDE.md`'s stated reason the scans directory exists:

> a scan that found six problems and one that never ran are the same pull request

The project already has this invariant written down, for the sibling case. `tests/test_install_skills.py::test_no_suppressed_wrapper_carries_more_than_a_pointer`:

> A wrapper that is suppressed must hold nothing its skill does not. Suppression drops the whole file, so anything the wrapper carries beyond "read the skill" is dropped with it — silently.

That test guards the *name-collision* direction and checks frontmatter keys only. This commit opens the same loss from the other direction — invocation by name rather than suppression by name — over wrapper *bodies* of 20 to 481 lines, and nothing checks it. The commit message's own standard applies: "further into a run before stopping than no route at all" is the argument against half-fixing a route; a route that runs to completion having silently dropped the review layer is further still.

**Fix (pick one, all three are consistent with the records):**

- **A (smallest, symmetric with the grant argument).** Add a back-pointer line to each mirrored `SKILL.md` — *"This project layers instructions over this workflow in `.agents/commands/speckit.analyze.md`; read it before proceeding."* — and pin it with a test shaped exactly like `test_every_mirrored_step_carries_its_wrappers_grant`. It is one more in-place edit to a derived file, defended by the identical `vendor-upstream-skills` argument the commit already makes for the grant. Requires `Read` in the grant, which every step has.
- **B (cleanest).** Lift each wrapper's wfctl-only body into a layering skill (the `reading-design-records` / `writing-a-scan-file` pattern this repo already uses) and have both entrances point at it, so neither entrance owns instruction the other lacks.
- **C (narrowest scope).** Restrict `_MIRRORED_SKILLS` to steps whose wrapper is a pure pointer — today only `speckit-specify` — and file the rest behind B.

Whatever is chosen, the invariant the new parity test asserts for `allowed-tools:` should be stated for the wrapper as a whole: *a mirrored step's wrapper holds nothing its skill does not.*

### BLOCKER — `wfctl/agents/skills/speckit-specify/SKILL.md:L4`, `speckit-plan/SKILL.md:L4`, `speckit-tasks/SKILL.md:L4` — three steps are mirrored with grants that cannot complete them

Verbatim copying propagates three wrappers whose grant does not cover the step's own artifact. The commit states the failure mode and then ships it:

> the name would resolve, the workflow would start, and the first `Write` would be refused

| Step | Grant as shipped | What the SKILL.md does |
|---|---|---|
| `speckit-specify` | `Read Glob Bash(wfctl status*) Bash(wfctl issue view*) Bash(git branch --show-current*)` | step 3 runs `mkdir -p "${FEATURE_DIR}/checklists"`; step 6 *"Write the specification to SPEC_FILE"*; step 7a generates `checklists/requirements.md` |
| `speckit-plan` | `Read Glob Bash(wfctl feature-paths*)` | fills IMPL_PLAN, generates `research.md`, `data-model.md`, `contracts/`, `quickstart.md` |
| `speckit-tasks` | `Read Glob Bash(.specify/scripts/bash/check-prerequisites.sh*) Bash(wfctl feature-paths*)` | writes `tasks.md` |

None grants `Write`, `Edit` or `Bash(mkdir*)`. `/speckit.specify` is the step named in the commit's first sentence, and after this commit `Skill(speckit-specify)` resolves and then stalls at `mkdir` or at the first write.

This is a pre-existing wrapper defect, but it is in scope because this commit is what makes the unattended route live, and because the repository has already diagnosed and fixed the identical defect once — `test_decompose_allows_the_commands_its_notify_gate_needs`:

> The list was `Read Glob`, which names neither the `Write` that puts `delivery.md` on disk nor the read that decides whether this run may create issues. Attended that cost a permission prompt someone answered. Unattended the two halves fail differently.

**Fix:** widen the three wrappers the way `speckit.decompose.md` was widened (`Write`, plus `Bash(mkdir*)` for specify, plus `Edit` for plan), then let the new parity test carry the widened line onto the `SKILL.md`. This is the direction the parity docstring already prescribes — *"narrow the wrapper as well, or drop the step from the mirror, but never let the copies differ"* — read toward widening. Add a by-name pin per step in the shape of the two that exist, so the grant is checked against what the step does and not only against its twin.

### WARNING — `tests/test_skill_cross_references.py:L403-421` — parity passes green when both copies lose the grant

`grant()` returns `None` when no `allowed-tools:` line is present, and `None != None` is false, so a step whose wrapper and skill both lose the line reports no drift. For six of the eight steps — `specify`, `clarify`, `plan`, `tasks`, `analyze`, `implement` — no other test pins any grant by name (`brainstorm` and `decompose` are the two that are pinned), so a symmetric deletion of the whole line passes the suite.

This is the exact failure `test_brainstorm_allows_the_commands_its_records_need` spends a paragraph on, and the commit moves that paragraph into the new test's neighbourhood while leaving the hole open for the six unpinned steps:

> equality catches only *one-sided* drift, and an assertion that reads "keep the two lines the same" trains the next editor to change both together — so a symmetric deletion, the shape it invites, passed here green.

**Fix:** one line in the loop —

```python
assert wrapper is not None, f"{skill}: the wrapper carries no grant to mirror"
```

— which also converts the `FileNotFoundError` a missing wrapper currently raises into a named failure. Longer-term this is the same gap the second BLOCKER's by-name pins close.

### WARNING — `wfctl/cli.py:L2739-2810` — mirroring silently converts seven human-typed-only commands into model-invocable ones, and the comment costs this out for one grant of the several that widen

Every `speckit.*` wrapper carries `disable-model-invocation: true`. A `SKILL.md` carries no such key, and none of the seven gained one, so the mirror makes each workflow auto-triggerable off its `description` — five of which are upstream spec-kit text written as a capability statement, not as a pipeline trigger (`speckit-clarify`: *"Identify underspecified areas in the current feature spec…"*). `speckit-brainstorm`'s description was rewritten in #361 to name its pipeline trigger; the seven were not.

The comment reasons this out only for `Bash(wfctl issue create*)`, and the argument there is sound — the gate does not ask which entrance called it. It does not address the rest of what is now model-reachable: `Write` and `Edit` on `speckit-analyze` and `speckit-clarify`, and `Bash(git add*)` / `Bash(git commit*)` on both. An auto-triggered `speckit-analyze` can commit.

**Fix:** either state the argument for the commit/write grants beside the one made for `issue create`, or (better, and it serves the first BLOCKER too) give the seven descriptions the pipeline-trigger phrasing brainstorm carries and pin it by generalizing `test_brainstorm_is_findable_from_the_command_status_hands_out` to walk `_STEPS` — the same generalization this commit made for the mirror test, for the same reason it gives:

> pinning the one step that had been fixed asserted the tree rather than the rule

Leaving that one test pinned to brainstorm while generalizing its sibling is an asymmetry the commit message does not explain.

### WARNING — `docs/architecture/vendor-upstream-skills.md` — five new in-place edits to derived files, undeclared in the record that governs them

The record's standing position is *"Prefer layering to editing"*, with the in-place edits it tolerates explicitly scoped to history: *"Most of the files above were edited in place before this record existed, and they stay that way (#213, #216)."* This commit adds five new ones (`speckit-analyze`, `-clarify`, `-implement`, `-plan`, `-specify`, `-tasks` — six, five of them derived).

The commit's defence is the record's own — a check makes the edit survivable — and I agree with it. But the record currently reads as denying that such edits are made, and the record itself names that as the failure to avoid: *"A record that omits a known exception is read as denying it."* Its Log carries entries for exactly this kind of change (#361, #370).

**Fix:** one Log line and a sentence in the Decision naming the mirrored grant as a second sanctioned in-place edit class, with `test_every_mirrored_step_carries_its_wrappers_grant` as the check that makes it safe. This is `knowledge-placement`'s answer too: the rule *a mirrored step's grant is its wrapper's* is a constraint on the system, and it presently lives only in a `cli.py` comment and a test docstring.

**Verdict: Request changes** (2 blockers, 4 warnings)

The change is directionally right, the test generalization is the correct instinct, and the diff is clean on all three gates. But it fixes half of the mechanism it correctly diagnosed: the wrapper carries more than its grant for six of seven steps, and the grant it does carry cannot complete three of them. As it stands the commit converts "an unattended run stops for a human" into "an unattended run stalls mid-step (specify, plan, tasks)" or "completes the step with the review layer silently missing (analyze, clarify, implement, decompose)" — the second of which the pipeline predicates read as `done`.
