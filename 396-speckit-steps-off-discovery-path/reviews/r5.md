## Findings

**WARNING  wfctl/agents/commands/speckit.specify.md:L12 — the grant still cannot run the
step's own step 3, which comes *before* the write.**
`speckit-specify/SKILL.md` step 3 runs `mkdir -p "${FEATURE_DIR}/checklists"` before anything
is written. The wrapper grants `Read Glob Write Bash(wfctl status*) Bash(wfctl issue view*)
Bash(git branch --show-current*)` — no `mkdir`. Every other wrapper whose workflow makes a
directory grants it (`speckit.brainstorm`, `speckit.brief`, `speckit.clarify`,
`speckit.analyze`), and `test_each_review_wrapper_allows_the_commands_the_scan_file_needs`
pins `mkdir` by name for exactly this reason. The commit body argues specify is "the one an
unattended run reaches first"; as merged, that run still stops one tool call *earlier* than
the `Write` this commit added.
→ Add `Bash(mkdir*)` to `speckit.specify.md`'s `allowed-tools`.

**WARNING  wfctl/agents/commands/speckit.plan.md:L12 — plan's Outline step 1 is a script the
grant does not name.**
`speckit-plan/SKILL.md` step 1 is `Run .specify/scripts/bash/setup-plan.sh --json`, and that
script is not incidental: it `mkdir -p`s `FEATURE_DIR` and copies `plan-template.md` to
`IMPL_PLAN` (`wfctl/specify/scripts/bash/setup-plan.sh:37-47`), which is where every later
step's paths come from. `wfctl/_paths.py:247` and `cli.py:1277` both record that wfctl relies
on that script having run. The wrapper grants only `Bash(wfctl feature-paths*)`; the sibling
wrappers that run a `.specify` script all name it (`speckit.tasks`, `speckit.implement`,
`speckit.clarify`, `speckit.analyze`, `speckit.checklist`). Unattended, plan is refused at
step 1 and never reaches the `Write` this commit added.
→ Add `Bash(.specify/scripts/bash/setup-plan.sh*)` to `speckit.plan.md`.

**WARNING  wfctl/agents/commands/speckit.implement.md:L4 — implement cannot run
`wfctl verify`, which is the artifact its own predicate actually reads.**
The commit's premise is "let every pipeline step write the artifact it produces". For
implement, the sentinel is explicitly *not* the deciding artifact — `speckit-implement`
step 9b says so in its own words ("**This sentinel is not evidence.** … Where one is
configured, step 9c is what decides"), and `_predicates.implement` gates `done` on
`ev.verification`, the record `wfctl verify` writes, per `wfctl-runs-the-verification`. The
wrapper grants `Bash(wfctl feature-paths*)`, `Bash(wfctl arch context*)`, `Bash(wfctl
arch-root*)`, `Bash(wfctl report-block*)` — not `Bash(wfctl verify*)`. So the step can now
write the file that certifies nothing and still cannot produce the one thing that moves it
to `done`; unattended it stalls at 9c with tasks ticked and the step reading `in_progress`.
→ Add `Bash(wfctl verify*)` to `speckit.implement.md`. (Not the same as granting implement a
general `Bash` for running the tasks themselves — that is open-ended by nature and correctly
left out.)

**NIT  tests/test_skill_cross_references.py:L332-337 — the parse raises instead of reporting
for the two failure shapes adjacent to the one it checks.**
A wrapper that is missing entirely gives `FileNotFoundError`, and one with no `allowed-tools:`
line gives `StopIteration` — both are the same defect class the test exists for (a step with
no grant), and both arrive as an error with no step name in the message.
`test_every_pipeline_step_reaches_a_skill_an_agent_can_invoke`, twenty lines up, guards with
`wrapper.exists()` for the first half of this. Cheap fix: `if "Write" not in
next((ln for ln … ), "")`, and let the missing line fall into `unwritable` by name.

**NIT  tests/test_skill_cross_references.py:L338 — the invariant cannot express "this step
only needs `Edit`".**
As written, every `_STEPS` row must carry `Write`, including `clarify`, whose artifact is an
*edit* of an existing `spec.md` — the exact case the commit message argues `Write` is the
wrong tool for. The first step added whose artifact is edit-shaped will be forced to take a
`Write` it never uses, which inverts the minimum-grant intent. It is right not to loosen the
assertion to `Write or Edit` today (that would let all four regress), but the docstring
should say the check is deliberately the coarse one and what to do when an edit-only step
arrives.

**NIT  wfctl/agents/commands/speckit.plan.md:L12 — `plan.md` is a pre-existing file the
workflow fills, and the commit's own Edit argument applies to it.**
`setup-plan.sh` copies the template to `IMPL_PLAN` and the workflow then fills Technical
Context / Constitution Check / Project Structure in place. `_predicates.plan` requires every
name in `_REQUIRED_PLAN_SECTIONS` to survive and requires the file to no longer read as its
own template — so a whole-file `Write` over plan.md is the same "most likely to drop what was
there" risk the commit cites for implement's `tasks.md`. Author's call: the four new artifacts
plan produces are genuinely new and need `Write` regardless, so this is an argument for
*adding* `Edit`, not for swapping it.
