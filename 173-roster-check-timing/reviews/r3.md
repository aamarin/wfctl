BLOCKER  `wfctl/agents/skills/fanning-out-code-review/SKILL.md`:L131-135 — the
fence consults memory **before** disk, so a stale `RETURNED` vetoes a report that
exists.

The `case` is the outer test and `[ -s ]` is nested inside it. A reviewer that
finished, wrote a real report, and was simply not added to `RETURNED` prints
`RUNNING` — and since this same commit makes `RUNNING` a `FAILURE_MARKERS` entry,
`wfctl check-body` then blocks the description over a report sitting on disk.
Reproduced against the shipped fence text (r3 holding a non-empty report, absent
from `RETURNED`):

```
reported  r1
MISSING   r2
RUNNING   r3      # r3.md is non-empty
```

This inverts the step's own premise two paragraphs above it — *"the roster is
checked against the disk, not against what you remember receiving"* and *"the
report is the evidence and its recollection is not"*. Disk should win; the
dispatch list is only needed to disambiguate an **empty** disk.

Fix — same line count, disk first:

```bash
for id in r1 r2 r3; do    # the roster you dispatched
  if [ -s "$REVIEWS/$id.md" ]; then echo "reported  $id"
  else case " $RETURNED " in *" $id "*) echo "MISSING   $id" ;; *) echo "RUNNING   $id" ;; esac
  fi
done
```

Verified: byte-identical output to the current fence on the shipped fixture
(`reported r1 / MISSING r2 / RUNNING r3`) in both `sh` and `zsh`, and
`reported r3` in the case above. The existing zsh-parity test still passes.

**Also checked, no finding:**

- *Correctness of the shell.* `case " $RETURNED " in *" $id "*)` is space-fenced,
  so `r1` does not match `r10`; quoted patterns are literal in both shells; an
  empty `RETURNED` yields all-`RUNNING`, which is the safe direction. The prose
  claim about zsh (*"zsh does not split an unquoted parameter into words"*) is
  correct — `SH_WORD_SPLIT` is off by default — and `for id in $RETURNED` would
  indeed loop once.
- *`elif matched := sorted(...)`* is valid as a bare condition; an empty match
  list is falsy, so the branch behaves as the old `elif [m for m in …]` did.
- *False positives on the marker match.* `_roster` reads only the line beginning
  `roster:`, and matching is case-sensitive uppercase, so a body discussing this
  change does not trip it. Symmetric with the pre-existing `MISSING` behaviour.
- *Security / performance.* No input boundary, no I/O, no secrets; the added work
  is a substring scan of one line.
- *Test quality.* `test_each_failure_marker_carries_its_own_remedy` is a genuine
  regression test — its `FAILURE_MARKERS["MISSING"] not in finding` assertion
  fails against the pre-change shared sentence. The docstrings name the failure
  each test exists for, per `CLAUDE.md`.
- *Comment style.* The new `_body.py` comment and the skill's inline `#`
  annotations inform the next reader rather than narrating the diff.
- *Not run, and owed by the author:* `CLAUDE.md` requires `uv run wfctl
  install-skills` plus a hands-on exercise for any change under `wfctl/agents/`.
  Both write outside my report-only remit, so the mirrored `.agents/` copy is
  still at the pre-change text in this worktree.
