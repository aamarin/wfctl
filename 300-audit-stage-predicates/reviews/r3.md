BLOCKER  `_pipeline.py`:L87–104 — **the eight lines are written as if each step's
predicate decided that step, and for six of them it usually does not.** The
`cascade` flag at the end of the loop (L537–539, `if state == "pending": cascade
= True`) forces every later step to `pending` *without evaluating its predicate
at all*. So none of the eight lines is a sufficient condition and none is
necessary. Executed:

```
spec.md + plan.md + checklists/analysis-report.md present, tasks.md absent
    tasks       pending
    analyze     pending      <- analysis-report.md is non-empty
```

The audit's `analyze` line reads "`checklists/analysis-report.md` is non-empty",
and the file is non-empty, and the step is `pending`. A reader editing
`_infer_steps` — the stated audience, L85 — who trusts these lines will conclude
a step's state is a function of its own artifact. It is a function of its own
artifact *and of every artifact upstream of it*. This is also the reason the
audit's own framing question is ill-posed for six steps: "what the predicate
proves" is undefined where the predicate never ran.

→ Fix: one line before the table. e.g. `Each line below is what the step's own
arm reads. It only runs while nothing earlier read pending — the cascade at the
foot of the loop reports every step after the first pending one as pending
without consulting its evidence.`

BLOCKER  `_pipeline.py`:L106–109 — **"The other six read a file that is there or
is not, which has no inconclusive state for the rule to judge, so a missing
artifact means the step has not run" is false for `decompose`, and false in the
direction that hides the finding #300 scope 2 asks for.** `_unkeyed_issues`
returns `None` for "no map, or a map with no rows", and its own docstring calls
that state by name: *"None means there is nothing here to judge."* That is an
inconclusive reading of a promised artifact, and it is resolved as **proceed**,
locally, without going through `blocks`. Executed, with a tracker configured
(`configured_key_pattern` → `\d+`) and a `delivery.md` holding prose and no
Issue Grouping Map:

```
    decompose   done
```

So for `decompose` the missing evidence means "the step is complete", which is
the exact inverse of the sentence at L108–109. Under `blocks(inconclusive,
accepted-record)` it would block. Whether that divergence is right is #240's
argument, not this diff's — but an audit whose purpose is to make the predicates
"judgeable against the rule" (#300, *Why it matters*) cannot state that six of
them raise no question for the rule when one of them raises it and answers it by
hand.

→ Fix: shrink the claim to what is true — five of the eight read a file that is
there or is not. Then name `decompose`'s third state: `decompose reads a table
inside the file, and a delivery plan with no map at all is an inconclusive read
resolved as proceed, in the arm rather than through blocks (see _unkeyed_issues).`

WARNING  `_pipeline.py`:L87–104 — **two of the three `skipped` arms are unstated,
and `infer_pipeline` folds `skipped` into `is_done=True`.** `brainstorm`'s is
covered (L89). `clarify`'s (L461–465, a spec predating the gate, pinned by
`tests/test_pipeline_commands.py:1045`) and `decompose`'s (L561–562, tasks closed
and no delivery plan at all) are not mentioned anywhere. Both are routes to
"this step does not block and reports done to `infer_pipeline`" on evidence the
audit says is required and which is absent. Executed:

```
spec.md (no ## Clarifications) + plan.md
    clarify     skipped      infer_pipeline -> clarify: True

spec.md + plan.md + tasks.md all ticked + analysis-report.md, no delivery.md
    decompose   skipped      infer_pipeline -> decompose: True
```

The `clarify` line currently reads as though the heading were required for the
step to pass. It is required for `done`; `plan.md` alone is enough for
`skipped`, which every consumer of `infer_pipeline` reads as done, and which
`_current_step_name` declines to route back to.

→ Fix: a clause on each of the two lines, matching the one `brainstorm` already
has. `clarify: … or `plan.md` exists, which reads `skipped` — the scan never
ran.` `decompose: … or the tasks are closed and no plan exists at all, which
reads `skipped`.`

WARNING  `_pipeline.py`:L102 — **`implement`'s second route to "the tasks read
closed" is a file, and the audit does not name it.** `_tasks_open` is
`_has_open_checkboxes(text) and not _file_exists(spec_dir /


`checklists/implement-complete.md` present over a box still open — and a

WARNING  `_pipeline.py`:L87–88 — **`brainstorm`: "some file under the arch root

→ Fix: `brainstorm  a design doc exists, and some file under the arch root
