## Findings

WARNING  wfctl/agents/skills/start-session/SKILL.md:L82-88 — the notice is named
"the one to act on", and the only act prescribed does not fix the worktree the
session is running in. `WFCTL_AGENT` is what `post_create` reads, so it fixes the
*next* worktree; `--agent` is what fixes this one. That split is explicit in the
code (`wfctl/cli.py:2752-2770` prints both halves) and in its test
(`tests/test_install_skills.py:817-823`: "`--agent` fixes the worktree the
developer is standing in. `WFCTL_AGENT` is what `post_create` reads"). Proven by
running doctor with `WFCTL_AGENT=claude` already exported in a base-only tree:
the notice prints unchanged, exit 0. So an agent that follows this paragraph
literally — set the profile variable, then obey L62 "run `wfctl doctor` again and
check it is green" — sees the same ℹ, has no rule for what that means, and
carries on in a session whose `.claude/` paths still do not exist. That is #178's
original symptom. → say both halves and execute neither: "this worktree stays
base-only until someone runs `wfctl install-skills --agent <yours>` in it; the
profile variable is what stops the next worktree repeating it. Report both to the
user in step 8; run neither."

WARNING  wfctl/agents/skills/start-session/SKILL.md:L84,L87 — actor ambiguity in
an executed file. "Set it in your shell profile" and "a setting **you** apply"
address the agent, which everywhere else in this file is the "you" that runs

WARNING  wfctl/agents/skills/start-session/SKILL.md:L174-176 — step 8's new
taxonomy is binary where doctor's is not: "its findings, which exit 1, *and* its
dim `ℹ` lines, which do not" has no room for the `⚠` class that warns without
