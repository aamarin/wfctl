## Findings

BLOCKER  wfctl/cli.py:2951 — `_last_exchange` treats **any** non-tool-result `user`
record as the reader's prompt. Claude Code writes several kinds of `user` record
that the reader never typed: `isMeta: true` skill injections ("Base directory for
this skill: …"), `<task-notification>` wake-ups, `<command-name>` slash-command
records, and compact summaries. When one of these is the most recent boundary at
`Stop` time, the Q3 depth gate is evaluated against machine text and the reader's
own words are gone. Reproduced against the shape found in real transcripts:

```
user: "why does doctor report that layer as stale?"     <- "why" licenses depth
assistant: tool_use(Skill)
user (isMeta): "Base directory for this skill: …"       <- overwrites the prompt
assistant: 300 words
→ Q3 — 300 words of prose, and nothing in the prompt asked for depth.
```

This is AC 5 — *"A long reply that was asked for is not flagged"* — failing on the
exact mechanism the issue says kills a check. Scale: across the 91 wfctl worktree
transcripts under `~/.claude/projects/`, 609 of 2025 turn boundaries (30%) are
`isMeta` / task-notification / slash-command / compact records, and 5 of the 40
transcripts I sampled end on one. It produced no Q3 false positive *in that
corpus* only because `<task-notification>` bodies happen to contain the word
`review` (`<summary>Agent "Review panel r2" finished</summary>`), which is in
`_ASKED_FOR_DEPTH` — the check is currently correct by accident.

→ Fix: skip `record.get("isMeta")` records outright, and for the remaining
non-reader shapes reset `reply` but keep the previous `prompt` rather than
replacing it. A regression test in the shape of
`test_a_tool_result_does_not_start_a_new_turn` — that test found one of the two
ways a `user` record is not a prompt and stopped there.

## What each pass checked, and what it found clean

**Correctness.** Walked `_prose`, `_HEADING`, `_COUNTED`, `_ASKED_FOR_DEPTH`,
`findings`, `_last_exchange`, `_message_text`, `hook_response_shape_cmd`,
`_merge_hooks`, `_unmerge_hooks`, `_check_managed_hooks`, and into
`_settings.merge_hook` / `remove_hooks` / `_is_managed`. The `[::4]` split in
`_prose` is correct for zero, one, two and unclosed fences — I probed all four,
including `~~~`, and the tail-dropping behaviour the docstring claims is real.
The per-pass `existed` sampling is the right fix and I confirmed the settings file
is still unlinked on uninstall. `_last_exchange` is right about sidechains: every
record in the main transcript carries `isSidechain: false`, subagents get their
own file. The `|| true` reasoning on `Stop` is correct and worth the odd-looking
string. The one defect is the BLOCKER above.

**Security.** The only external input is `transcript_path` from the hook payload
and the transcript's own bytes. Path is `expanduser`'d, opened read-only, errors
swallowed; every field is type-checked before use; `OSError`/`JSONDecodeError` are
caught. The finding text interpolates reply content into a bulleted
`systemMessage`, which is the forged-bullet shape `_SKILL_NAME`'s comment warns
about — but both interpolations go through `!r` after `splitlines()`/`" ".join`,
so a newline cannot survive, and the whole payload is `json.dumps`'d. Clean. The
new `Stop` entry does execute a shell command on every turn for everyone who
clones a repo with a committed `settings.json`; that is the existing merge-mode
bargain, and the README omission above is what makes it invisible.

**Architecture.** `_reply` matches `_guard`'s contract exactly — pure functions,
no `wfctl.*` imports, no I/O, decision table separated from the harness — and is
correctly placed in the domain band with `_last_exchange`/`_message_text` left in
the surface. `MANAGED_HOOKS` as a single map earns itself: three call sites
(merge, uninstall record, doctor) had to agree, and the diff shows each one now
reading from it. The `install-modes.md` amendment is honest about the mode not
changing. No cycles, no new upward edge.

**Readability.** Comments are `why`-shaped and match the house style. Names are
concrete. `_prose`'s `[::4]` needs a mental pause but carries a docstring that
earns it. Test names are sentences and every docstring names the failure it
guards — including the "does not flag" cases, which the module docstring
correctly identifies as the load-bearing half.

**Performance.** `_last_exchange` reads the whole transcript per turn, flagged in
the code with a `ponytail:` note. Measured on the largest transcript on this
machine (12.1 MB): 0.059 s to parse, 0.15 s for the whole `wfctl hook
response-shape` invocation. Not a problem; the note is the right disposition.

**Over-engineering.** Little to cut — the diff is lean. The two `NIT`s above
(`Path | str`, the in-loop `gone` dict) are the whole list. The regexes look long
but each is doing work and each is documented; the deliberately over-broad
`_ASKED_FOR_DEPTH` is the right call for a warn-only check.
