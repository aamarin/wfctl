## Findings

Git reads a leading `#` as a comment line, so that ignores nothing, and the "loud, not a fallback" warning the commit exists to add never fires — the silent failure, reproduced one character over. Verified both halves: `worktree_dir(...)` returns `'#'`, and a repo with `#/` in `.gitignore` still reports an untracked `#/x`. → `re.compile(r"^worktree_dir:\s*([^#\s]\S*)")`; a key whose only value is a comment then correctly reads as "does not say" and the warning fires.

WARNING  README.md:L357 — "For `workmux` it also idempotently adds `wt/` to `.gitignore`" is now the same shadowing one layer out: the literal is no longer what the command mirrors. NIT  tests/test_workmux.py:L110 — `test_worktree_dir_reads_a_quoted_value` pins the quoting that never needs quoting. ## Scope note (not a defect, but the claim overstates)

The commit message says the old shape left "the repo's real worktree directory
tracked", and the prompt's acceptance case is "a repo with `worktree_dir: trees`
must end up with `trees/` gitignored". That repo case is unreachable through this
command: the conflict check refuses when `.workmux.yaml` exists, and `--force`
overwrites the repo's `trees` with the template's `wt` before the value is read.
`test_gitignores_the_directory_the_config_names` passes `yaml=` to `_install`,
which writes into the *bundle*, not the repo — it configures the source template.

That is the right design for a seed-once command and the fix is correct for it,
but the value now has one reader of the *template*, not of the repo's config. Say
that in the PR rather than the repo-config framing, or the next reader will look
for a resolver that honours an existing `.workmux.yaml` and not find one.

## Pass-by-pass

**1. Correctness.** Traced `worktree_dir` → `_ensure_gitignored` → `git
check-ignore`. Probed the parser directly on ten inputs: comment-only value
(defect above), empty value (`None`, correct), quoted-with-space (NIT above),
indented key (`None` — matches `patch_seed`'s column-0 rule for `agent:`),
commented key (`None`), duplicate keys (first wins, matches YAML-ish
first-occurrence behaviour elsewhere in the module), `wt#nospace` (kept whole,
correct — YAML needs whitespace before a comment), `../trees` and `/abs/trees`
(returned verbatim; an absolute value would produce a root-anchored ignore, but
it is unreachable from the shipped template and was equally unreachable before).
The move of `_ensure_gitignored` below the write is the load-bearing part and is
right: reading `patched` in memory rather than re-reading the file removes any
window between write and read. Side effect of the move — an early exit in
`_resolve_config_agent`/`project_name` now leaves no `.gitignore` line rather
than an orphan one, which is the better partial state.

**2. Security.** The value flows from wfctl's own package data into a
`.gitignore` line and a `git check-ignore` argv slot. `install-config` has no
`--from`, so the bundle is not attacker-controlled the way `install-skills`'
source can be; `_ensure_gitignored` already passes `--` so a leading dash cannot
parse as an option. A hostile value could inject a negation (`!x`) or a comment
into `.gitignore`, but not a second line (`\S+` cannot span a newline) and not a
shell (no `shell=True`). No secrets, no logging of user data. Nothing to fix.

**3. Architecture.** Correct placement: the parse is a pure `str -> str | None`
in `_workmux`, which the module docstring commits to (no `wfctl.*` imports, no
`subprocess`), and the git/IO half stays in `cli.py`. Line scanning rather than a
YAML parser matches the stated house style and the existing `_WINDOW_PREFIX_LINE`
/ `_EMPTY_PRE_REMOVE_LINE` constants. Grepped for other readers of the value:
none — `wfctl/_guard.py` derives worktree roots from `git worktree list`, not
from a `wt/` pattern, and says so. No second reader was introduced.

**4. Readability.** Comments explain why, not what, and carry the rejected
alternative (the `"wt"` fallback) as the project asks. Function is 6 statements,
no nesting past 2. Two naming NITs above. Test names are sentences and the
docstrings name the failure they catch, per the testing conventions.

**5. Performance.** One extra pass over an ~90-line string per install; the
`git check-ignore` subprocess count is unchanged (still one). Nothing measurable.

**6. Over-engineering.** Nothing to delete. The quote strip is the only speculative
piece and it is one `.strip()` call, so it is not worth cutting even given the NIT
above. The `if wt: ... else: warn` shape is required by the design decision, not
optional flexibility. `net: 0 lines possible` — lean already.
