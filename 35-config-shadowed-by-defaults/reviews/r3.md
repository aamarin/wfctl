## Findings

WARNING  wfctl/cli.py:L2846 — a `worktree_dir` outside the repo produces a junk
`.gitignore` line. `f"{wt}/"` goes to `_ensure_gitignored` unconditioned. Probed
against a real repo: `git check-ignore -q --no-index -- /srv/trees/` exits 128
("Invalid path"), `../trees/` exits 128 ("outside repository"), `~/trees/` exits
1 — and `_ensure_gitignored`'s documented fallback is *non-zero means write it*,
so all three get appended to a **tracked** `.gitignore`. `~/trees/` matches
nothing; `/srv/trees/` is silently re-anchored by git to `<repo>/srv/trees/`.
Out-of-repo `worktree_dir` is a normal workmux setup, and following the config
wherever it points is this change's whole thesis. The repo already has the guard
and the reasoning, at `cli.py:L2079-2082`:
"Only a path inside the checkout can be gitignored by it … `_ensure_gitignored`
would otherwise be handed a path its `check-ignore` call cannot evaluate against
this repo."
→ Fix: mirror it — treat `Path(wt).expanduser().is_absolute()` or a leading `..`
as "not ignorable here" and take the same warning branch as the missing key.
Not a BLOCKER only because the value read is always wfctl's own bundled template
(see the scope note below), so `wt` is the only value reachable today.

WARNING  tests/ — nothing exercises the **real** shipped template. The autouse
`bundle` fixture repoints `_bundle.BUNDLE_ROOT`, so `test_install_config.py`
parses `_WORKMUX_YAML` (a fake); `test_workmux.py`'s `TEMPLATE` is a *trimmed*
copy whose `worktree_dir: wt` line has no trailing comment; and the new
`test_worktree_dir_reads_the_template_shape` hand-copies the real line into the
test body. That is three transcriptions of the value, none compared to
`wfctl/agents/configs/workmux/.workmux.yaml`. A rename, an added quote, or an
indent in the shipped template leaves the whole suite green while every user
silently gets the yellow warning and no gitignore — the exact drift the commit
message says the change exists to prevent. The repo already has the pattern for
bypassing the fixture (`tests/test_skill_cross_references.py:L16`,
`test_skill_attribution.py:L29`).
→ Fix: one test that reads the shipped file and asserts
`_workmux.worktree_dir(path.read_text()) == "wt"`.

WARNING  README.md:L357 — prose still asserts the literal. "For `workmux` it also
idempotently adds `wt/` to `.gitignore`" is now a fourth hand-written copy of the
value, and over-claims: after this change the command adds whatever the seeded
config declares, and adds *nothing* when it declares no key.
→ Fix: "adds the `worktree_dir` the seeded config declares (`wt/` by default) to
`.gitignore`, or warns when the key is absent."

NIT  wfctl/_workmux.py:L38 — `\S+` truncates a value that needed its quotes.
Verified: `worktree_dir: "my trees"` → `'my'`, and `.gitignore` then silently
gets `my/`. The new `test_worktree_dir_reads_a_quoted_value` covers `'trees'` /
`"trees"` — quotes that were never required. The one case where quoting is
load-bearing is the one that mis-parses, and it mis-parses *silently*, which is
the failure shape #35 is about.
→ Fix: `^worktree_dir:\s*("[^"]*"|'[^']*'|\S+)`, keeping the `.strip("\"'")`.

NIT  wfctl/_workmux.py:L38 — a key with only a comment after it reads the comment
marker. Verified: `worktree_dir: # nothing set` → `'#'` → `_ensure_gitignored`
writes `#/`, which git parses as a *comment line*. Nothing is ignored and no
warning fires, so the user gets neither the effect nor the evidence. (`worktree_dir:`
bare and `worktree_dir: ''` both correctly reach the warning branch.) Same fix
as above, or reject a group starting with `#`.

NIT  wfctl/_workmux.py:L121-125 — `shrink:` the loop is a `re.MULTILINE` search.
`m = _WORKTREE_DIR_LINE.search(text)` with `re.M` on the pattern, then

Counter-argument accepted in advance: `patch_seed`, `_block` and `wire_pre_remove`

NIT  wfctl/cli.py:L2844 — the local is named `wt`. In a change whose argument is

## Scope note (not a defect)

The issue's stated symptom — "a repo that sets `worktree_dir: trees` gets `wt/`
gitignored" — is not actually reachable through this command in either direction:
the copy loop at `cli.py:L2812` overwrites `.workmux.yaml` unconditionally (and
refuses without `--force`), so the text handed to `worktree_dir()` is always the
template wfctl just wrote, never a value the repo declared. The real and correct
win is the one the commit message claims: the ignore now follows the *template's*
key, so the two cannot drift. Worth knowing because it is precisely why the
missing shipped-template test above matters — template drift is the only live
failure mode left, and nothing guards it.

Also: this is `Refs #35`, and correctly so. A2/A3 (`--repo`/`--ref` defaulting
over the manifest) and B1 (`_WFCTL_REPO`) are untouched; the issue stays open.
