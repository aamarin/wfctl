### Findings

- **E · Coverage gap, HIGH** — FR-011's second clause is that the version is
  produced without reading the shape file, *so the file's absence cannot break a
  caller*. An implementation task emitted it from a constant and nothing tested
  the absence. A version read off the file and a version emitted from a constant
  are indistinguishable while the file is present, which is every test run.
  → Fixed: new T026 runs `status --json` against a tree with
  `wfctl/contracts/status-payload.json` absent and asserts the command succeeds
  and emits the same version. Decided against folding it into T022, the
  version-equality test: that one needs the file, so a single test cannot hold
  both halves.

- **B · Ambiguity, HIGH** — T013 named its verification as "assert the string
  … carries no imperative verb", for FR-008's requirement that a stall detail
  read as an observation rather than an instruction. No assertion carries a
  claim about wording, so the task named a verification path nobody could write,
  and an implementing agent would have invented one.
  → Fixed: T013 now pins the exact string by equality against a literal in the
  test, and says why that is FR-008's checkable form — the wording cannot change
  without someone editing that line, which is what puts a reword in review.
  Decided against a regex over imperative verbs: it fails on wording nobody
  intended and passes on wording nobody checked.

- **E · Coverage gap, MEDIUM** — FR-017 puts the nested step structure inside
  the versioned surface, and it is the one clause `/speckit.clarify` confirmed
  rather than assumed. T023 renamed "a key" without saying which, so a top-level
  rename would satisfy the task and leave FR-017 unproven.
  → Fixed: T023 now requires one of its renames to be
  `steps[].sub_steps[].manual`. Decided against a separate task: the comparison
  under test is one test file and a second task would split one assertion set.

- **E · Coverage gap, MEDIUM** — FR-012c fixes the recorded type vocabulary as
  JSON names with nullability spelled out. Nothing pinned it. A walker emitting
  Python names, and a file regenerated by that same walker, agree with each
  other — the comparison is symmetric and cannot see a vocabulary that is wrong
  on both sides.
  → Fixed: T029 gains a unit assertion that a nullable object renders
  `"object | null"` and a string renders `"string"`, with the reason the
  comparison cannot do it. Decided against a schema for the file itself: it
  checks the same thing a level lower and adds an artifact this feature's spec
  rules out.

- **E · Coverage gap, MEDIUM** — FR-009's second half is that the derivation
