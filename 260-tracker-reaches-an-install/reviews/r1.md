### WARNING — `README.md:L517-524` documents the behaviour this commit replaced

The diff changes what a bare `install-skills` does to `.agents/trackers/` and
updates no user-facing prose. Two sentences are now wrong or misleading:

> "Once a repo has a tracker, later installs leave the choice and your edits to its
> config alone — re-copy the shipped one with an explicit `--tracker github`."

Edits are still left alone (correct), but "re-copy … with an explicit `--tracker`"
is no longer the only way a *missing* file arrives.

> "That last rule is the upgrade path for `start`/`stop`: a repo that installed the
> GitHub backend before they existed keeps the config it has, so the verbs arrive
> only with an explicit `--tracker github`."

The mechanism described is now half wrong. After this change a bare install *does*
deliver `github-board.sh` to such a repo; what still does not arrive is the
rewritten `github.json` that declares the verbs. The conclusion survives by
accident, the explanation does not — and the explanation is the part a reader
uses to reason about the next backend change.

Fix: one paragraph in the README saying missing backend files are filled by any
install, an in-place config change still needs `--tracker <name>`, and hand edits
are never overwritten. That paragraph is also the natural home for the ceiling the
commit body argues.

### WARNING — `wfctl/cli.py:L2050` `--tracker` help now contradicts behaviour

```
"custom name whose .agents/trackers/<name>.json you author. Omit to leave unchanged.",
```

"Omit to leave unchanged" is exactly the reading #260 was filed against. It is now
true of the *choice* and false of the *files*. Fix: `"Omit to keep the recorded
choice; a missing file of that backend is filled either way."`

### WARNING — `wfctl/cli.py:L2394-2399` names a flag the user did not pass

Verified by probe (scratchpad copy of the post-change tree, bundle missing
`github-issue-create.sh`, run as `install-skills --yes`):

```
⚠ --tracker github, but agents/trackers/github-issue-create.sh is missing from
this wfctl install (…/bundle0) — nothing installed for it
```

No `--tracker` was passed. This is the direct consequence of the commit's own
premise — `tracker` stopped meaning "the caller selected one on this run" — and the
message is the one place the old meaning leaked into user-facing text.

It is not theoretical noise: `doctor`'s remedy is `wfctl install-skills --from
<path>`, and `/start-session` runs it with `--yes`. Installing from an older
checkout is precisely how the bundle ends up short a file, so this is the message
that will actually be read, on an unattended run, telling the reader to look at a
flag they never typed.

Fix: phrase off the trigger, e.g. `f"tracker '{tracker}' is recorded, but
agents/trackers/{fname} is missing from {origin_label} — nothing installed for
it"`. A separate `install_tracker` variable (leaving `tracker` to mean the flag)
is the larger version of the same fix and would keep L2394-2399 and L2531-2536
honest without either of them re-deriving the reason.

### WARNING — `wfctl/cli.py:L2531-2536` fires on a custom backend the fill cannot serve

Verified by probe: repo installed with `--tracker jira` (no config ever authored),
then a bare `install-skills --yes` prints

```
⚠ selected tracker 'jira' but no .agents/trackers/jira.json found — author it
with /scaffold-tracker
```

Two problems. First, wording again — nothing was selected on this run, and this one
now repeats on *every* `/start-session`. Second, the fill branch is inert here by
construction: it sets `tracker = "jira"` and `tracker_skip_existing = True`, but
the copy loop is gated `if tracker == "github"`, so no file can ever arrive and the
condition re-fires unchanged next run. The branch's only observable effect for a
custom backend is a recurring warning.

Arguably that warning is a useful drift signal — a custom tracker with no config
is genuinely broken, and this is the closest thing in the tree to the `doctor`
half of #260. If it is meant to be one, make that deliberate and say so in the
comment; if not, restrict the fill to backends the bundle can actually serve
(`if any(... ) and _tracker_files(recorded) != (f"{recorded}.json",)` reads badly —
better is to skip the fill when `bundle_root / "agents" / "trackers" / f` does not
exist). Either way it should not be an unremarked side effect.

### WARNING — `Closes #260` with decision (2) and the in-place ceiling unfiled

#260 poses two decisions; this change takes (1) and argues the ceiling on (2) and
on in-place refresh clearly in the commit body. That reasoning is good and belongs
where it is. But `Closes #260` retires the issue, and `gh issue list --state all
--search "doctor tracker drift"` turns up no follow-up: nothing tracks "should
`doctor` see tracker drift", and nothing tracks "a rewritten `github.json` still
reaches no existing install" — which is the other half of #232's delivery and of
#260's own title.

The `code-review` skill, step 6: defer "only with written justification (file a
follow-up; 'clean it up later' without a ticket doesn't count)". A commit body is
justification, not a ticket. Open one issue for the `doctor` question before merge,
and reference it from the `# The ceiling that buys:` comment so the next reader of
`cli.py` can find where the decision lives.

### NIT — `wfctl/cli.py:L2536` untrusted manifest value in an unescaped string

`CLAUDE.md` warns that a repo can commit `.wf-skills-manifest.json` and that it
should be read before the first `doctor`. This change makes `manifest["tracker"]`
flow into two places on the *bare* form, where before it needed `--tracker` or an
inherited key:

- `trackers_dir / f` at L2214 — an arbitrary joined path, `.exists()` only. No
  write follows (the copy loop is `== "github"`), so this is an existence oracle,
  not a traversal. `_recorded_path()` exists in this file for exactly this refusal
  and is not used here.
- L2536 interpolates the name into a rich-markup string with no `escape()`, unlike
  every neighbouring `console.print` in this function.

Both are pre-existing shapes reachable through the inheritance branch, so this
commit widens exposure rather than creating it. Low severity, but `escape(tracker)`
at L2536 is a one-word fix that matches the surrounding code.
