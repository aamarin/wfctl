WARNING  wfctl/_review.py:L166-170 — The trunk refusal compares branch names, and two ordinary setups get past it. Both reproduce the failure the commit names: `commit_range` returns no commits, and `review start` reports the group up to date with nothing reviewed.
  1. A tag named like the branch. `git symbolic-ref --short HEAD` disambiguates, so it prints `heads/637-x`, which never equals `637-x`. Repro: in a `--single-branch --branch 637-x` clone, run `git tag 637-x <sha>`, and the range comes back with 0 commits.
  2. A local branch whose name differs from the remote branch it tracks. Repro: in the same clone, run `git checkout -b 637-y origin/637-x`. `origin/HEAD` is `origin/637-x`, the current branch is `637-y`, and the range comes back with 0 commits.
  → Compare full refs. Refuse when `git symbolic-ref -q HEAD` equals `refs/heads/<local>`. Also refuse when `git rev-parse --symbolic-full-name @{upstream}` equals `refs/remotes/origin/<local>`. Add one test for each setup.

WARNING  wfctl/_review.py:L105-111 — `--no-replace-objects` corrects what wfctl lists, but the reviewers still read through the replacement, and the older grafts file isn't covered at all.
  1. `.git/info/grafts` is still honored under `--no-replace-objects` with git 2.44. A grafts line that cuts `a` and `b` out leaves 1 of 3 commits in the range. This is the same gap the commit closes for `git replace --graft`.
  2. A whole-object replacement, `git replace <b> <other>`, makes wfctl list the real `b` as reviewed. But the reviewer's `git diff main..637-x` shows only the replacement's tree, here `innocent | 1 +`. As a result, a completed run records `b` as reviewed when no reviewer saw its content.
  → Refuse the way a shallow clone is refused: fail when `git for-each-ref refs/replace/` prints anything, or when the path from `git rev-parse --git-path info/grafts` exists, and name the command that clears it. That keeps the reviewers' view and wfctl's view of the history the same. Update R3 item 4 to match.
