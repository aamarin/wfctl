### Findings

WARNING  wfctl/_review.py:L464-471 — `check` writes `completed_at` into `run.json` first and `last-reviewed.json` second, and it skips both writes once `completed_at` is set. An interrupt or I/O error between the two writes leaves a run that `check` reports as `complete: security reviewed through <head>` on every rerun, while `last-reviewed.json` is never written. That file is what the next `start` and the #638 guard read. I reproduced this with a run whose `completed_at` was set and no `last-reviewed.json`: `check` returned `complete=True` and the file was still missing. So the docstring's "safe to run twice" holds only on the happy path. → Write `last-reviewed.json` before `run.json`, so a rerun repairs the gap. Or, when `complete`, write `last-reviewed.json` whenever it doesn't already name `run.head`, whatever `completed_at` says. Add a test for the partial state.

WARNING  wfctl/_review.py:L330-341, L246-256 — a `start` interrupted between `path.mkdir()` and `write_atomic(run.json)` leaves an empty `runs/NNN/`. `latest_run` then raises `can't read …/runs/NNN/run.json` for every later `start`, `check` and `relay` on that group (verified), so the group is stuck until someone deletes the folder by hand. The race the L334 comment guards against fails the same way: a second `start` calls `latest_run`, reads the first one's half-made folder and errors, so it never gets to step past the number. → In `start`, take the next number from the directory names alone, not from `latest_run`. In `latest_run`, pass over a numbered folder that has no `run.json` and fall back to the highest one that has it.

WARNING  wfctl/_review_config.py:L32, wfctl/_review.py:L39-40 — `re.match` with `$` accepts a trailing newline. `"money\n"` loads as a valid group, so `check config` stays silent and `start` would create `reviews/money\n/`. `GROUP_NAME.match("security\n")` and `REVIEWER_ID.match("s1\n")` both return True (verified). data-model.md gives `^[a-z][a-z0-9-]*$` as the rule that makes a name "always safe as a directory name", and a newline in the name also splits the `start` header that the panel skill parses line by line. → Use `fullmatch` (or `\Z`) for all three patterns, and add a `"money\n"` case to the bad-name parametrization.

WARNING  wfctl/_review_config.py:L88-99 — a group listed twice is silently collapsed (`declared[name] = entry`), and the later entry wins. `[{"group":"security","reviewers":[]},{"group":"security"}]` loads clean with three Claude reviewers, which hides the empty-list finding. `money` listed with counts 1 and then 5 keeps 5 (both verified). `check config`'s docstring promises "nothing here is dropped silently". → When `name in declared`, append `review group 'money' is listed more than once` and skip the entry.
