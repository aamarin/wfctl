### Findings

WARNING  wfctl/_review.py:L111-L131 (`trunk_refs`): when `_paths.trunk_branch` returns a local name, `origin/<name>` is never added to the `--not` list. That happens when there is no `origin/HEAD` (a remote added with `git remote add`), and on the bare-head and `main`/`master`/`dev` fallbacks. In that case a stale local `main` makes trunk commits merged into the branch read as the branch's own work. Probe 1 reproduced this: after `git merge origin/main`, the range was `feat1, main2, main1, main0`. The failure is closed, since nothing goes unreviewed, but it forces a review round after every `main` merge, which R3 exists to prevent. Once #638 lands it also makes the guard refuse on those commits. This matches R3 item 1 to the letter, so the gap is in the spec as well as the code. The test fixture always sets `origin/HEAD`, which is why the suite doesn't see it.
→ Fix: when `trunk` has no `origin/` prefix and `refs/remotes/origin/<trunk>` exists, append `origin/<trunk>` to `refs`. It is the mirror of the existing branch, one `show-ref` with the same `answers=(0, 1)`. Add a range test with `origin/HEAD` deleted, and amend R3 item 1 to say both directions.

NIT  wfctl/_review_config.py:L175: model names aren't validated. A name holding a newline (`"x\ns9 claude"`, with a matching `commands` key) passes `load`. `review start` then prints it verbatim through `_say`, which puts a fake reviewer line into output the panel skill parses. The repository controls this, and it already controls `commands`, so this is not an escalation. The fix is still cheap, and it also keeps the padded model column sane.
→ Fix: hold model names to the `GROUP_NAME` pattern, with a finding like `review group 'security': model name 'x…' is lowercase letters, digits and hyphens`.

NIT  wfctl/_review_config.py:L189-L201: `count` has no upper bound. `2_000_000` passes and takes 1.85s, and a typo of a few more digits hangs `check config`, `review start`, and later the guard's import path.
→ Fix: cap it, for example at 20, with a finding in the existing `count for '<model>' must be …` wording.

NIT  wfctl/_review.py:L303 and wfctl/_review_config.py: a `commands` value `shlex.split` can't parse, such as an unterminated quote, passes `check config`. `start` then marks the model unavailable with a confusing `` `codex 'unterminated` not found on PATH `` reason.
→ Fix: make it a `check config` finding (`review.commands['codex'] isn't a command line wfctl can split`), since it is a fact about the repository rather than the machine.

NIT  wfctl/_review.py:L391: only a bare backtick fence is stripped before reading the verdict line. A report wrapped in `~~~` reads as `no verdict at the end`.
→ Fix: also strip a line that is exactly `~~~`.

NIT  wfctl/_review.py:L407-L416: `Entry.expected` (bool), `Checked.expected` (int) and `Started.expected` (list of ids) are three meanings of one word in one module.
