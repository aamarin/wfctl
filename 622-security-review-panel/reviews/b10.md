The fix compares the merge with the merge git would have made on its own. `_archive.py:L195` already uses `git merge-tree --write-tree`, so this adds no new git requirement:

```python
def _has_own_edits(repo_root: Path, merge: str, parents: list[str], timeout: float | None) -> bool:
    if len(parents) != 2:
        return True
    auto = _git(repo_root, "merge-tree", "--write-tree", *parents, timeout=timeout, answers=(0, 1))
    if auto.returncode == 1:
        return True
    tree = _git(repo_root, "rev-parse", f"{merge}^{{tree}}", timeout=timeout).stdout.strip()
    return auto.stdout.split("\n", 1)[0] != tree
```

I ran this rule on the same scenarios. It keeps all three merges above and still drops a clean merge from a side branch. An octopus merge is kept, which is the safe default. `git show --remerge-diff --format= --no-ext-diff <merge>` gives the same answer without writing objects. `git diff-tree --remerge-diff` hits `BUG: log-tree.c:1059` on git 2.44, so use `show` if you go that way.
