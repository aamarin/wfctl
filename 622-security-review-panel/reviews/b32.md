## Review: 6bd8954 `fix(review): refuse a shallow clone, and count an unnamed entry toward the cap`

The target does what its commit message says for the shallow refusal and for the reviewer cap, and both have regression tests. Two things hold it back. One `repr` site the message claims to have fixed is still unquoted. And the remedy the new error prints, `git fetch --unshallow`, leads a single-branch clone into a fail-open in the trunk lookup that the branch already had. ### Findings

BLOCKER  wfctl/_review.py:L129-152 and L206-214 (not introduced by 6bd8954) — a clone made with `--single-branch --branch <feature>` sets `origin/HEAD` to the feature branch itself. `_paths.trunk_branch` returns `origin/637-x`, `trunk_refs` returns `refs/remotes/origin/637-x` and `refs/heads/637-x`, and `rev-list --not` those refs drops every commit on the branch. `commit_range` returns `commits=()`, so `review start` prints `security is up to date` and the guard would see no unreviewed commits. This happens without a shallow clone, and it is also where the new message sends a `git clone --depth 1 --branch 637-x` clone: after `git fetch --unshallow` the same clone returns `Range(base=…, commits=())` (reproduced, see below). This repo declares no `trunk` in `wfctl.json`, so it takes the `origin/HEAD` path. → In `trunk_refs` (or `commit_range`), refuse with a `ReviewError` when the resolved trunk names the branch being reviewed, such as `can't find the trunk branch: origin/HEAD points at 637-x; set trunk in wfctl.json`, and add a test that clones with `--single-branch --branch 637-x`. research.md R3 item 2 needs a line for it too.

WARNING  wfctl/_review_config.py:L94 — `review: unknown key '{k}'` still interpolates the key raw. The commit message says the findings that print "an unknown key" now quote it with `repr`, but only the group-level (L117) and reviewer-level (L237) sites changed. `{"review": {"commands\nx": 1}}` prints `review: unknown key 'commands` and `x'` on two lines, which is the split the commit set out to stop. → `f"review: unknown key {k!r}"`, and add a `\n` case beside `review-typo` in `test_a_declaration_that_would_have_passed_silently_is_a_finding`.

WARNING  wfctl/_review.py:L89-103 (not introduced by 6bd8954) — the reasoning behind `ShallowClone` is that `rev-list` can't list commits past a cut, so a completed run marks them reviewed unseen. A replace ref does the same thing and `--is-shallow-repository` says `false`: after `git replace --graft <c> <a>` on a three-commit branch, `rev-list main..HEAD` lists 2 commits instead of 3. Replace refs aren't fetched by default, so this takes a deliberate local command, but the guard exists because the agent shouldn't grade its own panel. → Run every `_git` call with `GIT_NO_REPLACE_OBJECTS=1` in the environment (or `git --no-replace-objects`), which makes `rev-list` list all 3. File it as a follow-up if it's out of scope for #637.
