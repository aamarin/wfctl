## Findings

WARNING  wfctl/agents/skills/reviewing-security/SKILL.md:L38-L47 — The range
commands review commits the run doesn't cover once the branch has merged its
trunk. R3 sets a run's commits to `git rev-list --no-merges <base>..<head> --not
<trunk>`, where the base is the last reviewed commit. US2 scenario 4 is a
branch that merges `main` after a reviewed round. In that case `git log
<base>..<head>` and `git diff <base>..<head>` both include every commit and
every line that came in from `main`. The skill's reason for skipping the
prompt's git section is that it shows "every commit on the branch rather than
the ones this run covers", and its replacement has the same defect in this
case. The prompt then reports `main`'s code as "newly added by this PR". T074
checks for exactly this: "each security reviewer's findings stay inside the
fix commit's range". → Either have the launcher pass the trunk ref, or name it
in the skill as the remote default branch. Then list the run's commits with
`git log --no-merges --no-decorate <range> --not <trunk>` and review those
commits with `git show <sha>`, keeping the range diff for the case where both
lists agree. A test pinning the `--not` in the skill would keep a later edit
from dropping it.

WARNING  wfctl/agents/skills/reviewing-security/SKILL.md:L38, L54, L74-L78 —
The skill quotes text in the vendored prompt by name, and nothing pins that
text. The quoted text is the `GIT STATUS` to `DIFF CONTENT` blocks, the
`FALSE POSITIVE FILTERING` block, "Do not use the bash tool or write to any
files", the three `START ANALYSIS` steps, the cut at confidence 8, and the
last line. The record's whole subject is an upstream pull that changes a file
with nothing failing. If upstream renames a heading or rewords the
no-bash line, the override points at text that no longer exists, and the
reviewer follows the new wording with no skill rule above it.
`a-rule-is-expressed-as-a-check` applies here, because the violation shows in
the shipped tree. → Add a test in the shape of
`test_opening_a_change_routes_an_old_template_to_the_moved_table`. It asserts
that each quoted anchor appears in `references/security-review.md`, and that
`reviewing-security/SKILL.md` still names it.
