WARNING  wfctl/agents/skills/reviewing-security/SKILL.md:L43-47 — The replacement git commands cover more than the run does. R3 defines the run's commits as `git rev-list --no-merges <base>..<head> --not <trunk refs>`. That definition is deliberate, so that merging `main` into the branch costs no review round. But `git log a..b` and `git diff a..b` include everything a `main` merge brought in after `a`. On a branch that merged `main` and then added a fix, the reviewer gets main's whole delta as "the change". It will then review and report on already-merged code. That breaks the skill's own stated reason for skipping the prompt's git section ("rather than the ones this run covers") and the prompt's "focus ONLY on security implications newly added". T074 already plans to check that "findings stay inside the fix commit's range", which this would fail. → Use per-commit patches limited the way R3 limits the range, for example `git log --no-merges -p a1b2c3d..9f8e7d6 --not origin/main`. Or have the coordinator pass the trunk ref and the commit list. `wfctl review start` doesn't print the trunk today, so #637/#638 may need to carry it. If the fix belongs there, note it on #638.

WARNING  wfctl/agents/skills/reviewing-security/SKILL.md:L52-55 — Sub-tasks get the git section the skill told the reviewer to skip.
