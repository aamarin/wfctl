WARNING  wfctl/_review.py:L338-L352 (with `latest_run` at L239) — a run directory is created before its run.json exists. `latest_run` treats the highest-numbered directory as authoritative and raises `can't read …/runs/NNN/run.json` when the file is missing; I reproduced that with an empty `runs/001/`. A Ctrl-C or failed write between `path.mkdir()` and `write_atomic` therefore wedges the group. `start` calls `latest_run` before its own mkdir, and `check` and `relay` call it too, so all three fail until someone deletes the directory by hand. The same window also defeats the race handling the comment claims: a second `start`, or a `check` launched in parallel, sees the new directory before its file and errors out instead of moving to the next number. → Have `latest_run` skip numbered directories that have no run.json. The mkdir loop already steps past them, so nothing else changes. The alternative is to build the run in a temporary directory and rename it into place. Add a test that leaves `runs/002/` empty beside a valid `001` and expects `check` to judge `001` and `start` to open `003`.
