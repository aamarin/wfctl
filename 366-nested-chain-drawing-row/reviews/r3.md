## What each pass checked

**1. Correctness — the row itself.** The row lands at SKILL.md:321, inside
*Show: the drawing is the description*, third of six, immediately under `one source,
several destinations` — the row it extends, which is the right neighbour. Both
columns hold the established shape: left is a bare noun phrase for the material,
right is *form, comma, where the parts sit* (`two columns, counts in the headers`;
`a fan-out, annotations hanging right`; `a flow, exits hanging off the step that
takes them`). It reads like the five already there.

Discrimination from the two nearest rows holds. Against `one source, several
destinations` the discriminator is the word *again*; against `a sequence with exits`
it is that the chain is reached through other nodes rather than being the sequence.
A picker holding #366's own material lands on the new row.

**Arithmetic, re-derived rather than trusted.** `SKILL.md` is 491 lines by
`splitlines()` (the same call the test makes, and the file ends in a newline, so
`wc -l` agrees). `_LINE_CEILING` moves 490 → 491. The diff adds exactly one line to
`SKILL.md`. The "ceiling equals the file exactly" invariant the 483 block set up is
therefore preserved, which is the property that forces the *next* line to argue for
itself. Claim checked, holds.

`digest.md` is 493 characters, unchanged by the diff, against `_DIGEST_MAX_CHARS =
500` (`wfctl/cli.py:4139`) — the cap is characters, and the file is pure ASCII, so
chars and bytes agree at 493. The commit message's "493 of its 500" is accurate, and
its reason for leaving the digest alone is right: the digest projects the six
numbered rules and the no-`##` rule, and never the selection table.

**2. Security.** Nothing executable in the diff. The digest is untouched, which
matters here more than it looks: `digest.md` is read by the `UserPromptSubmit` hook
and its abuse cases are already covered by `tests/test_hook_user_prompt.py`

**3. Architecture — where the knowledge lives.** This is where the one WARNING sits.

The selection table is asserted to be the *single owner* of which drawing a piece of
material calls for, and the test enforces that by searching for the literal header
`| The material is |`. `wfctl/agents/skills/design-levels/SKILL.md:165-175` carries a
paraphrase that the literal-string test cannot see:

```
what shape is the thing?
 ├ two versions of one output ───► side-by-side code block
 ├ one input, several outcomes ──► ASCII fan-out
 ├ a line with sides ────────────► boundary sketch
 ├ N conditions × M outcomes ────► table
 └ one thing ────────────────────► render the string
```

Five branches, mapping material to form, with no nested-chain branch — and it
governs how a **gate answer** is rendered, which is exactly the surface #366's
motivating case (#151/#363, "where is `architecture-design` reached from") is
written on. So the row that was added lands in the reply skill, while the reader who
hit the original failure is picking from this list and still finds nothing for a
nested chain.

The duplication predates this commit; what the commit does is widen the gap by one
row, and each future row widens it again. The remedy is not to add the row in two
places — that contradicts single ownership and is the staleness the invariant test
exists to prevent. Per the rubric's step 6, this is a follow-up rather than
something to smuggle into this diff: either `design-levels` points at the table the
way `pull_request_template.md` does, or it gains the branch. Note the invariants
docstring already anticipates this work ("two more skills point at it once #556
lands"), but #556 does not exist in this repo — `gh issue view 556` resolves to
nothing — so nothing currently tracks it.

**4. Readability.** Two NITs, both on the row's wording, neither worth blocking.

The row introduces *caller* in the right column after the left column has dropped
*of calls*. The commit message, the ceiling comment (`for a chain of calls whose
destinations fan out again`) and #366 all keep "of calls"; only the shipped row
drops it. Restoring it makes *caller* earn its place. Precedent cuts both ways —
`one source, several destinations` → `annotations hanging right` also introduces a
noun from nowhere — so this is a preference, not a defect.

The row is also the only one in the table to drop a clause #366 specified:
"branches hanging off the node that takes them". Defensible, and I would not ask for
it back: it would near-duplicate `a sequence with exits`'s right column two rows
below, and the left column's "fan out again" plus row 2's "annotations hanging
right" compose to the same instruction. Worth recording only because the
specification and the implementation differ and a later reader may wonder.

Mechanical note attaching to the same line: at 98 characters it is the widest row in
the table (the others run 59-78) and the widest body line in a file otherwise
wrapped near 79. Markdown does not care; a terminal reading the raw source wraps it.
Trimming per the NITs above would also bring it back under 80.

**5. Performance.** Not applicable — no code path changed. The one cost model that
does apply is the ceiling's own: context spent per turn. One line for a sixth row in
the most-used table in the file is a good trade, and the comment argues it in the
register of the two exceptions before it.

**6. Over-engineering.** The 14-line comment for a one-line change is in register —
483 took ~12, 490 took ~13, and CLAUDE.md asks comments to carry *why this shape*.
One genuine `shrink:` inside it: lines 73-75 are the third near-verbatim copy of the
same disclaimer, six lines after the second (lines 60-62), differing only in "which
is why" vs "so". A fourth copy arrives with the next exception. Lifting it once,
above the numbered blocks — *"Each exception below ships without an example of its
own; the sentence about cutting rather than adding still governs the seventh rule."*
— removes the growth. `net: −4 lines possible`. Nothing else to cut; the arithmetic
paragraph and the "what the line buys" paragraph both answer a question a future
reader of the constant will actually have, so neither is diff narration.

**Chesterton's fence.** Checked before calling anything removable: the ceiling
constant, its exactly-equals-the-file property, and the no-example rule each have
their reason written beside them, and this change honours all three rather than
spending them.
