WARNING  wfctl/agents/commands/speckit.clarify.md:L36–40 — the new clause puts the
withdrawal-rule question through a rendering the same file forbids completing.
The paragraph now reads *"Ask each question as step 4 renders it, recommendation
and all — including the ones the withdrawal rule below covers."* Step 4's format
is mandatory (`speckit-clarify/SKILL.md` L155–162: every question renders
`**Recommended:** Option X` or `**Suggested:** …`), and L55 of this file says
**"Do not invent a recommendation in order to have one"** for exactly the class
the clause just extended. So the instruction is: render these questions
recommendation and all, and do not render their recommendation. Under the old
unconditional shape the conflict could not arise — the question was never put.
An agent tracing it has two exits and both are bad: invent the recommendation
(the silent decision the section exists to prevent, reached by obeying the new
sentence), or drop the `**Recommended:**` line with nothing said about what
replaces it, on a question the reader is being asked to answer.
→ Say it in the clause: these are put *without* a recommendation, name that as
the one place step 4's format is overridden, and give the line that stands in
its place (*"No recommendation — this is a question only you can answer."*).
That also restores the hand-off to the table's first row, which can only fire
where a computed answer exists.
