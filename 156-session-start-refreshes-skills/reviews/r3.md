## Findings

**WARNING  wfctl/agents/skills/start-session/SKILL.md:L34–L35 — `--agent` guidance is buried in a
comment, and omitting it leaves `doctor` red forever.**
Both layers always report stale together, because one bundle hash is recorded for every layer
(`cli.py:L3466`, "One hash for the whole bundle") — the real output above shows `base` *and* `claude`.
An agent that copies the command and skips the trailing comment runs a base-only install. `install-skills`
writes a fresh manifest entry **only** for layers it installed (`cli.py:L1998–L2005`), so the `claude`
entry keeps its old `content_hash`, `.claude/commands` stays at the old version, and the next `doctor`
reports `claude: skills stale` again — as will every session after that, each re-running the same
incomplete fix. That is precisely the "every session fixes it back and forth" failure the step warns
about eight lines later. → Promote it out of the code-block comment into the imperative sentence:
"pass `--agent <name>` for every native layer `doctor` named beside `base` — a base-only install leaves
that layer stale and `doctor` red."

**WARNING  wfctl/agents/skills/start-session/SKILL.md:L33–L36 vs cli.py:L3499 — the tool tells the agent
to run a different command than the skill does.**
`doctor`'s own repair line is `    update: wfctl install-skills` — bare, no `--prune`, no `--agent`, and
in this repo the wrong wfctl. It is printed immediately above where the agent decides what to run, and
it is the line an agent is most likely to copy. The change's stated purpose (#3: run both through the
same wfctl) is undermined by the tool itself advertising the bare form. → Either make `doctor`'s hint
carry the layer and flags it means, or add one sentence to the skill: "ignore the `update:` line
`doctor` prints — it names neither the layer nor `--prune`, and in a repo that develops wfctl it names
the wrong wfctl."

**WARNING  wfctl/agents/skills/start-session/SKILL.md:L41–L42 — the `--prune` claim is over-broad, and
the step has no instruction for what `--prune` cannot reach.**
The skill says `--prune` "clears paths a past install left behind when they were renamed upstream".
`_check_abandoned_entries` (`cli.py:L3325–L3385`) reports two disjoint sets: `flagged` (still on record,
carrying `orphaned: true`) and `scanned_only` (on disk, absent from the record). `--prune` only removes
the first — the second is unreachable by design ("removing on that evidence would eventually delete
someone's work"), and `doctor` says so: "Delete the rest by hand once you've checked nothing needs them."
Every orphan created *before* `c8e18d5` landed is in the unreachable set, which is the population the
sentence describes. Consequence: the agent runs the refresh, `doctor` still exits 1, and the skill gives
it no next move. → Qualify the sentence ("paths a past install *recorded* and stopped shipping") and add
one line: "paths `doctor` lists that `--prune` does not remove are not on record — surface them for the
user to delete by hand; never delete them yourself."

**WARNING  wfctl/agents/skills/start-session/SKILL.md:L31–L60 — nothing verifies the refresh worked.**
The step ends at "say in one line what changed"; step 8 then asks the agent to report the refresh. No
re-run of `doctor` confirms the mirror is actually level. For a step whose entire premise is that two
invocations can disagree without either noticing, the confirming read is the cheap half and its absence
is how a session reports "refreshed" over a still-drifted tree — and W1 and W3 both produce exactly that
outcome. This repo's own `verification-before-completion` skill states the rule. → Add
`wfctl doctor` after the install in the same block, and make step 8 report its result rather than the
agent's recollection.

**WARNING  wfctl/agents/skills/start-session/SKILL.md:L49–L56 + AGENTS.md:L43–L47 — one rule, two homes,
in a repo with an accepted record against exactly that.**
`knowledge-placement` says "A fact with two homes has no owner, which is the condition this rule exists
to remove," and routes worker guidance to `AGENTS.md`. The same-wfctl constraint is now stated in full in
both places, and the skill's own text concedes the scope ("This only comes up in a repo that develops
wfctl itself") — so eight lines of wfctl-repo-specific reasoning ship to every consumer repo that installs
these skills, where they are inert. The skill already has the correct mechanism (defer to the repo's
`AGENTS.md`); it just also duplicates what it defers to. → Cut L49–L56 to the deferral plus its
consequence, two lines: "Run `doctor` and `install-skills` through the **same** wfctl — they compare
against whichever bundle the wfctl you invoked carries, so mixing them makes them disagree permanently.
If the repo's `AGENTS.md` names an invocation, use it for both or neither." Leave the reasoning in
`AGENTS.md`, which now carries it.

**WARNING  AGENTS.md:L43 vs L54 — the two new paragraphs contradict each other on which is "the one
place".** L43 says `uv run` for `doctor` "is not optional"; L54 then says of `install-skills` "this is
the one place the distinction bites". After the diff there are two such places and both claim to be
the only one. → Reword L54 to "and it bites hardest here" (or drop the superlative), since the
`install-skills` case is the one that silently succeeds while doing nothing.

**NIT  AGENTS.md:L43 — "for the same reason as below" is a forward reference that is immediately made
redundant.** The sentence points down the page and then states the reason in full anyway. → Drop the
clause; the paragraph stands alone.

**NIT  wfctl/agents/skills/start-session/SKILL.md:L38–L40 — "the installed trees are wfctl's own output
— generated, gitignored, never hand-edited" is the justification for `--yes`, but names the wrong file
set.** The prompt `--yes` suppresses fires only on `foreign_overwrites` (`cli.py:L1916–L1924`) — paths
*not* in the record, i.e. the files that are **not** wfctl's own output. Separately, `install-skills`
can append to `.gitignore` (`_ensure_gitignored`, `cli.py:L1544–L1547`), which is tracked, so the
"everything it touches is gitignored" framing has one real exception; it fires when a new wfctl version
adds a gitignore target, leaving an unexplained tracked-file change at session start. The behaviour is
defensible (originals are backed up to `.wf-skills-backup/` and a yellow line is printed) — the
*argument* for it is not, and it is what a future reader will lean on. → Say what is actually true:
"`--yes` is required because a session's shell is not a TTY and the overwrite prompt would abort rather
than prompt; any pre-existing file it overwrites is backed up and named in the output — surface that
line if it appears."

**NIT  wfctl/agents/skills/start-session/SKILL.md:L124–L127 — the step 8 justification does not parse
as an argument.** "Omit if all current and nothing was refreshed — a silent refresh is how a mirror gets
stale again without anyone noticing it had been wrong." A refresh does not make a mirror stale; the
clause is arguing for the opposite branch of the sentence it is attached to. The "(the tool)" parenthetical
also narrows the residual wrongly — after a refresh `doctor` can still flag skills (unpruned orphans, a
half-refreshed layer, per W1/W3). → "Report every refresh, even a clean one: a refresh nobody hears about
is how the next session inherits a mirror it has no reason to doubt. Include anything `doctor` still
flags."

**NIT  .workmux.yaml:L78 — `--prune` in `post_create` can never fire.** `--prune` diffs against
`.wf-skills-manifest.json`, which is gitignored and therefore absent from a freshly created worktree, so
`prior_layer_items` is empty and `orphans` is always empty at the only moment this hook runs. Harmless
today; unexplained, and the surrounding comment (rewritten in this diff) explains `uv run` but not this.
If it is defensive, say so in one clause; otherwise drop it. Note the hook is also non-interactive with
`|| true`, so were a manifest ever to reach a new worktree (`files.copy`, a repo that commits it), the
prune would run and its output would be swallowed.

**NIT  AGENTS.md:L23 — "653 tests, ~45s" is stale; the suite is 816 tests, ~57s** (measured above).
Pre-existing, not introduced here, but this diff's whole subject is `AGENTS.md` telling the truth about
what to run, and the line sits nine lines above the paragraphs being corrected. Cheap to fix while open.

**NIT  .workmux.yaml:L78 — the hook now requires `uv` on PATH, and `|| true` still swallows its
absence.** Previously a missing `wfctl` produced a skill-less worktree; now a missing `uv`, an
out-of-sync `uv.lock` needing a re-lock with no network, or a cold uv cache does too, with the same
silence. Pre-existing failure mode, slightly wider surface. Not worth changing for this repo (`AGENTS.md`
already makes `uv` mandatory) — noting it because the same `|| true` is what made the original drift
invisible.
