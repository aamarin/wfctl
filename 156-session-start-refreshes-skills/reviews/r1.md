## Findings

**BLOCKER  `wfctl/agents/skills/start-session/SKILL.md:33-36` — the refresh can leave the mirror
the agent actually reads stale, and report it as fixed.**

The command in the block is `wfctl install-skills --prune --yes`. The native layer is only in a
trailing inline comment ("plus `--agent <name>` for any native layer doctor named beside
`base`"), and nothing verifies the result. Reproduced:

```
$ wfctl install-skills --agent claude --prune --yes   # worktree as created
$ echo "# drift" >> wfctl/agents/skills/start-session/SKILL.md
$ wfctl install-skills --prune --yes                  # the skill's command, literally
$ wfctl doctor
✓ base: skills current (wfctl 0.15.0)
⬆ claude: bundled skills changed since install
    update: wfctl install-skills
$ tail -1 .claude/skills/start-session/SKILL.md
tail: .claude/skills/start-session/SKILL.md: No such file or directory
```

`.claude/skills/` — the mirror the harness enumerates — is exactly what #156 says a session
must not start on, and the base-only refresh does not touch it. Prune is layer-scoped
(`cli.py:2058-2068`: `for layer in items`), so this is not data loss; it is silent no-op.
Two aggravating factors, both inside this diff:

- Step 8 (`SKILL.md:124-127`) says report "anything `wfctl doctor` still flags as behind
  **(the tool)**" — it assumes skills are green afterwards, so a still-⬆ layer has no line to
  land in.
- post_create already solves this (`\.workmux.yaml:78` passes `${WFCTL_AGENT:+--agent
  "$WFCTL_AGENT"}`); the session-start path drops that and delegates to the agent's reading of
  doctor's layer names.

Fix: put the layer in the command, not a comment, and add a verification step — e.g.

```bash
wfctl install-skills --prune --yes ${WFCTL_AGENT:+--agent "$WFCTL_AGENT"}
# Repeat with --agent <name> for every native layer doctor named beside `base`
wfctl doctor        # must come back green; a still-⬆ layer means you skipped its --agent
```

and change step 8's parenthetical from "(the tool)" to "(the tool, or a layer the refresh did
not reach)". Optionally also `cli.py:3498`, whose printed hint is `update: wfctl install-skills`
— bare, no `--prune`, no `--agent`; an agent following the tool's own advice reproduces this bug
forever. No test asserts that string, so it is a one-line change.

**WARNING  `SKILL.md:15-22` vs `31-36` — step 1 reads the two output-style skills *before*
step 2 refreshes them.**

Step 1 loads `.agents/skills/i-have-adhd/` and `.agents/skills/conversation-response-shape/`
and says "skip either silently if it isn't installed". A skill that landed after the worktree
was made is precisely what a stale mirror lacks — so on the run where the fix matters most,
step 1 silently skips, step 2 installs the file, and nothing goes back. The change fixes the
disk and not the session.
Fix: either move the freshness block ahead of step 1, or add one line to step 2: "if the
refresh installed or changed step 1's files, re-read them now."

**WARNING  `AGENTS.md:43-47` — "A bare `wfctl doctor` in this repo … reports drift permanently"
is false in this worktree right now, and the direction is backwards.**

Observed here: `uv run wfctl doctor` → `⬆ base` / `⬆ claude`; bare `wfctl doctor` → all green.
`doctor` compares the manifest's recorded `content_hash` against the bundle of the wfctl you
invoked (`cli.py:3461-3497`), and the hash was written by whichever wfctl *installed*
(`cli.py:1927-1932`). So the rule is "the one you did not install with reports drift" — bare
only reports drift once the tree has been installed by `uv run`, which the new post_create makes
true for *future* worktrees. "Permanently" is also load-bearing-wrong: drift lasts while the
working tree differs from the released bundle, which is most of the time in this repo but ends
on release.
Fix: state it as the invariant ("whichever wfctl installed is the one that reports clean") and
add the migration line this diff otherwise omits: every worktree created before this change was
installed by the bare wheel and needs one `uv run wfctl install-skills --prune` to switch sides
— including this one, where the new `uv run wfctl doctor` step of the definition of done
currently exits 1.

**WARNING  `AGENTS.md:128-131` (Safety, untouched) — `"--yes` skips that prompt and is for CI"
is no longer true.**

This diff makes `--yes` the normal session-start path in every repo the skill ships to, and the
prompt it skips (`cli.py:1916-1923`) is specifically the one for files at owned paths that wfctl
did *not* record — the hand-authored case that paragraph is about. AGENTS.md is edited in this
diff; leaving its safety claim contradicting the new behavior is exactly the doc drift the file
exists to prevent.
Fix: amend to "`--yes` skips that prompt — for CI, and for the session-start refresh, which
relies on `layer-model`: the owned trees are generated output. Originals are still backed up to
`.wf-skills-backup/`."

**WARNING  `SKILL.md:38-42` — the rationale for `--yes` does not cover `.claude/settings.json`,
which the auto-run also writes.**

"The installed trees are wfctl's own output — generated, gitignored, never hand-edited" is true
of the layer trees and false of the merge target. With a native layer, install-skills merges a
managed `UserPromptSubmit` hook into `.claude/settings.json` (`cli.py:1147-1166`; observed:
"Merged the managed hook into .claude/settings.json"). That file is not gitignored, is
explicitly expected to be *committed* in consumers (`cli.py:2329`), holds the user's own hooks
and permissions, and wires a command that executes a shell hook on every prompt. So an unasked
session-start step can now modify a committed, security-relevant, user-owned file — and step 5's
`git status --short` will show the session's own change three steps later.
Fix: name it in step 2 ("with a native layer this also merges wfctl's managed hook into
`.claude/settings.json`, a file you own — it is reported and reversible with
`wfctl uninstall-skills`") and require it in step 8's freshness line.

**WARNING  `SKILL.md:44-47` — a skill installed mid-session may not be usable by the session
that installs it.**

The premise is that the session "silently lacks whichever skills landed since". Harnesses
(Claude Code included) enumerate skills and commands at startup, so writing them to disk at step
2 does not necessarily put them in this session's index — the agent can still `Read` them by
path, which is what step 1 does, but `/`-commands and skill activation may need a restart.
Verify against the harness you target; either way the report should say so.
Fix: one clause in the step 8 freshness line — "…and whether the session needs a restart to pick
them up".

**NIT  `.workmux.yaml:78` — `--prune` here is inert.**

`--prune` diffs against `.wf-skills-manifest.json` at the *worktree* root (`_manifest.py:19`,
`_paths.py:44` uses `--show-toplevel`), and that file is gitignored (`.gitignore:15`), so a
freshly created worktree has no record and no orphans to prune. The comment block above the line
argues for `uv run` and against symlinking, and never mentions the flag it adds.
Fix: drop it (−1 line), or keep it for symmetry with the session-start command and say that in
the comment.

**NIT  `SKILL.md:41-42` — "`--prune` also clears paths a past install left behind" overstates.**

Prune only removes *recorded* orphans; doctor's other half — paths found by scanning that were
never on record — cannot be pruned and is reported as "Delete the rest by hand"
(`cli.py:3376-3384`). A session that prunes and then sees that line still standing will loop on
it.
Fix: "clears the paths still on record that this install no longer ships; anything doctor lists
without a `--prune` hint has to go by hand."

**NIT  `SKILL.md:54-55` — "would overwrite the skill edits the session exists to make" reads as
data loss.**

The bare install overwrites the installed *mirror*, not the tracked source under
`wfctl/agents/`; nothing is lost, the session just runs the released copies of files it is
editing. AGENTS.md:54-57 already says this precisely ("your change is nowhere in it").
Fix: match that wording.

**NIT  `AGENTS.md:49-51` — the definition of done still says `uv run wfctl install-skills` with
no `--prune`, while both other files in this diff now pass it.** Pick one.

**NIT  `.workmux.yaml:78` — `|| true` now also swallows "uv is not installed".**

AGENTS.md:27 still supports `pip install -e ".[dev]"`, and this line adds a second binary that
must be on the hook shell's PATH. On a machine without uv the worktree comes up with no skills
at all and says nothing (it surfaces one step later — doctor prints "Nothing installed — run
`wfctl install-skills` first" — so this is recoverable, not silent forever).
Fix: `… || echo "⚠ uv run wfctl install-skills failed — run it by hand" ; true`.
