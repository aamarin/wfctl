### WARNING — `tests/conftest.py:33` · the flag makes the suite machine-dependent

Reproduced on this tree:

```
$ WFCTL_SHAPE_ECHO=1 uv run pytest tests/test_shape.py -q
4 failed, 28 passed
  test_the_finding_reaches_the_model_and_is_not_also_printed
  test_the_report_carries_the_finding_before_the_instruction
  test_the_handed_over_reply_is_preferred_to_the_walked_one
  test_a_line_this_hook_cannot_parse_does_not_stop_the_scan
E json.decoder.JSONDecodeError: Extra data: line 2 column 1
```

Cause: `_run()` (`tests/test_shape.py:187`) reads `result.output`, which is the
*combined* stream, while the new echo test correctly reads `result.stdout`. With
the variable exported, the echoed report lands in `.output` behind the JSON and
every `json.loads(_run(path))` blows up.

This is not hypothetical. The flag exists precisely so a developer exercises the
check by hand, and the natural way to do that is to export it in the shell for a
session. It is also the exact failure class `conftest.py` already guards, with a
comment describing the same symptom: `os.environ.pop("FORCE_COLOR", None)`
(`tests/conftest.py:33`) was added after Claude Code's `FORCE_COLOR=3` failed 30
tests on a clean tree. The convention in `CLAUDE.md` — "anything touching output
pins `NO_COLOR` … assertions become machine-dependent" — is the same rule.

Fix: one line beside the existing pop, with the comment that repo style asks for.

```python
# The Stop hook echoes its report to stderr when this is set, and CliRunner's
# `.output` is the combined stream — an exported flag lands behind the JSON and
# four `json.loads` assertions here fail on a clean tree. Same reason as
# FORCE_COLOR above: tests must not depend on where they run.
os.environ.pop("WFCTL_SHAPE_ECHO", None)
```

### WARNING — `wfctl/_shape.py:111` · `example` is singular-only

Verified against the compiled regex:

| prompt | opens the gate |
|---|---|
| `an example please` | yes |
| `give me some examples` | **no** |
| `in plain terms` | yes |
| `plainly put` | **no** |
| `like a PM` | yes |
| `npm run build`, `at 5pm` | no (correct) |

"give me some examples" is at least as common as the singular, and it is a

opposite, and the same line already uses the widening form for its neighbour
