## NITs, with the evidence

**`example` vs `examples`** (wfctl/_shape.py:L111). Probed against the shipped
regex:

| prompt | gate |
|---|---|
| `provide a simple example` | matches |
| `give me some examples` | **does not match** |

`\bexample\b` stops at the `s`. Its neighbours in the same expression are
`tradeoffs?`, `detail\w*`, `analys\w+` — the file's own convention is to cover
inflections, and the plural is the commoner way to ask. `examples?` closes it.
This is not a re-litigation of the over-broad principle; it is the principle
applied one character further.

**`simpl\w+`** (wfctl/_shape.py:L111) also matches `simplify` / `simplification` /
`simplest`, so `simplify wfctl/cli.py` — the verb of a slash command this repo
ships — now licenses unbounded length. That is squarely inside the recorded
tradeoff (a missed real violation costs nothing), so it is the author's call; if a
narrower form is preferred without touching the principle, `simple|simply` is
exactly the row's vocabulary and nothing else. Same class, no action needed:
`ship it at 4 pm` matches on `pm` (`3pm standup` does not — `\b` saves it).

**The echo is silent on a clean run** (wfctl/cli.py:L3736). The docstring sells
the flag as the way to "exercise the check by hand", but with the flag on and no
finding, the command prints nothing at all — the same output as an unparseable
payload, a missing `transcript_path`, an `OSError`, or an empty reply, each of
which `return`s early above. The operator learns nothing from silence, which is
the failure mode the flag exists to end. An `else: print("no findings",
file=sys.stderr)` under the same guard would close it; reasonable to decline as
scope.

**Default-off is unasserted** (tests/test_shape.py:L240-257). The new test sets
the variable; nothing asserts the behaviour without it. The flag is *for* hand
use, so `WFCTL_SHAPE_ECHO=1` exported in a shell profile is the expected end
state — and in that shell the suite still passes even if the guard were deleted.
`monkeypatch.delenv("WFCTL_SHAPE_ECHO", raising=False)` plus
`assert result.stderr == ""` on `test_the_hook_says_nothing_when_the_reply_is_clean`
pins it.

**Env table** (README.md:L696-704) lists every other `WFCTL_*`; this one is
absent. Adjacent, and lower value:
`docs/architecture/approval-mode-is-stored-intent.md:L88` says "the six `WFCTL_*`
overrides" — still literally true (a debug flag is not an override resolved
before a state dir), but the count is now one shy of the number of `WFCTL_*`
names in the tree.

**Over-engineering** (wfctl/cli.py:L3736 + tests/test_shape.py:L243-257). The
report is already on stdout inside the JSON, so
`wfctl hook response-shape < payload.json | jq -r '.hookSpecificOutput.additionalContext'`
is the same capability at zero lines. The flag costs 2 lines of code, 15 of test
and 5 of docstring. Against that: it needs no `jq`, and it shows the report while
the JSON still flows to the harness, which piping does not. The brief asked for
it by name, so this is noted rather than pressed.

## What each pass checked, and found clean

**1. Correctness.** Traced `hook_response_shape_cmd` through `_last_exchange`,
`_shape.findings`, `_prose`/`_split_fences`. The gate reads the *prompt* only, so
none of the added words can be triggered by the reply's own text. `\b`-anchoring
holds on the short additions (`pm` does not fire inside `3pm`, `apm`, `rpm`). The
echo sits inside `if found:`, after the stdout write, on a separate stream — it
cannot corrupt the payload the harness parses. The `2>/dev/null` claim in the new
docstring paragraph is true and load-bearing: `STOP_HOOK_COMMAND`
(wfctl/cli.py:L1474) has carried it since the hook was introduced (`cd7ede0`), so
every already-installed `settings.json` entry swallows the echo too — no existing
install can regress into a second double print by exporting the variable.

**2. Security.** No new input trust. The env var is compared `== "1"`, exact; its
value is never interpolated into a command, a path, or the payload. The report
written to stderr is text the process already composed. Nothing secret crosses a
boundary that did not already carry it.

**3. Architecture.** The `_shape.py` owns *what broke* / `cli.py` owns *who is
told* split the brief names is respected exactly: the regex change is wholly in
`_shape.py`, the channel and echo wholly in the hook command. No new module, no
new dependency, no cycle. `os` and `sys` were already imported at
wfctl/cli.py:L5,L7.

**4. Readability.** Comments explain *why this shape* (the row that licenses the
longest replies; the measurement that was true of the harness of the time) rather
than narrating the diff — matches `CLAUDE.md`. The corrected docstring keeps the
seven-run measurement as evidence instead of deleting it, which is what the brief
asked for and the right call: the next reader needs to know it was measured, not
guessed. Test names are sentences and the docstrings say why the tests exist, with
the one exception that the BLOCKER covers (`test_the_explain_it_simply_row…`
states a provenance that is not its prompt's).

**5. Performance.** One extra alternation branch in a pre-compiled regex run once
per `Stop`; one conditional `os.environ.get` and at most one `print`. Unmeasurable.

**6. Over-engineering.** One finding, above. The `systemMessage` removal is a net
deletion of speculative flexibility ("emitted beside it so a version that wires it
up costs no change") that the intervening four months proved was a liability, not
an option — good.
