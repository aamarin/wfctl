**WARNING** `wfctl/_pipeline.py:16-43` — `Verdict` / `_PROMISED` / `blocks()` is
28 lines of structure with **one** production call site, and at that call site it
computes nothing. `design_block:531` is the only caller and always passes
`"ambient"`, for which `blocks()` reduces to `verdict == "unsatisfied"`, i.e. the
`touched is False` the deleted `cli.py` call site already spelled. Three of
`_PROMISED`'s four sources (`repo-declared`, `accepted-record`, `human`) have no
caller anywhere but `tests/test_pipeline_commands.py:1109-1134`, which asserts
against the frozenset's own contents — a test of a lookup table, not of behaviour.
Worse for the record's own argument: the two implementations of the *blocking*
half of the rule (`verification_block:202-251` and `_arch.parse_record`) do not call
`blocks()`. So the rule is stated once and applied once, in the only place where
it changes nothing, while the two sites the record names as already holding the
policy go on holding it independently — which is precisely the drift
`promised-evidence-blocks-on-silence.md` §"Owns truth" says the abstraction
exists to stop.
→ Pick one. **Either** make it load-bearing: `verification_block`'s inconclusive
arms become `if record is None and blocks("inconclusive", "repo-declared"):` /
`if record["inconclusive"] and blocks("inconclusive", "repo-declared"):`, so the
function that actually blocks on silence consults the rule. **Or** delete the
apparatus and let the record carry the rule in prose, with `design_block` reading:

```python
touched = touched_on_this_branch(repo_root, arch, exclude=arch / "design")
# `None` is "git cannot answer" — ambient evidence proceeds on silence; see
# docs/architecture/promised-evidence-blocks-on-silence.md.
return DESIGN_BLOCK_REASON if touched is False else None
```

Shipping it un-consulted is the worst of the three: it reads as enforced and is not.

**WARNING** `wfctl/_pipeline.py:563-573, 597-623` — the `_RECOMPUTE` sentinel is not

## What the change gets right, for the record

- Moving the design verdict out of `cli`'s refusal and into the inferred payload is
  correct and is the change's real content: `status` naming a command that `next`
  then refused was a live contradiction, `pipeline-state-is-one-payload` forbade it,
  and `speckit-orchestrate` carried a prose workaround for it that this diff
  correctly deletes.
- `_implement_verdict` is a genuine consolidation — two sites composing one verdict
  by convention, now one — and the docstring names the exact regression class (#262
  one level up).
- Deriving the "past the boundary" guard from `spec.md` (`:513`) rather than from
  `_AFTER_DESIGN`'s table index is behaviour-preserving and removes an index
  computation whose failure mode was silent.
- "A blocked step is never automatic, whatever the table says" is the right rule and
  the right place for it; my only complaint is that the test for it does not cover
  the path orchestrate actually reads.
