## Findings

**WARNING  wfctl/_pipeline.py:119–131 — a 13-line rationale comment now hangs
over `def _file_exists`.** `DESIGN_BLOCK_COMMAND` was deleted and its comment
kept in place. It reads as a header for the next definition, which is a two-line
`Path.exists()` helper. The argument in it is the most valuable prose in the
commit — "any single string here names one of them and hides the other" — and it
is the one place it is written down; `next_step_content`'s docstring covers
implement-vs-step but not why `next_command` cannot be a remedy at all.
→ Move the block into `next_step_content`'s docstring (or immediately above the
`if blocked and step in _STEPS:` branch it actually explains) and delete the
orphan.

**WARNING  wfctl/cli.py:278 — `status` selects the remedy by a different rule
than `next` and `resume` do.** `status` takes `next((step["remedy"] for step in
steps if step["remedy"]), None)` — the first step in pipeline order carrying one.
`next_cmd:320` and `resume_cmd:384` take the remedy of `step_name`, the current
step. Today only `brainstorm` can carry a remedy so the two agree, but the field
is generic (`_PipelineStep.remedy`, `"How to clear the block"`) and the commit
message frames it as the shape future blocks will use. The second one added makes
`status` and `next-step.md` name different fixes from the same payload — a view
applying its own selection rule, which is precisely what
`pipeline-state-is-one-payload` forbids and what the rest of this branch removed.
→ Filter on `step["is_current"]` in `status_cmd`, matching the other two sites.

**WARNING  tests/test_pipeline_commands.py:1263–1266 — the assertion guarding the
unescaped-payload decision cannot fail.** `assert "\[" not in step["remedy"]` runs
against `_arch_root`'s fixture root `docs/architecture` (helper at :196), which
contains no rich metacharacters, so `escape()` is the identity there. The test
passes unchanged if `_design_remedy` is reverted to call `cli._arch_location`.
That is the whole point of moving `arch_location` into `_pipeline` in `a85e360`,
and nothing pins it.
→ Set `WFCTL_ARCH_DIR` to a bracketed root in that test (as
`test_a_bracketed_root_reaches_the_reader`:470 already does) and assert
`"docs/[wip]/architecture/<slug>.md" in step["remedy"]`.

**WARNING  wfctl/cli.py:280 — the console remedy is the one print site the shared
escaper no longer covers, and no test reaches it.**
`test_a_bracketed_root_reaches_the_reader`:466–469 states the invariant this
branch relied on: *"The escaping lives in `_arch_location`, which every caller
shares — one caller forgetting is the silent failure it exists to prevent, so any
one of them covers it."* After `a85e360` that is no longer true: `_pipeline.
arch_location` is a second, unescaped path to the same string, and `status`'s
remedy is escaped at the print site rather than through the shared helper. A repo
with `arch_root = docs/[wip]/architecture` and a blocked design step is not
covered by any test; `[/wip]`-shaped roots raise `MarkupError` and kill the whole
`status` output. The escaping in the code is correct — the guarantee that a
future caller cannot forget is what was lost.
→ Add a `status` case with a bracketed arch root asserting the literal path
survives, and correct the stale claim in the :466 docstring.

**WARNING  wfctl/_pipeline.py:664–667 — `repo_root` and `spec_dir` are now dead
parameters, and both call sites still pass them.** With `_step_block` deleted the
body reads only `step` and `blocked`, yet `build_report`:761 and `cli.next_cmd`:328

**WARNING  wfctl/cli.py:336–340 — `next-step.md` now ends the remedy block one
