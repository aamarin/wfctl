## Findings

WARNING  tests/test_start_session_asks_conditionally.py:L31-47 — **all three
tests pass on the exact inversion of the branch they exist to protect.** They are
substring checks over one slice of the file, and no assertion ties a cell to its
row. I swapped the two table cells in a scratch copy (row 1 → `Ask: "What are we
working on today?"`, row 2 → `**Do not ask.** Quote the line …`) — that is #244
reintroduced *and* every session with no summary starting work unprompted — and
all five assertions still hold: `Do not ask` ✓, `session-summary.md` ✓, `What are
we working on today?` ✓, `no summary` ✓, `Quote the line` ✓. This is the finding
that decides acceptance criterion (c): `a-rule-is-expressed-as-a-check` asks
whether a violation is visible in an artifact the work produces, and here the
violating artifact passes the check. → Assert per row, not per file:
`row = next(l for l in step.splitlines() if l.startswith("| a summary naming"))`
then `assert "Do not ask" in row`, and the mirror for the `no summary` row.
Four lines, and the inversion goes red.

WARNING  wfctl/agents/skills/start-session/SKILL.md:L177-180 — **the branch does
not distinguish attended from unattended, so an ordinary main-checkout session
now begins work unprompted too.** `wfctl end` writes `session-summary.md` on
every `/end-session`, so the steady state of any long-lived branch — `main`
included — is "a summary naming a first action", i.e. row one. Yesterday's
attended session in the main checkout is asked today only if it never ended
properly. Acceptance criterion (b) reads "the fix must not make `/start-session`
in the main checkout start doing things unprompted"; as written the change does,
for the common case. Note this is a behavior change and not just a rewording:
the old step still *asked*, with the TODO as the default answer, so a human
confirmed. The commit body defends row two ("a session with no summary has
genuinely not been told what to do") but never says that row one now swallows
attended sessions, and #239's argument — handoff-vs-summary is undecidable — does
not cover attended-vs-unattended, which is a different discriminator and the
issue's own recommended shape (#127). → Either state the widening explicitly in
the commit/PR body and pin it with a test ("an attended session with a filled
TODO also proceeds — deliberate, pending #127"), or hold row one to handoffs by
some signal that exists today. Silence is the part I would not merge.

WARNING  wfctl/agents/skills/start-session/SKILL.md:L180 vs wfctl/_session.py:
L81-83 — **the skeleton `wfctl end` itself writes is the highest-frequency
near-miss and the skill never names it.** `_render_session_summary` emits
`## Next Session TODO\n\n- [ ] (fill in)` whenever a session ends without the
prose being filled in (`test_the_handoff_prose_reads_as_unfilled` pins exactly

and names no action. Row two covers it in principle ("one naming no next
action"), but the gate is left as a judgment about whether `(fill in)` is a
sentence saying what to do first — which is the class of judgment this change
exists to remove. → One clause in row two: `no summary, one whose next action is
still \`(fill in)\`, or one naming no next action`. It is also a free test case
the current three do not cover.

WARNING  wfctl/agents/skills/start-session/SKILL.md:L179 — **no evidence the fix

### Passes, and what each checked

1. **Correctness** — traced the branch against every state that can produce
   `session-summary.md`: `wfctl end`'s skeleton (`_session.py:L61-84`), a filled
   end-session summary (`end-session/SKILL.md:L104-106`), a `worktree-handoff`
   copy (`worktree-handoff/SKILL.md:L134-146`), and no file at all. Findings 2, 3
   and the prompt-only NIT come from that walk. Nothing in the diff mis-states
   what step 4 reads; the table is internally consistent with steps 4 and 8.
2. **Security** — nothing new. The diff adds no command, no path handling, no
   input parsing. Worth noting only that the change *authorizes an agent to act
   unprompted on the contents of a file*: `session-summary.md` in the state dir is
   attacker-adjacent only for someone who already has write access to the user's
   XDG state dir, which is the same trust level as the skills tree itself. The
   "first row is not a permission question" paragraph correctly keeps push /
   comment / merge behind an ask, which is the mitigation I would have asked for.
3. **Architecture** — weighed against all 9 accepted records.
   `a-rule-is-expressed-as-a-check` is the one in force here and is what finding 1
   is about; the change's *design* honours it (the quote is observable, step 8
   reports the row) while its *test* does not. `session-state-is-re-derived` is
   respected — step 9 reads the one thing re-derivation cannot reach and derives
   nothing from a stale write. `knowledge-placement` is right: this is a
   constraint on the worker, and it landed in the skill, not in `AGENTS.md`.
   `layer-model` respected — source under `wfctl/agents/`, no generated tree
   touched.
4. **Readability** — the table is the right shape for a two-way branch and reads
   at a glance. Prose matches house style (argument beside the rule, issue
   numbers for the failures that produced it). Test docstrings say why the test
   exists and name the failure, per Testing conventions. Naming is fine.
5. **Performance** — not applicable; no code path changed. The suite grew by
   three file-read tests, ~0s.
6. **Over-engineering** — one candidate: the "Do not try to tell a handoff from a
   previous session's summary" paragraph (L190-194) forecloses an inference the
   table never invites, and its load-bearing half is one sentence. Against that,
   #239 is real history and the next reader will otherwise re-derive it. I would
   leave it. Nothing else is speculative: no flag, no config, no abstraction. The
   diff is +92/−8 and the fix itself is a table.

net: −8 lines possible (and I would not take them)

**Verdict: Request changes** — no blockers, but two warnings bear directly on
stated acceptance criteria: finding 1 (the check passes on the inversion, so
criterion (c) is not yet met) and finding 2 (attended main-checkout sessions now
proceed unprompted, which criterion (b) forbids as written and the commit does
not acknowledge). Findings 3–6 are should-fix and cheap. The change is the right
shape and definitely improves code health; it is one test rewrite and one
paragraph of honesty away from merge.
