## Observations outside the diff

These are not findings against this change, and I list them so they are not lost.

1. When an epic's sub-issue branch runs `wfctl step complete implement`, the copy accepts its sibling sub-issues' incomplete tasks as finished. Writing the record by hand did the same, and research R7 records that nothing changes here, so this is not a regression. It does mean "a copy taken earlier would accept work that was never done", from the wrapper, is by construction true for every sub-issue but the last.
2. Matching by count cannot tell a new incomplete task from an old one with the same description once the old one is ticked. For example, a copy that holds "Update docs" incomplete and a live list where that task is ticked and a new "Update docs" is added reads closed. This follows from matching by description (FR-006), and it needs duplicate descriptions to occur.
