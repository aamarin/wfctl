### Findings

WARNING  wfctl/cli.py:L2164, wfctl/agents/commands/speckit.implement.md:L93-L97 — When `tasks.md` holds no task and no completion record exists yet, `tasks` reads `in_progress` ("tasks.md holds no task"), so `wfctl step complete implement` refuses with `implement is not reached yet: tasks is the current step`. I confirmed this with a probe. The wrapper then tells the agent that writing the file by hand is not a fallback, and that "that step runs first", which means `/speckit.tasks`. The `tasks` reader's own comment (#8) names that as the trap, because `/speckit.tasks` rewrites the file from a template, so a shipped story is left with no route to `/end-session`. As a result, FR-008's with-copy shape (Story 4 #3, tested in `test_any_record_over_a_task_list_with_no_task_reads_finished_and_tasks_skipped`) can't be produced by the one writer that writes copies. The first plan review's PR-006 raised this case, and the fix it got covers refusals in general but not this one. → Add one sentence to the wrapper's refusal paragraph: when the refusal names `tasks` because `tasks.md` holds no task, stop and hand the story to a person rather than running `/speckit.tasks`. I prefer that to relaxing the gate, because a gate that lets an unattended run close a story with no task in it is the shape #308 removed.

NIT  wfctl/agents/commands/speckit.implement.md:L89 — "Run it after the last box is ticked" assumes every box is ticked. The paragraph above says the record exists for the story whose boxes stay unticked because the work was done outside the skill, and for a fully ticked list the record changes no verdict. An agent reading it literally could tick boxes it never checked so that it may run the command. → "Run it once the last task's work is done and the refactor pass above has run, and before step 9c."

NIT  wfctl/_completion.py:L36 — `_SPAN` is a second copy of the inline-span rule that `_evidence._blanked` writes inline (`` r"`[^`\n]+`" ``). `_completion` cannot import `_evidence`, and `_md` exists so that a rule like this has one home. If one copy changes alone, `description` picks a different box than `quoted_out` treats as the task's box, and the ID stays in the description, so a renumber reopens the step. That is the safe direction, but it would be a silent drift. → Move the pattern to `_md` (for example `_md.INLINE_SPAN`) and use it from both modules.

NIT  wfctl/cli.py:L2172 — `read_text()` translates line endings, so a CRLF `tasks.md` is recorded with LF endings. The probe confirms the copy equals the text that was read but not the bytes on disk. No verdict changes, because the live side is read the same way. The spec's Story 2 independent test still says "byte for byte". → Reword that test to "identical to the text wfctl reads", or read with `newline=""` and write with `write_atomic(..., newline="")`. The wording change is the smaller fix.

NIT  tests/test_completion_record.py:L244, L133 — `test_only_the_task_added_since_completion_is_new_work` takes `spec_tree` and `tmp_path` and uses neither. `test_whitespace_collapses_and_the_ends_are_stripped` is the one test in the file with no docstring saying why it exists. → Drop the two parameters, and give the whitespace test a one-line reason, such as an indented subtask matching its unindented copy.
