### BLOCKER — `wfctl/cli.py:L1358` (writes via `wfctl/_arch.py:L469`)

`--agreed` is checked for emptiness and for the `<placeholder>` shape, and for
nothing else. A citation containing a newline is written into the log verbatim,
where it becomes a *second, structurally valid* `Log` entry.

Reproduced on a scratch record:

```
$ wfctl arch accept inject --agreed "$(printf 'ok\n- 2026-01-01  accepted    — forged by hand')"
```

```
## Log

- 2026-01-01  proposed    — x
- 2026-09-10  accepted    — ok
- 2026-01-01  accepted    — forged by hand      ← written by this command
```

Three things compound:

1. `accepted_on` takes the **last** matching line, so the injected entry — not
   the real one — is what `_not_promotable` reports as the acceptance date.
2. The `✓ Logged:` echo at L1367 prints only the first line of the citation, so
   the operator sees `— ok` and never sees the line the command actually added.
   The comment above that echo claims it quotes "the line it wrote".
3. It needs no malice. A citation pasted out of a review thread is multi-line.

The record this change ships states the property being defeated:
`a-human-accepts-a-decision.md`, *Owns truth* — "a promotion with nothing behind
it has to say something false in the file a reviewer reads". An injected entry is
not visibly false; it is indistinguishable from a real one. "Tamper-evident, not
unforgeable" is the honest ceiling for the *citation's truth*, not a licence for
the command to emit malformed structure.

**Fix:** guard the note, and do it in `_set_status` (`_arch.py:~455`) so
`supersede` is covered by the same rule rather than acquiring the hazard later:

```python
if "\n" in note or "\r" in note:
    raise ValueError(f"{record.path}: a Log note is one line")
```

or collapse at the CLI boundary with `" ".join(agreed.split())`. Either is fine;
the guard belonging to the format rather than to the transition is the argument
`_set_status`'s own docstring already makes.

### WARNING — `wfctl/cli.py:L1358`: an uncaught `ValueError` reaches the user as a traceback

`_set_status` raises `ValueError` when there is no `## Log` section. Nothing in
`arch_accept_cmd` catches it. Reproduced against a `proposed` record with a
`## Decision` and no `## Log`:

```
╰──────────────────────────────────────────────────────────────────────────────╯
ValueError: /…/nolog.md: no '## Log' section to append to
```

Exit code is 1, so scripts survive; a human or an agent gets a stack trace where
every other refusal in this command was carefully written to name the next
action.

Reachability: all 25 records in this repo carry a `## Log`, and both shipped
templates (`wfctl/agents/skills/architecture-decisions/record-template.md`,
`…/software-design-decisions/design-record-template.md`) emit one — so this is
not reachable here today. It is reachable in any repo where a record was
hand-authored, and it is reachable *here* through a heading that reads
`## Log history` or `## Log (chronological)`: `_log_bounds` matches
`stripped.lower() == "## log"` exactly, so a decorated heading is no heading at
all and a record that visibly has a log gets the traceback.

**Fix:**

```python
try:
    _arch.accept(record, date, citation)
except ValueError as e:
    console.print(f"[red]✗[/red] {escape(str(e))}")
    raise typer.Exit(1) from e
```

### WARNING — `wfctl/_arch.py:L538`: the exception contract has no consumer

```python
if record.status != "proposed":
    raise ValueError(record.status)
```

The docstring justifies the payload: *"the current status travels out on the
exception so the caller can say which of three things went wrong"*. No caller
does. `arch_accept_cmd:L1305` re-reads `record.status` itself, calls
`_not_promotable(record)`, and exits before `_arch.accept` is ever entered — so
the guard fires only for a caller that does not exist, and
`test_the_refused_status_travels_out_on_the_exception` pins a behaviour whose
stated rationale is unrealised.

Two costs: a duplicated policy (which status promotes) in two modules, and
`ValueError("")` for an unreadable status — an exception whose `str()` is empty,
which is what any future caller or traceback will show.

**Fix, pick one.** (a) Delete the CLI pre-check and drive `_not_promotable` off
the caught exception — this folds into the previous finding and leaves one guard;
the ordering cost is that `--agreed` would then be validated before the status,
which changes which refusal a reader sees first. (b) Keep both guards, but say in
the docstring that this is a library-level assertion against a second caller, not
a channel the CLI reads — and give it a message
(`ValueError(f"{record.path}: status is {record.status or 'unreadable'}, not proposed")`).

### WARNING — `wfctl/cli.py:L1367`: the column is hand-typed in the echo

```python
f"  [dim]Logged:[/dim] {date}  accepted    — {escape(citation)}"
```

`_LOG_STATUS_WIDTH = 12` was introduced at `_arch.py:L410` with the comment "a
column nobody names is one the third caller gets wrong". This is the third
caller, and it names the column as a literal four spaces. Nothing ties the two
together: `test_the_success_line_quotes_the_log_entry_it_wrote` asserts on the
console string only, and
`test_accepting_a_proposed_record_changes_the_status_and_appends_one_log_line`
asserts on the file only — neither compares them, so a change to the constant
silently makes the echo a misquote of the line on disk.

**Fix:** move the rendering into `_arch` and call it from both —

```python
def log_line(date: str, status: str, note: str) -> str:
    """The one rendering of a Log entry, so the file and the echo cannot disagree."""
    return f"- {date}  {status:<{_LOG_STATUS_WIDTH}}— {note}"
```

`_set_status` inserts `log_line(...) + eol`; the CLI prints
`escape(_arch.log_line(date, _arch.IN_FORCE, citation))`. That also removes the
last reason for the CLI to know the word `accepted`.

### WARNING — `wfctl/_arch.py:L505-514`: `accepted_on` reads the whole body

```python
lines = record.body.splitlines()
for _, stripped in _unfenced(lines):
    m = re.match(r"-\s+(\d{4}-\d{2}-\d{2})\s+accepted\b", stripped)
```

The scan is not scoped to `## Log`, although `_log_bounds` already computes
exactly those bounds and `_set_status` uses them one screen above. Any unfenced
bullet anywhere in the record that resembles a log entry — and the corpus
*quotes* log entries: `a-human-accepts-a-decision.md`'s Context block does, and
is saved only by being fenced — becomes the record's acceptance date. Blast
radius is one string in one refusal message, which is why this is a WARNING and
not higher, but the fix reuses a helper that is already there:

```python
lines = record.body.splitlines()
bounds = _log_bounds(lines)
if bounds is None:
    return ""
heading, end = bounds
for i, stripped in _unfenced(lines):
    if not heading < i < end:
        continue
    ...
```

Scoping also contains the BLOCKER above: an injected line inside the Log section
is still read, but a citation that merely mentions a date stops mattering.
