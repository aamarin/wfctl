# Design: session truth — #42 and #70

Epic #74. Levels 1 and 3 only; level 2 landed as records and is not repeated
here:

- `session-state-is-re-derived` — accepted
- `pipeline-state-is-one-payload` — proposed

## Level 1 — behavior

`current.md` goes away, which promotes `wfctl status` from a convenience to the
only answer a session gets to "where is this feature". Every string below was
captured from the real command against a scratch spec root, except where marked.

### The states

```
1. no spec dir
   #74  74-session-truth-ownership
   ────────────────────────────────────
   (no spec dir found)
   brainstorm   ○  ← current
   specify      ○
   → TRUE. Nothing exists, brainstorm is where you start.

2. spec dir exists, empty
   brainstorm   –
   specify      ○  ← current
   → FALSE. `–` means "never ran, does not block". Nothing has been
     done, and the pipeline routes past design to specify. Same real
     situation as state 1, opposite advice; the only difference is
     whether a directory exists.

3. spec.md carries [NEEDS CLARIFICATION
   specify      ▶
   clarify      ▶  ← current
   → TRUE.

4. clarify skipped — plan.md predates the gate
   specify      ●
   clarify      –
   plan         ●
   → TRUE for a human who has read _pipeline.py:200.
     FALSE for an agent: `–` and `●` are both "does not block", and
     nothing recovers the difference from the drawing.

5. implementing, unverified
   implement  ▶  1/1 done  unverified — run `wfctl verify`  ← current
   → TRUE. Two observed facts, neither concluded. This is the state the
     others should look like.

6. every step done                                    (read from code, not run)
   brainstorm ● … implement ●
   (no ← current, no line, nothing)
   → FALSE. The terminal state renders as an absence. The string that
     says it exists only in `resume`.
```

### `wfctl end`, before and after

```
before                                after
──────────────────────────────        ──────────────────────────────
✓ Session ended. Summary              ✓ Session closed — implement 3/8,
  written to <path>                     boundary answered, tree dirty.
                                        Summary: <path>
session-summary.md:                   session-summary.md:
  **Status**: complete                  **Step**: implement 3/8
                                        (no status line)
```

`complete` is not observable and had no reader. What replaces it is what `end`
can see at the moment it runs.

### Decisions

1. `status` prints the next command. State 6 gets
   `Story complete — open PR or run /end-session` instead of an absent cursor.
2. An empty spec dir must not read as "brainstorm skipped". States 1 and 2 are
   the same situation and must render the same.
3. `end` reports position, boundary and dirty tree; it claims no completion.
4. Session `status` is deleted. It has no reader.

No assumptions left standing.

Observed alongside it: the header reads `#unknown  main` when the branch name
encodes no issue. Out of scope for #42, but it is the same class of string —
a field rendered from something that was not there.

### Consequences generated by the level-1 decisions

- Decision 1 → `status` needs `next_step_content`, which it does not import
  today, and a story-complete branch for when no step is current.
- Decision 2 → `_infer_steps` needs "no artifacts at all" separated from
  "this artifact is absent". It cannot express that today, because
  `_file_exists` collapses missing and empty into one answer.
- Decision 3 → `end` needs the boundary check and the dirty-tree read that
  `status` and `verify` already do, which means the payload from
  `pipeline-state-is-one-payload` is what it reports from.
- Decision 4 → `status` leaves `current.json`, and what remains in that file is
  the session-exists marker plus the fields `_resolve_context` derives anyway.
  Whether the file survives at all is a level-3 question this design does not
  close.

## Out of scope

- Which flag or format the machine view takes — belongs to
  `pipeline-state-is-one-payload` being accepted first.
- `next-step.md` and the design gate. Untouched.
- Deleting `load_agentconfig`. Falls out, but is not this feature.
