## Findings

**BLOCKER** `wfctl/agents/commands/speckit.clarify.md:110` and
`speckit.analyze.md:110` — the commit is unscoped, so it writes the whole index.

Both wrappers instruct:

```bash
git add <root>/scans/<issue>-clarify.md
git commit -m "docs(scans): clarification scan for #<issue>"
```

`git commit -m` with no pathspec commits everything already staged. `clarify`
runs immediately after `specify` and `analyze` runs after `tasks` — both are
mid-pipeline moments where an author's staged code is entirely normal — so
whatever is in the index rides along in a commit whose subject says it contains a
scan file. The change is silent and only visible on a later `git show`.

This repo has already met this exact failure and written down the fix.
`wfctl/agents/skills/software-design-decisions/SKILL.md:76-85` carries the same
three-line block *with* the pathspec, and the paragraph under it:

> The pathspec on `commit` is not the same instruction as the one on `add`. A
> bare `git commit` writes the whole index, so anything already staged when the
> design session began lands in a docs commit alongside the record; naming the
> path makes git commit that path and leave the rest staged where it was.

The new block is that block with the pathspec and its explanation dropped.

Fix, in both wrappers:

```bash
git commit -m "docs(scans): clarification scan for #<issue>" -- <root>/scans/<issue>-clarify.md
```

and add the assertion to `tests/test_scan_files.py` — a parametrized check that
`git commit` in the section is followed by `--` on the same line, in the same
shape as `test_each_review_wrapper_makes_the_step_commit_before_checking`.

**WARNING** `docs/architecture/scans/` — two existing readers walk the arch root
recursively, and the level-2 record's `Consequences` misses both.

The record checks the three readers that are unaffected (`arch check` takes any
path, `load_records` globs one level, `design_block` returns `None` once
`spec.md` exists — I verified all three and they are correct). It does not check
the two callers that ask git about the whole arch root with no exclusion:

- `wfctl/cli.py:639` — `_observe` sets `boundary=_BOUNDARY[touched_on_this_branch(repo_root, arch_root(repo_root))]`,
  with **no** `exclude`. `touched_on_this_branch` is recursive by git pathspec and
  says so in its own docstring. So a branch whose only arch-root file is a scan
  file now reports `boundary: answered` in `wfctl end`'s handoff observations.
  `_BOUNDARY`'s own comment (`cli.py:611-613`) says *"calling a missing answer
  'answered' is the kind of claim #70 is about."* Because `clarify` and `analyze`
  run on essentially every branch, this observation becomes constant-true and
  stops carrying information.
- `wfctl/cli.py:443` — `records_on_this_branch(repo_root, arch_root(repo_root))`
  lists slugs under the auto-approve notice as `record: <slug>`, i.e. "the
  records this unattended run decided". Scan files land in that listing as
  records.

Measured on this branch:

```
touched (no exclude, what `wfctl end` reads): True
touched (design excluded, what design_block reads): True
records_on_this_branch: ['307-analyze', '307-clarify',
                         '307-the-coverage-map-is-the-evidence',
                         'the-scan-is-attested-where-the-reviewer-reads']
```

`307-analyze` and `307-clarify` are scan files being reported as architecture
records.

Note this is not the design-gate hazard the record already cleared — that one
really is closed by step order. It is a separate pair of readers.

Fix, cheapest first: pass `exclude=arch / "scans"` at `cli.py:639`, and filter
`scans/` out of `records_on_this_branch` (or give it the same `exclude`
parameter its sibling already has). Then extend the record's `Consequences` to
name these two callers, since the section is what a future reader will trust as
the complete list of what the destination touches.

**WARNING** `wfctl/agents/commands/speckit.clarify.md:50-63`,
`speckit.analyze.md:47-57` — a clarification the spec recorded never reached the
instruction, and the committed exemplar shows the wrong shape.

a sentence ("a second run on a date already present extends that section rather
than opening a new one"), and make the exemplar match.

Worth noting the shape of this defect: an answer written where the implementer
does not read it, which is the failure #307 exists to close.
