1. Correctness: the gate `not pr_base or head_is_this_repository()` leaves non-PR runs unchanged and adds the head check in PR runs. I traced the failure modes of the event read. A missing or empty `GITHUB_EVENT_PATH` gives `Path("")`, so `read_text` raises OSError. Bad JSON and bad UTF-8 raise ValueError. A non-dict event or a null `head.repo` (deleted fork) raises TypeError or KeyError. All of these return False, so the PR is treated as a fork. An empty `GITHUB_REPOSITORY` also returns False. The same-repo case still gets the exemption, which the release script depends on.
2. Security: the exemption no longer depends on `GITHUB_HEAD_REF` alone. The event file is written by the runner and a fork cannot change it. The check fails closed. Not a regression: a fork PR can edit the script itself, because the job runs the merge commit's copy, but that was already true and is outside this diff. Residual: a same-repo writer can still name a branch `release/v*`. That is the intended trust boundary.
3. Architecture: stdlib only (`json` added), the helper sits beside `pull_request_base`, and it reads env vars the same way. The CI job triggers only on `pull_request`, so the event shape assumed here is the right one.
4. Readability: the docstring explains why, and it is in the repo's comment style. The module docstring is updated.
5. Performance: one small file read on a path that only runs for release-shaped branches.
6. Over-engineering: none. Lean already.
