## Passes with nothing to report

**Correctness.** The flip's live path was traced end to end.
`build_report` → `_infer_steps` → `_predicates.decompose` → `blocks(verdict,
"ambient")` → `next_step_content(current, blocked)`. The three states that matter
were measured:

| Fixture | pre-flip | post-flip |
|---|---|---|
| analyze done, no `delivery.md`, tasks open | `decompose`, `/speckit.decompose`, `auto=False` | same route, `auto=True` |
| plan on disk, three `_(TBD)_` rows, tasks open | `auto=False` | `auto=False` |
| plan fully keyed, tasks open | `implement`, `/speckit.implement`, `auto=True` | identical |

So the flip changes exactly one payload, and
`test_a_feature_that_has_analyzed_enters_decompose_without_a_prompt` is the test
that would fail without it. The livelock a reviewer should look for — loop enters
decompose, decompose writes placeholder rows, loop enters it again — does not
occur: the second `wfctl status` sees unkeyed rows with work open,
`_predicates.decompose` returns `in_progress` with a reason, and
`next_step_content` returns `auto=False` for any blocked step regardless of the
table. `test_an_unkeyed_map_stops_the_loop_the_flag_now_lets_run` pins that on
`auto` rather than on `state`, which is the field `speckit-orchestrate` step 5
branches on — correct choice, and the docstring says why.

Edge cases checked and unchanged by the flip: no tracker configured
(`tracker: null` → `unkeyed is None` → `inconclusive` → `ambient` proceeds), a
plan with no Issue Grouping Map or a map with no rows (same path), a key pattern
opening with an inline flag, and tasks already closed (`decompose` reports `done`
with the annotation surviving, so `/end-session` stays reachable). One state is
worth naming as *not* a regression: a `delivery.md` written without a map reads
`done` and lets the loop into `implement` with no issues. That hole predates this
commit and the flip does not widen it — pre-flip, `review_required` only made a
human *launch* decompose; nothing paused between decompose finishing and
`implement` running either way.

**Security.** This is a change to a gate on an outward-facing action, so it got
the most attention. The claim "the flag decides whether the step is entered,
never whether the tracker is written" holds: `speckit-orchestrate/SKILL.md:L127`
emits `EXECUTE_COMMAND` on `auto`, and nothing downstream reads the continuation
again. The grant is real and enforced in code, not only in prose —
`_refuse_notifying` exits 1 and records the refusal — and it is resolved
per-branch from the recorded `wfctl start` answer (`_pipeline.py:L417`), so a
shared state dir cannot let one feature's grant answer for another. The
governing record is `docs/architecture/a-human-grants-outward-facing-authority.md`
(status: proposed), which names #240 by number as the issue parked on the gap
#280 closed, and argues in advance that a setup-time grant costs an unattended
run nothing. This change is what that record was written to enable. The one soft
spot is the third WARNING above.

No secrets, no injection surface, no untrusted input newly parsed. `_unkeyed_issues`
is unchanged.

**Architecture.** `pipeline-state-is-one-payload` — no view gains a computation;
the new tests assert on `build_report`'s payload rather than console output,
which is the right side of that line and also why `NO_COLOR` is correctly absent
here. `a-rule-is-expressed-as-a-check` — honoured for the notify rule, with the
step-7 caveat. `knowledge-placement` — the rationale for the flip sits beside the
predicates it describes, in the file that already owns the rung ladder; nothing
argues it belongs in `docs/architecture/` given the record above already draws
the boundary. `layer-model` — the bundle edits are in `wfctl/agents/` (source),
not in the generated `.agents/`, with `.agents/` refreshed by an

**Readability.** Test names are sentences; the `_predicates.py` docstring edit
informs the next reader rather than narrating the change to a reviewer, and
