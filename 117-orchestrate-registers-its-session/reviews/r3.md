## Findings

WARNING  speckit-orchestrate/SKILL.md:L10–L20 — the gate checks "has a session
ever existed on this branch", but the prose reads as "did this run skip
`/start-session`". `session_started` (`wfctl/_session.py:35`) scans an
append-only `events.jsonl` for any `start` event, ever; nothing clears it, and a
second `wfctl start` does not even append (`cli.py:141` returns early with
"Already initialized"). So on any branch where one session has already run
`/start-session`, a later conversation that skips it passes the gate and does
exactly the work #117 describes. That is orchestrate's normal habitat — it runs
*after* a speckit step, i.e. on branches with history. The #117 reproduction
(first session on the branch, no `start` ever) is genuinely covered; the general
sentence at L15–L16 ("A run that reaches a conclusion here leaves it in
scrollback and nowhere else") is not, and the next reader will lean on it.
→ Fix: state what is checked. There is no per-session identity in the state dir
to check against, so documenting the limit is the honest repair rather than a
stronger check — e.g. append to the first paragraph: "This fires on a branch with
no session ever recorded. The `start` event is append-only and never cleared, so
a second session on a branch already started passes here; #117's case is the
first kind." The displayed message itself (L13, "No wfctl session for this
branch") is already accurate to what is read — only the rationale overstates it.

WARNING  speckit-orchestrate/SKILL.md:L24–L26 — mis-citation. "a read that opens
a session writes state as a side effect, which is what `session-state-is-re-derived`
exists to forbid". That record forbids *caching* derivable session state —
"Every piece of session state that can be derived from artifacts on disk is
derived at read time… Nothing is carried forward from an earlier write" — and its
two dashed edges are the agent asserting pipeline position and asserting
completion. It does not forbid a command with a write side effect; `wfctl start`
appending to the event log is a shape that record keeps, not one it rejects. The
rule this paragraph is actually reaching for is `wfctl-runs-the-verification`:
"the agent never certifies its own completion… the verdict has to be a side
effect of running the command, not a claim about having run it" — clearing your
own gate is that shape one level over.
→ Fix: cite `wfctl-runs-the-verification`, or drop the citation clause entirely
and keep the reason that already stands alone (it hides from the user that
`/start-session` was skipped, and skips the three things only `/start-session`
does). HEAD~1 on this branch is "cite sources that ship" — same standard.

`session_started`. If it is `false`" has no answer for the field being absent or
