WARNING  wfctl/agents/skills/speckit-orchestrate/SKILL.md:L10-L20 — the gate is
per-*branch-lifetime*, not per-agent-session, and the prose around it reads as
though it were the latter. `session_started` scans an append-only log
(`_io.py:append_event` opens mode `"a"`; `end_cmd` never truncates; only
`start --force` re-appends), so **one** `wfctl start` on a branch — a week ago,
by a different session — makes the gate pass forever. Re-run #117's exact
scenario as the *second* session on that branch and it is unprotected: findings
still exist only in scrollback, and "`/end-session` has no run to summarize"
still holds. The gate closes the first-session case only. Nothing better is
available — wfctl has no per-conversation identity, and inventing one here would
be a much larger change — so the fix is honesty, not machinery: → say what it
catches ("a branch wfctl has never seen"), and file the residue (a later session
entering mid-branch without `/start-session`) as a follow-up on #117 rather than
letting the paragraph imply it is covered.

WARNING  wfctl/agents/skills/speckit-orchestrate/SKILL.md:L10-L13 — the gate has
no failure branch, so it fails *open*. The step says what to do when
`session_started` is `false` and nothing about the command not answering.
`wfctl status` exits 1 with a red message from `_resolve_context`
(`cli.py:115-119`) outside a git repo, and `build_report` can raise on
artifacts it cannot read. A literal reader that gets no `session_started` falls
through to step 1 and does exactly the work the gate exists to prevent — the
#117 failure, reached through the gate. The file already has the pattern one
step down ("**If it exits non-zero, display its output and stop.**"). → Add one
clause: "If the command itself fails, display its output and stop as well — an
unreadable gate is a closed gate."

WARNING  wfctl/agents/skills/speckit-orchestrate/SKILL.md:L25-L26 — the record
cited does not say this. "a read that opens a session writes state as a side
effect, which is what `session-state-is-re-derived` exists to forbid" — that
record forbids *remembering* derived state ("Every piece of session state that
can be derived from artifacts on disk is derived at read time… nothing is carried
forward from an earlier write"), and its two dashed edges are the agent

false weakens the instruction it is attached to — and 3453f22 on this branch is
that same correction. → Cite `pipeline-state-is-one-payload`, or drop the
citation and keep the second half of the sentence, which stands on its own: it
hides from the user that `/start-session` was skipped, along with the mirror
refresh, the contract and the handoff.
