## What each pass checked, and what it found

**1. Correctness.** Traced the gate to its source rather than trusting the
prose. `session_started` is a real field of the `--json` payload
(`cli.py:174`), fed from `PipelineReport.session_started` (`_pipeline.py:441`),
computed by `_session.session_started` from a `start` event in `events.jsonl` —
not from a file's existence, so a truncated final line cannot make a live
session read as unstarted. Reading it via `--json` is *required*, not
preference: `pipeline-state-is-one-payload` L48 says in as many words that
`session_started` "is not rendered at all" by the console view. The four
factual claims in the new prose all check out — `wfctl start` is what appends
the `start` event; `end_cmd` (`cli.py:372`) refuses without it, so "`/end-session`
has no run to summarize" is literal; `start-session/SKILL.md` steps 2-4 do the
mirror refresh, `wfctl arch context` and the handoff read that a bare `wfctl
start` does not; and both `/start-session` and `wfctl start` clear the check.

*Can it fire when it should not?* No regression: before this change, a
sessionless branch already stopped at the old step 2 (`resume` exits 1 via
`cli.py:297`). The gate moves that stop earlier and renames the remedy from
`wfctl start` to `/start-session`; it cannot stop a flow that previously
completed. *Can it fail to fire?* Two ways, both minor and both filed as NITs
above — a non-zero `status` call, and the per-branch (not per-run) meaning of
`session_started`. A third, version skew (skills installed `--from` a newer
checkout than the `wfctl` on `PATH`, an explicitly supported shape per
`.wf-skills-manifest.json`), fails *open*: a missing key is not `false`, so an
old CLI degrades to today's behavior rather than blocking every run. That is
the right direction, so I am not filing it.

*Satisfiable by the allowed tools?* Yes. `commands/speckit.orchestrate.md:4`
carries `Bash(wfctl status*)`, which `wfctl status --json` matches — the gate
adds no new tool surface, and the prefix was already needed by steps 2 and 4.

*Numbering and cross-references.* Internally consistent: 0-5 with no gaps, and
the one internal pointer ("Step 4 is a read", L84) was correctly re-aimed at the
`--json` step. Externally it is not — W1.

**2. Security.** Nothing. No new command, no new argument built from untrusted
input, no secret, no widened `allowed-tools`. The gate strictly *reduces* what
runs before a human is in the loop: the `gh pr list` in step 1 and the
state-writing `wfctl resume` in step 3 now both sit behind it.

**3. Architecture.** Fits. The gate reads truth wfctl owns through the machine
view that record designates, adds no second inference path, and refuses rather
than writing — consistent with the handoff's recommendation and with the two
identical gates the CLI already has at `cli.py:297` and `cli.py:372`. The
message deliberately diverges from `_NO_SESSION` ("Run `wfctl start` first") and
the file explains why in the next paragraph, so the duplication is argued, not
accidental. The only architectural blemish is the unsound record citation (W2).
Placing the check in the skill rather than in `status` is right: `status` is a
read every tool calls, and a gate there would break `/start-session` step 4.

**4. Readability & simplification.** Matches house style — rationale prose that
says why this shape, dense, addressed to the next reader of the file. Chesterton's
Fence respected: the old step-2 warning about `resume` exiting non-zero is kept
rather than deleted as now-redundant, which is correct, because the boundary
refusal is the other way that exit happens. The blockquote makes the exact user-
facing string unambiguous, and "Stop means stop: no checks, no analysis, no
recommendation offered first" forecloses the partial-compliance reading an agent
would otherwise take. Nothing here needs renaming or restructuring.

**5. Performance.** One extra `wfctl status --json` per orchestrate run. It is a
read of spec files with no subprocess beyond git (`_pipeline.build_report`), and
it runs before the `gh pr list` network call in step 1 — so on the gated path it
*saves* work. Immaterial; the duplicate-read observation is filed as a NIT for
staleness reasoning, not cost.

**6. Over-engineering.** The step is 20 lines for a 3-line rule, which is this
repo's norm and not bloat — the rationale is what stops a later reader deleting
the gate as redundant with `resume`'s. Nothing to `delete:`, `stdlib:`,
`native:` or `yagni:` here. One `shrink:` — the citation clause in W2, which is
unsound as well as long.
