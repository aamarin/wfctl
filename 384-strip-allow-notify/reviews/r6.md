## Findings

WARNING  wfctl/_tracker.py:297 — `record_notify_action(agent_dir, f"issue-{verb}")`
writes a `notify-action` event with **no `branch` field**, and `standing_blocks`
(`_session.py:342`) treats a branchless event as matching *every* branch
(`data.get("branch") not in (None, branch)`). Renaming tracker writes to
`issue-<verb>` makes them collide exactly with the names the skills file holds
under, so under a shared `WFCTL_STATE_DIR` a successful `wfctl issue create` in
one worktree now lifts a *different* branch's `report-block issue-create` hold —
the pipeline reports a refused step released with nobody having taken the action
on that branch, which is the one failure `report-block` exists to prevent. The
hole pre-dates this change but was reachable only for `push`: before it,
`wfctl issue create` recorded bare `create`, which never matched a hold filed as
`issue-create`, so the tracker verbs — the names the skills actually use — were
immune. This change makes them the likeliest collision. Not called a blocker
because it needs a non-default `WFCTL_STATE_DIR` and two branches contending on
one action name; it is a judgment call and I would not argue with an author who
raised it.
→ Fix: `record_notify_action(agent_dir, action, branch)` writing `branch=branch`,
as `record_blocked` already does. `report_action_cmd` (`cli.py:389`) already has
`branch` in hand; `dispatch` can take it from `resolve_branch(repo_root)` — the
same two local git calls the deleted `action_grant` made on this path. Keep the
`None → matches every branch` rule for lines written before the field existed,
the rule `record_blocked`'s reader already applies.

NIT  wfctl/cli.py:400 — `held.step` is interpolated unescaped while `action` on
the neighbouring line (`:403`) is `escape()`d. `step` comes from `_STEP_NAMES` in
every path wfctl writes, so this is unreachable in practice, and rich silently
swallows an unknown `[tag]` rather than raising — but the asymmetry on two
adjacent lines is what a later copy will reproduce somewhere it matters.
→ `escape(held.step)`.

NIT  wfctl/_session.py:284,300 — both docstrings were rewritten in this diff and
kept bare `FR-005, FR-006` and `FR-012, FR-020, FR-021` tags carried over from
#364's spec. #384's spec has its own FR-005 (delete grant-only code) and FR-006
(`report-action`), and no FR-020 or FR-021 at all, so a reader resolving them
against this feature's spec lands on different requirements. Bare FR tags are the
repo's existing convention, which is why this is a nit rather than a warning —
but these two were edited here and the collision is new.
→ Qualify them (`#364 FR-020`) or drop them; the surrounding prose already
carries the argument.

NIT  wfctl/_session.py:251 — `record_notify_action` keeps a name whose meaning
