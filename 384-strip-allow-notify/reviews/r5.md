## Findings

**WARNING  wfctl/_session.py:264 — a recorded action lifts another branch's hold.**
`record_notify_action` writes `notify-action` with no `branch` key, and
`standing_blocks` (`_session.py:343`) reads an event with no `branch` as matching
*every* branch. Now that `_tracker.dispatch` (`_tracker.py:297`) records
`issue-<verb>` — exactly the names the skills file blocks under — a successful
`wfctl issue create` on one branch lifts a hold filed on another whenever
`WFCTL_STATE_DIR` points several worktrees at one log. The path was unreachable
before this change: the release event was `block-cleared`, which carries a branch,
and `dispatch`'s `notify-action` carried a bare `create` that no skill-filed block
ever matched (spec.md's own assumption, "No log in use holds a block that only a
bare action name like `create` would lift"). Making the two names agree is the
point of the change and is what opens this. The repo treats the shared state dir
as supported and defends it everywhere else — `record_blocked` stores `branch` for
this reason, `_stall._passes_this_sitting` filters on it, and
`tests/test_report_events.py::test_a_block_on_one_branch_does_not_hold_a_step_on_another`
pins the *block* side. Nothing pins the release side.
→ `append_event(agent_dir, "notify-action", action=action, branch=branch)`, with
`branch` passed by both writers — `cli.report_action_cmd` already holds it,
`_tracker.dispatch` gets it from `resolve_branch(repo_root)` on a path that is
already about to spawn a subprocess. Keep `standing_blocks`' branch-less reading
for lines written before the field. Add the mirror of the block-side test.

**WARNING  wfctl/cli.py:191 — the comment names a test that does not exist.**
The 72-character budget on `_IRREVERSIBLE_NOTICE` and `_HOST_AUTHORITY_NOTICE` is
attributed to `test_every_notice_line_fits_on_one_terminal_line`. `git grep` finds
that name in exactly one place in the repository: this comment. The real name on
`origin/main` was `test_notify_status.py::test_every_line_fits_on_one_terminal_line`,
deleted with its file; the budget is now pinned by
`tests/test_report_verbs.py::test_status_says_who_decides_and_what_is_never_taken`.
A comment that sends the next reader to a nonexistent test is worse than no
comment, because the reader concludes the rule is unpinned and re-derives it.
→ Name the real test.

**WARNING  tests/ — the check the design record promised was not written.**
`docs/architecture/design/384-an-action-is-named-by-the-verb-that-takes-it.md`
§ Verification lists three checks. Two shipped (`test_a_successful_retry_lifts_the_hold_its_refusal_filed`,
`test_board_moves_and_reads_record_no_action`). The third — "`grep -rn "report-block issue-"
wfctl/agents` names only actions in the constant" — did not. The skills' names and
`_tracker._RECORDED_VERBS` (`_tracker.py:72`) agree today by hand only, across six
files, and `spec.md`'s own edge case (`report-block issue-crate`) is precisely the
failure it would catch: a hold nothing can lift, silently. `plan.md`'s Constitution
Check cites `a-rule-is-expressed-as-a-check` for this exact class and applies it to
the removed verbs but not to the action names, which are the newer and more fragile
coupling of the two.
→ In `tests/test_skill_cross_references.py`: every `issue-<x>` appearing in
`wfctl/agents/**/*.md` after `report-block` or `report-action` must be `issue-{v}`
for some `v` in `_tracker._RECORDED_VERBS`.

**WARNING  wfctl/agents/commands/speckit.decompose.md:8 — the wrapper grants a verb
its skill never tells the agent to run.** `Bash(wfctl report-action*)` replaced
`Bash(wfctl notify*)`, which was there for the `--declined` arm this change deletes.
`speckit-delivery-plan/SKILL.md` mentions `report-action` once, at line 124, and it
is addressed to *a person who created the issue outside wfctl* — the agent is never
instructed to run it. The effect is that an unattended `decompose` may both file a
hold and lift it. The level-2 record accepts that ceiling in general ("tamper-evident,
not unforgeable"), and `test_report_block_holds_step.py::test_the_next_action_for_a_held_step_is_the_steps_own_command`
exists specifically so an unattended agent is never *told* to clear its own hold —
handing it the permission anyway works against that without buying anything.
`test_decompose_allows_the_commands_its_unattended_run_needs` requires only
`report-block`.
→ Drop `Bash(wfctl report-action*)` from that `allowed-tools` line.

**NIT  wfctl/agents/skills/end-session/SKILL.md:151 — the step contradicts itself
