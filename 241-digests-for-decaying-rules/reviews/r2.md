### Findings

WARNING `wfctl/agents/skills/worktree-handoff/digest.md:2` — narrows the rule it
projects. The `SKILL.md` red flag it sources from is "Doing the work in the
checkout you are standing in" — deliberately general, because the failure mode is
*any* checkout already open, not specifically `main`. The digest compresses this to
"A branch in the main checkout is the failure," which reads as scoped to `main`. Per
`conversation-response-shape`'s own contract ("digest.md ... projects this file and
never sources it"), the digest is the only copy of this rule an agent sees on later
turns — narrowing it here means an agent standing in a *different* feature branch's
worktree, mid-session, forty turns past the SKILL.md read, has a plausible reading
under which the digest's version of the rule doesn't apply to it. → Reword to keep
the general claim, e.g. "New work gets its own worktree — never the checkout you're
already standing in."

WARNING `wfctl/agents/skills/opening-a-change/digest.md:4-5` — drops the sharper
half of the rule it projects. `SKILL.md`'s point is that an empty Review Panel
section is *indistinguishable* between "skipped" and "ran, found nothing" — that
ambiguity is why the red flag ("The reviewers had nothing, so there is nothing to
write") exists, and why a clean pass still has to be written down as a result. The
digest's "A body without one is what a skipped panel looks like" states only the
skipped case, losing the reason a clean run also needs a line. → e.g. "A body
without one reads as skipped — write a clean pass down too."

WARNING — issue #241's acceptance criteria list the behavioral A/B proof as the
