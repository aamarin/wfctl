## Findings

### WARNING  wfctl/agents/skills/writing-a-scan-file/SKILL.md:107 — the shared skill still states the singular rule this change replaced

> **Findings** — what was found, and for each, **the alternative** the answer was
> decided against.

Both files ship in the same bundle, and the wrapper sends the agent to the shared
skill *first* ("Follow `.agents/skills/writing-a-scan-file/SKILL.md` … It owns the
destination, the session rule, the commit and the check"). The shared skill's own
delegation clause names what it does *not* own — "the categories, their meanings,
and what each verdict means for that step" — and the findings-line shape is not on
that list, so the skill still claims it. An agent working the "What every section
carries" checklist writes one line; an agent working the wrapper's new section
writes N. That is the exact drift `test_each_review_wrapper_points_at_the_shared_scan_skill`'s
docstring says already happened once here.

→ Fix: amend that bullet to defer the count — "…and, for each, what the answer was
decided against; the wrapper says how many" — or make it plural. This file is
wfctl-owned, not spec-kit-derived, so the edit is free and no upstream pull reverts
it. (`speckit.analyze.md:88` keeps the singular line, correctly: analyze's findings
have no option set.)

### WARNING  tests/test_scan_files.py:273-321 — the four new tests guard the rationale, not the shape an agent copies

All four assertions match text inside the new `## The options the answer was chosen
over` prose. Nothing asserts `wfctl/agents/commands/speckit.clarify.md:85-86` — the
two `Decided against **<option>**: <why it lost>.` template lines — and nothing
asserts the literal `No options offered — short answer.` line the prose instructs
the agent to emit. Verified: `grep -rn "Decided against" tests/` returns only a
docstring and the prose assertion.

Consequence: reverting the `### Findings` template to the single
`Decided against <the alternative>: <why>.` line, while leaving all the new prose
in place, ships green — and the template is the part an agent copies. The test
module's own preamble says its purpose is that "a wrapper that lost a rule would
ship green"; here that hole is open on the half that renders.

→ Fix: add `assert "Decided against **<option>**: <why it lost>." in section` twice
(or a count), and `assert "No options offered — short answer." in section`.

### WARNING  wfctl/agents/commands/speckit.clarify.md:75-90 — the short-answer branch is absent from the template it has to appear in

### NIT  wfctl/agents/commands/speckit.clarify.md:103-108 — the mixed case (multiple-choice answered with a free-form short answer) is left to inference

`speckit-clarify/SKILL.md:156` puts a `Short` row inside the multiple-choice
table — *"Provide a different short answer (<=5 words)"* — and `:157` tells the
answerer they may use it. So a question can offer 2–5 options and take none of
them. The main rule handles this correctly ("per option the question offered **and
the answer did not take**" → all of them get lines). The exemption paragraph, read
at speed, does not: it is keyed on the *question* type ("A short-answer question
offered no options"), but its trigger word is the answer's shape, and an agent that
took the `Short` escape hatch has every reason to write `No options offered — short
answer.` — which would be false, and would destroy exactly the evidence the change
exists to keep.

Secondarily: `Short` is itself a row in the rendered options table, so a literal
reading of "per option the question offered" produces a `Decided against **Short**`
line on every multiple-choice finding, which is noise.

→ Fix: one clause — "…a question that *offered* options and was answered in free
text still names all of them; the `Short` row is an escape hatch, not an option."

### NIT  wfctl/agents/commands/speckit.clarify.md:97-99 — "they exist nowhere but the run's working memory" overstates the attended path
