### Findings

WARNING  wfctl/agents/skills/writing-a-scan-file/SKILL.md:107 — the shared skill still states the
findings contract in the singular: *"**Findings** — what was found, and for each, **the
alternative** the answer was decided against."* The wrapper now says one line per rejected option.
The shared skill declares what it owns ("the destination, the session rule, the commit and the
check") and what it does not ("what *this* step scanned: the categories, their meanings, and what
each verdict means") — the findings *shape* is on the owned side, in its own "What every section
carries" list. So an agent reading both is handed two cardinalities for the same line by two
documents, and the one that claims ownership is the one that says "the alternative". The wrapper
being nearer and more specific is a bet, not a rule. → Make the shared line cardinality-neutral and
defer explicitly, e.g. "for each, the alternatives the answer was decided against — how many, and
when none, is the wrapper's to say." That leaves `speckit.analyze.md:88`'s singular line correct
(analyze's findings come from no option set, which the commit message argues correctly) without
contradicting clarify's.

WARNING  wfctl/agents/commands/speckit.clarify.md:112 — the exemption is scoped to *questions*, but
the derived skill lets a multiple-choice question be answered free-form, and the two rules do not
partition that case. `speckit-clarify/SKILL.md` step 4 tells the user "you can reply with the option
letter …, accept the recommendation …, **or provide your own short answer**", and validation accepts
"the answer maps to one option **or** fits the <=5 word constraint". When an A/B/C question is
answered with a short answer, "A short-answer question offered no options and writes none" reads as
covering it — and the agent writes `No options offered — short answer.` for a question that offered
three, discarding exactly the evidence #286 was filed over. Under the first rule the same case
should produce *three* `Decided against` lines, since the answer took none of them; the two
readings are maximally far apart. → Scope the exemption to the question's rendering rather than the
answer's form: "A question that rendered no option table writes none." Then a free-form answer to an
option table keeps all its lines.

WARNING  wfctl/agents/commands/speckit.clarify.md:95 — "per option the question offered" is
ambiguous against what step 4 actually renders. The option table carries a trailing `| Short |
Provide a different short answer (<=5 words) |` row alongside A–E. It is a row in the table the
question offered, so one reading requires `Decided against **Short**: <why it lost>` on every
multiple-choice finding — and there is no true reason such a row "lost", so the anti-straw rule at
:106 then forces the agent to either fabricate one or ignore the instruction. The line's own gloss
("renders each multiple-choice question as 2–5 options") suggests the lettered rows are meant, but
the normative sentence does not say so. → Name it: "one line per lettered option the table offered";
the `Short` escape row is not an option and writes no line.

WARNING  wfctl/agents/commands/speckit.clarify.md:93 — the three sub-rules close fabrication and
leave suppression open. The commit message says each sub-rule answers "a way the instruction could
be satisfied without producing the evidence", and they cover inventing options (:106), inventing
them where none exist (:112), and mode-conditionality (:118). The one they miss is the cheapest:
the same agent chooses how many options the question offers *and* then owes one line per option it
rejected. `speckit-clarify/SKILL.md` step 3 permits "2–5 distinct, mutually exclusive options" with
no floor above two, so a two-option question discharges the whole rule with one line, and the new
rule is the first thing in the pipeline to make a narrow option set cheaper than a wide one. That is
a quality regression in clarify itself, paid for in the artifact this change exists to improve. →
One sentence of counter-pressure, in the same voice as the others: an option set narrowed so there
is less to record is the same defect as an option invented so there is more — the set is what step 3
found credible, not what is convenient to write down.
