## Findings

### WARNING `wfctl/cli.py:L3319` — path printed without `soft_wrap=True`; rich folds an out-of-tree arch root mid-path

```python
console.print(f"    records: {_arch_location(root, repo_root)}/")
```

Reproduced at 80 columns with an out-of-tree `arch_root`:

```
✗ new-way: supersedes 'never-existed', which is not a record here
    records:
/private/tmp/claude-501/-Users-andremarin-Development-wfctl-wt-113-arch-validate
-in-doctor/a03b082c-63d1-44b1-bab8-487171fef7c1/scratchpad/very-long-out-of-tree
-architecture-record-root-directory-name/docs/architecture/
```

The line's own comment says the reader needs the path *because* it cannot be
guessed — and the wrapped form cannot be copied or pasted. This is a house
convention, not a preference: every path-bearing line in `cli.py` passes
`soft_wrap=True` (33 call sites), including the repair line in the sibling doctor
check fifteen lines up — `_check_spec_root_migration` at L3164, whose comment
reads "this names a path the reader is expected to act on; a wrapped path cannot
be copied" — and `_check_abandoned_entries`' path list at L3453. `arch_root_cmd`
(L916) and `_arch_location`'s own docstring already document the same hazard for
the same value.

In-tree roots render as `docs/architecture/` and never wrap, so this only bites
the out-of-tree configuration — which `arch_root` explicitly honours.

**Fix:** `console.print(f"    records: {_arch_location(root, repo_root)}/", soft_wrap=True)`

### WARNING `wfctl/cli.py:L3479–3496` — `doctor_cmd`'s docstring is the admission contract for this command, and the new check does not satisfy it as written

`doctor_cmd`'s summary line is *"Report state wfctl put in this repo that has
since drifted"*, and its rule is:

> A check belongs here when it describes something wfctl installed or seeded that
> no longer matches its source, **and can name the command that repairs it**. A
> check describing what the *user* has or hasn't done belongs wherever that work
> happens — this command runs unprompted at every session start, which makes it a
> magnet for anything you want noticed, and each arrival costs the exit code some
> of its meaning.

Architecture records are hand-authored user content, not something wfctl
installed or seeded, and `_check_arch_records` explicitly cannot name a repairing
command — its own comment says so ("The one repair is editing the records, so the
reader needs the path rather than a command"). The new docstring argues the case
against `arch context`; it never engages the rule doctor states for itself. The
next contributor applying that rule reads this check as one that should be
evicted.

Two further sentences of the same docstring are now wrong by a wider margin:

- *"Two of the checks below are freshness … and three are integrity (the teardown hook, the spec-root move, abandoned entries)"* — there are now **seven** checks (version, workmux hook, spec-root migration, verify config, arch records, abandoned entries, managed hooks).
- *"Kept together while the whole report is five lines a session; **a sixth check is the sign to split them**"* — this diff adds the seventh, and the stated trigger passes without acknowledgement.
- L3514: *"a repo can have a `.workmux.yaml` or a recorded `spec_root` … **Both** are drift"* — that list now holds four entries.

**This staleness is pre-existing** (verified on `main`: `_check_verify_config`
and `_check_managed_hooks` were already unenumerated). I am not asking this diff
to fix inherited debt — but it is the diff that pushes the count past the
docstring's own written split threshold, and it is the diff whose check the rule
excludes. Per CLAUDE.md, "comments inform the next reader of the file"; this one
now misinforms them about whether the code beneath it belongs.

**Fix:** amend `doctor_cmd`'s docstring in this diff — widen the admission rule
to cover repo state wfctl can check for internal consistency (naming the
*location* rather than a command when there is no command), correct the
freshness/integrity enumeration, and either honour or retract the "sixth check"
split trigger. Alternatively file it as a follow-up issue and say so in the PR
body — but "clean it up later" without a ticket does not count.

## Observation (not a finding)

`arch_root` defaults to `docs/architecture`, a conventional location wfctl merely
guesses at. Any repo that installed wfctl skills and keeps unrelated ADRs there
now gets a permanent `⚠` at every session start if one of them literally reads
`status: superseded`, with no way to silence it but editing files wfctl does not
own. Narrow in practice — MADR's `status: superseded by [ADR-0005]` does not
match `STATUSES` and parses to `""` — and arguably a correct warning. Noting it
because it is the exact hazard `doctor_cmd`'s docstring warns about, which is why
the WARNING above matters beyond bookkeeping.
