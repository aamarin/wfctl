## Findings

**WARNING  cli.py:L3477-3505 (`doctor_cmd` docstring) — the new check breaks the
admission rule the docstring states, and the docstring is not updated to admit
it.** Doctor says a check belongs there when it "describes something wfctl
installed or seeded that no longer matches its source, **and can name the command
that repairs it**", and that "a check describing what the *user* has or hasn't
done belongs wherever that work happens." Architecture records are hand-authored
— nothing in the CLI writes one (`_arch.supersede` still has no caller), and the
new comment concedes the point: "The one repair is editing the records, so the
reader needs the path rather than a command." The same docstring's inventory —
"Two of the checks below are freshness … and three are integrity (the teardown
hook, the spec-root move, abandoned entries) … Kept together while the whole
report is five lines a session; **a sixth check is the sign to split them**" —
now undercounts by three (version, workmux hook, spec-root, verify-config,
arch-records, abandoned, managed-hooks, content-hash = eight). Two of those three
predate this branch (`git show main:wfctl/cli.py` confirms the sentence is
unchanged), but this is the diff that adds the check the sentence is written
about, and the trigger it names has been passed. → Amend `doctor_cmd`'s docstring
in this diff: widen the admission rule to cover integrity over content wfctl
*reads* rather than only content it wrote, and either refresh the inventory or
delete the count sentence and act on the split it asks for.

**WARNING  cli.py:L3308 — this is the first doctor check that reads a directory
wfctl does not own, and it can exit 1 on a repo that never adopted the feature.**
`arch_root` defaults to `<repo>/docs/architecture`. Every other check that runs
*before* the manifest gate keys off a wfctl-owned artifact — `.workmux.yaml`,
`wfctl.json`, the manifest itself — so "not adopting the feature is not a
finding" (this test file's own words, `test_doctor_is_silent_when_no_definition_of_done_exists`)
holds for all of them. This one parses whatever `.md` files a repo already keeps
in `docs/architecture/`. Quantified: an `error` requires literally
`supersedes: <value>` in frontmatter whose value is not another file's stem —
MADR puts the successor in `status:` (`superseded by ADR-0005`, which is outside
`STATUSES` and parses to `""`), and adr-tools writes it as body prose, so neither
of the two common conventions trips it. `status: superseded` alone is more
plausible and yields only a `warning` (exit 0). So: low probability, but the
failure is a red build in a repo that never opted in, arriving through a check
that runs before the "nothing installed" gate. → Either gate the check on
adoption (`arch_root_declaration(repo_root) is not None`, or "at least one record
parsed a recognised status"), or state in `_check_arch_records`' docstring why
the default path is treated as wfctl's ground when `_scan_owns` goes to
considerable trouble to avoid exactly that assumption for `.claude/skills`.

**NIT  cli.py:L3294-3296 — the docstring's opening narrates the change rather

**NIT  cli.py:L3306 — `for f in findings` → `for finding in findings`.** One-char

## Things checked and found sound (not findings)

- **Exit-code contract (#41).** `any(f.level == "error" …)` is the whole rule;
  warnings print and return `False`. `_check_arch_records` sits inside the list
  (not `or`-chained), so it runs even when an earlier check already found drift —
  matching the comment's stated reason for the list form.
- **VR-002 noise at session start.** `.agents/skills/start-session/SKILL.md:48`
  says "check it is green before moving on", and a VR-002 ⚠ is by design
  repairable only by a human editing records — so it would sit in the report for
  the duration of a review. I chased this and am not raising it: the split-across-
  branches state VR-002 warns about needs the *predecessor* merged as
  `superseded` while the successor is still unmerged, and `#121 item 3` puts both
  records in one branch diff, so it is a rare shape. `_warn_missing_bootstrap`
  and the "installed before content hashing" line already set the precedent of a
  ⚠ that does not move the exit code.
- **`arch none` interaction.** Declarations land in `declarations/`, records in
  `design/` — neither is reached by `load_records`' one-level glob, so no
  false VR-003 from a declaration filename.
- **Test quality.** All three names are sentences; all three docstrings say why
  the test exists rather than restating the assertion, and the first one names
  the exact defect class ("a test that calls `validate()` proves nothing about
  that") — which is the right call, given the bug was a missing call and not
  broken logic. Going through `doctor` rather than `validate()` is what makes
  them regression tests for #113 rather than more of the coverage that already
  existed.
- **Coverage gap I decided not to flag.** No doctor-level test for VR-004 or
  self-supersession. Both are `error` and share the exact code path VR-003
  exercises, so a test for them would prove nothing the dangling test does not.
