## Findings

BLOCKER  wfctl/_entry.py:L29, wfctl/cli.py:L3638 — `sys.stdin.read()` moved *outside*
the `try`, so undecodable stdin now raises `UnicodeDecodeError` and the hook exits 1
with a traceback where HEAD exited 0 silently → read stdin inside `_hook`, e.g. add
`def guard_from_stdin() -> int:` there wrapping the read in the existing
`except (json.JSONDecodeError, UnicodeDecodeError): return 0`, and call it from both
doors; or pass `sys.stdin.buffer.read()` (`json.loads` accepts bytes and raises the
same `UnicodeDecodeError`, restoring HEAD byte-for-byte).

Evidence — reproduced in this worktree, both doors:

```
$ printf '\xff\xfe not utf8' | uv run python -c \
    "import sys; sys.argv=['wfctl','hook','worktree-guard']; from wfctl._entry import main; main()"
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xff in position 0
EXIT=1
$ printf '\xff\xfe' | uv run python -c \
    "from wfctl.cli import hook_worktree_guard_cmd as c; c()"
RAISED UnicodeDecodeError
```

On HEAD the read was `json.loads(sys.stdin.read() or "{}")` *inside* the try, and
`UnicodeDecodeError` is in the except tuple precisely because a `str` argument to
`json.loads` cannot raise it — the only thing that could was the read. After the move
that except clause is unreachable dead protection, while `_hook.py:L64-69` still
documents the protection as present ("a traceback from it reaches the agent as a hook
error on work that had nothing wrong with it"). This violates the stated constraint
that the exit codes and the payload contract are unchanged. Triggering it needs bytes
stdin cannot decode under the process locale — improbable per-call, but locale-shaped
rather than random: in an environment where it happens it happens on *every* Bash
call. Cost to fix: three lines.

WARNING  wfctl/cli.py:L3405 — `_worktree_roots` is now a dead shim with no caller
anywhere in the repo, and its docstring ("this name stays because it is what the tests
and the hook command both call") is false on both counts: `tests/test_guard_entry.py`
patches `wfctl._hook.worktree_roots`, `tests/test_worktree_guard.py` never names it,

**1. Correctness.** Diffed the moved code against HEAD statement by statement — the
payload parsing, the type guards, the `cwd` fallback, the stderr write and the exit
codes are byte-identical apart from `return`/`raise` (found: the stdin read is the one
statement that changed position, and that is the blocker). Verified the early-out is
sound: `_guard._ABS_PATH` is `/[^\s'"`;|&<>()]+`, so a command with no `/` produces no
match in any segment, `refusal()` returns `None` for every root set, and the
`_WRITE_REDIRECT` branch is only reachable after a trespass is found — `"/" not in
command` is exactly equivalent to the work it skips, and it sits above `worktree_roots`
as required. Checked argv edge cases: `[]`, extra positional args, `--help`, and shell
decoration in a settings entry (`… 2>/dev/null || true`, as this repo's own hooks are
written) all leave `sys.argv[1:]` either exactly `["hook","worktree-guard"]` or falling
through to typer. `wfctl/__init__.py` is empty, so the fast path drags in nothing
implicitly. Confirmed the two doors emit identical refusal text (`cmp fast.err
typer.err`).

**2. Security.** The guard is itself a security-shaped control, so the question is
whether the fast path weakens it. It does not: the same `_guard.refusal` decides, the
payload is still treated as untrusted (`isinstance` on the dict, on `tool_input`, on
`command`), no field is interpolated into a shell, `worktree_roots` still passes
`["git", "-C", cwd, …]` as a list with no `shell=True`, and nothing is logged. The
early-out cannot be used to smuggle a trespass, per the `_ABS_PATH` argument above.
The one direction it *does* fail is the blocker: a payload that used to fail closed-
and-quiet now fails loud.

**3. Architecture.** Two surface modules instead of one is a real widening, and the
view's added section owns it honestly, including the membership test it costs. Import
direction stays one-way (`_entry` → `_hook` → `_guard`; `cli` → `_hook`), no cycle.
`tests/test_architecture_view.py:114` enforces that the modules and the ```layers block
agree, so the doc edit was required, not decorative — it passes. The remaining
duplication is `cli._worktree_roots` (see WARNING).

**4. Readability.** Names read straight; comments explain why-this-shape, per the repo

naming callers that no longer exist; `_hook.worktree_guard` describing defensive
