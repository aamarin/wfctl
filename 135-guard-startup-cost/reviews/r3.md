# Review (r3): #135 — guard startup cost, working tree of `135-guard-startup-cost`

Target: `git diff HEAD` + the three untracked new files (`wfctl/_entry.py`,
`wfctl/_hook.py`, `tests/test_guard_entry.py`), as supplied in `TARGET.diff`.
All six passes run. Findings first; what each pass checked and what I measured
is at the bottom.

## Findings

WARNING  wfctl/_entry.py:L29 (and wfctl/cli.py:L3638) — `sys.stdin.read()` moved
*outside* the `try` that used to wrap it, so a payload that does not decode in
this process's stdin encoding now raises instead of returning 0. On `main` the
read was inside the block: `try: payload = json.loads(sys.stdin.read() or "{}")
except (json.JSONDecodeError, UnicodeDecodeError): return`. The
`except UnicodeDecodeError` survived the move into `_hook.py:L73` but is now
**dead** — `json.loads` on a `str` cannot raise it — so the docstring above it
("a payload this code cannot read describes no command") claims a defence the
code no longer has. Reproduced end-to-end against the installed console script:

```
$ printf '\xff\xfe' | .venv/bin/wfctl hook worktree-guard
Traceback (most recent call last):
  File ".../.venv/bin/wfctl", line 10, in <module>
    sys.exit(main())
  File ".../wfctl/_entry.py", line 29, in main
    raise SystemExit(worktree_guard(sys.stdin.read()))
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xff in position 0
exit=1
```

and, with a stdio encoding that is not UTF-8, on an entirely ordinary command —
`git commit -m "fix — dash"` under `PYTHONIOENCODING=ascii` tracebacks on the
em dash. `LC_ALL=C` is safe (PEP 538 coerces to UTF-8), which is why this is a
WARNING and not a BLOCKER: it is unreachable under a default locale and it fails
*open* (exit 1 is non-blocking), so the cost is a hook error printed on work that
had nothing wrong with it — exactly the failure the comment that was moved says
this block exists to prevent.

→ Fix: hand the guard bytes and let `json.loads` do the decoding, which both
restores the old behaviour and makes the retained `except` live again:
`worktree_guard(sys.stdin.buffer.read())` in both callers, signature
`stdin_text: str | bytes`. Verified on 3.11.14: `json.loads(b'\x80\x81')` and
`json.loads(b'{"a": "\xff\xfe\xfd"}')` both raise `UnicodeDecodeError`, and a
`str` argument still works, so `tests/test_guard_entry.py` needs no change. (A
`try/except` around each read is the alternative; it duplicates the handler in
two callers, which is what the bytes form avoids.)

WARNING  tests — nothing exercises `_entry.main` with a payload. The only
end-to-end exit-2 test, `tests/test_worktree_guard.py:L307`, drives
`runner.invoke(app, ["hook", "worktree-guard"])` — the typer door, which the
diff's own docstring says "in practice … does not run". `test_guard_entry.py`
covers the *decision* in-process, the `--help` fall-through, and the pyproject
string, but never the assembled path. That gap is not theoretical: the finding
above lives precisely in it, and the whole suite (1122 passed) is green with it.
→ Fix: one subprocess test that feeds a refusing payload to the dispatcher and
asserts exit 2 plus the message on stderr —
`subprocess.run([sys.executable, "-c", "import sys; sys.argv=['wfctl','hook','worktree-guard']; from wfctl._entry import main; main()"], input=payload)`
— which does not depend on the console script having been re-installed.

WARNING  wfctl/_hook.py:L87 — the `"/" not in command` early-out is correct today
*because* of `_guard._ABS_PATH` (`r"/[^\s'\"`;|&<>()]+"`), and nothing on the
`_guard` side records that dependency or tests it. `_guard`'s docstring already
names relative paths (`../105-mypy-cold-venv/AGENTS.md`) as a known gap and #137
tracks closing part of it; the day `refusal()` learns to judge anything that
contains no `/`, this early-out silently disables it and every test in
`test_worktree_guard.py` still passes, because they all call `refusal()` directly.
The nearest existing test, `test_a_command_naming_no_worktree_is_never_examined`
(L292), uses `rm -rf /tmp/scratch` and `uv run ruff check wfctl/` — both contain
a `/`, so neither pins the invariant.
→ Fix: assert the invariant where it lives — a case in `tests/test_worktree_guard.py`
(`assert _guard.refusal("rm -rf ..", HERE, ROOTS) is None`, named for the
early-out that depends on it), plus a line beside `_ABS_PATH` saying `_hook`
relies on `/` being necessary for any refusal.

WARNING  wfctl/cli.py:L3405-L3414 — `_worktree_roots` is now dead, and its
docstring says otherwise: "This name stays because it is what the tests and the
hook command both call." Neither is true after the change. `grep -rn
"_worktree_roots"` over the repo returns exactly one hit, its own definition; the
hook command calls `_hook.worktree_guard`, which calls `_hook.worktree_roots`,
and `tests/test_guard_entry.py` patches `wfctl._hook.worktree_roots`. Under the
project's comment rule this is worse than plain dead code — it will send the next
reader looking for callers that do not exist.
→ Fix: delete the function (−10 lines). If it is being kept as a deliberate
alias, the docstring has to name the caller that justifies it.

NIT      tests/test_guard_entry.py:L65-L71, L86-L94 — hand-rolled patching
(`original = hook.worktree_roots` / `try` / `finally`) with two
`# type: ignore[assignment]` and a `(calls.append(cwd), ("", []))[1]` tuple-index
lambda, which is the "clever trick that needs a mental pause" the rubric names.
Other tests in this suite use the fixture (`tests/test_hook_user_prompt.py`,
`tests/test_shape.py`, …).
→ Fix: `monkeypatch.setattr(hook, "worktree_roots", lambda cwd: calls.append(cwd) or ("", []))`
— restores automatically, drops both ignores, −8 lines across the two tests.
Also, one appends `[cwd]` and the other `cwd` for no reason; make them the same.

NIT      tests/test_guard_entry.py:L105 — `Path(sys.executable).parent / "wfctl"`
passes for the wrong reason in a stale environment: a console script still
generated from `wfctl.cli:app` answers `--help` identically, so the test asserts
nothing about the dispatcher it is named for. Same fix shape as the coverage
finding — drive `_entry.main` with a patched `sys.argv` in a subprocess and keep
the console-script variant only if you want to assert the install is current.

NIT      worktree root — `fast.err` and `typer.err` are untracked, not gitignored,
and would be swept up by a `git add -A`. They are good evidence (I ran `cmp`:
byte-identical, so the refusal text constraint held across both doors) — quote
them in the PR and delete the files.

NIT      follow-up, not this diff — the path-bearing case still pays two `git`
subprocesses. Measured here: `rev-parse --show-toplevel` 9.2 ms, `worktree list
--porcelain` 9.9 ms, and the guard costs 62.9 ms with a path against 27.8 ms
without one. `here` is derivable from the porcelain listing by longest-prefix
match on the resolved cwd (`_guard._owner` already does that shape), which would
drop one of the two. Non-trivial because of symlinked paths (`/tmp` vs
`/private/tmp`), so file it rather than smuggle it in.

net: −18 lines possible (dead `_worktree_roots` −10, test patching −8), before
the two tests the findings above ask for.

**Verdict: Request changes** — no blocker, but the stdin-decode regression is a
one-line fix and the missing end-to-end test is what let it through.

## What each pass checked

**Correctness.** Traced `_entry.main` → `_hook.worktree_guard` → `_guard.refusal`
against the pre-change body (`git show main:wfctl/cli.py`) field by field: the
JSON parse, the `isinstance` ladder on `payload` / `tool_input` / `command`, the
`payload.get("cwd") or "."`, the `if not here` fail-open, and the exit codes.
Only one difference found (the WARNING above). Exercised the shipped path
directly: refusing payload → exit 2 with the message on stderr, allowing payload
→ 0, `command: 123` → 0, `not json` → 0, `[]` → 0, empty stdin → 0. The `"/"`
early-out is sound against today's `_ABS_PATH`, which is anchored on a literal
`/`, so `refusal()` could not have returned a message for those commands.
Confirmed `--help` still reaches typer (exit 0) and that a *longer* argv falls
through, which is what the exact-match `_GUARD_ARGV` buys.

**Security.** No new input surface: same untrusted stdin, still parsed with
`json`, still defended by the type ladder. `subprocess.run` is list-form, no
`shell=True`; the payload-controlled `cwd` reaching `git -C` is unchanged from
`main`. The `"/"` early-out cannot widen the allow set, because a command with no
`/` matched no path before either. Refusal text unchanged (`_guard._message`
untouched; `cmp fast.err typer.err` identical).

**Architecture.** `_entry` (surface) → `_hook` (surface) → `_guard` (domain) flows
one way; no cycle, and `wfctl/__init__.py` is empty so the fast path drags in
nothing. `docs/architecture/views/current-state.md` was updated in the same diff
and `tests/test_architecture_view.py` — which parses the ```layers block and
compares it against the modules on disk — passes. The one-console-script,
argv-dispatch choice is argued in the module docstring and is the right call
given `wfctl hook worktree-guard` is written into consumers' settings and quoted
at `README.md:435`; a second script name would strand those.

**Readability.** Comments explain *why* throughout and match the house style. Two
exceptions, both filed: the false docstring on `cli._worktree_roots`, and the
tuple-index lambda in the tests.

**Performance.** Measured on this machine (20 iterations each, warm, via the
installed console script): guard with no path in the command **27.8 ms** against
a **24.9 ms** bare-interpreter floor; guard with a path 62.9 ms; `wfctl
--version` (the CLI door) 97.2 ms. `-X importtime`: `wfctl.cli` 61.9 ms
cumulative (typer 30.8, rich.console 20.1) versus `wfctl._hook` 1.4 ms. So both
halves of the change are real and the dominant case — no path named — now costs
essentially interpreter startup. Acceptance (a) holds: verified no `git`
subprocess runs for a path-less command.

**Over-engineering.** The diff is a net simplification of `cli.py`. Nothing
speculative: `_entry` holds one branch, `_hook` holds the code that already
existed. The only removable thing is the dead re-export.
