### Findings

BLOCKER  wfctl/cli.py:L1605-L1606 — The overlap check resolves the state dir outside any `try`, so a bad state dir now lets the removal go ahead and deletes the untracked files. On Python 3.11, `Path.resolve()` raises `RuntimeError` on a symlink loop, and `is_inside` catches only `ValueError`. The error reaches the hook's catch-all, which exits 0. I reproduced this with `WFCTL_STATE_DIR` set under a looped symlink and an untracked `notes.md` in the worktree. With no plain spec folder, the hook prints "✗ couldn't save unsaved files ([Errno 62] Too many levels of symbolic links ...) — removal stopped, nothing lost" and exits 1. With a plain spec folder, it prints "⚠ worktree-remove failed (Symlink loop from '.../la/state') — continuing so the removal is not blocked" and exits 0, and workmux then deletes `notes.md`. The comment above the call says it avoids creating the state dir for this exact reason, but resolving the path can fail the same way. The trigger is narrow. Even so, this is the one outcome the hook must never produce, and the same machine stopped safely before this change. → Wrap the check in `try` and, on `(OSError, RuntimeError)`, return the copy line with `[spec_dir]`, so `_save_unsaved` meets the same failure inside its own `try` and stops the removal. Another option is to run the overlap check inside `_save_unsaved`'s `try`. Add a hook test with a looped `WFCTL_STATE_DIR` that asserts exit 1.

WARNING  wfctl/_archive.py:L365 — A relative spec dir outside the worktree is treated as inside it, so the copy lands outside `unsaved/` and every later removal of the branch stops. The rule `not path.is_absolute() or is_inside(...)` assumes any relative path is relative to the worktree. However, `spec_root` returns `Path(WFCTL_SPEC_DIR)` unanchored, so `WFCTL_SPEC_DIR=../plain-specs` gives `Path("../plain-specs/56-x")`. That path goes through `_relative` unchanged, and `copytree(worktree / rel, staging / rel)` writes it to `<state>/plain-specs/56-x`, beside `unsaved.staging` rather than inside it. I reproduced this through the hook with the worktree as the working directory. The first run exits 0 and prints the "a copy is saved with the unsaved work" line. "✓ saved 1 file" then lists only `notes.md`, and the spec copy sits at `<state>/plain-specs/56-x`, where nothing reports it. The second run fails with "File exists: '.../unsaved.staging/../plain-specs/56-x'" and exits 1. Every later removal of that branch stops the same way until someone deletes the stray folder. From any other working directory, `worktree / rel` reads a different folder from the one `resolve_spec_dir` found. → Have the hook pass an absolute path: return `[spec_dir.absolute()]` from `_plain_spec_dir_backup`, or resolve `extra` once at the top of `save`. Add a test with a relative `WFCTL_SPEC_DIR`.

WARNING  docs/architecture/spec-storage-read-from-git.md:L66 — The accepted record still says "A plain folder outside any repository is not backed up anywhere, and removal says so instead of calling it durable." After this change, removal saves a copy and prints a different line. The record has a Log, and #359's revision added a `revised` line for a change of the same kind. → Update consequence 1 to say removal copies the folder into `unsaved/` and that a failed copy stops the removal, and add a `revised — #56 ...` line to the Log.

NIT  wfctl/cli.py:L1597-L1598, tests/test_worktree_remove.py:L556 — The reason given for the overlap rule doesn't hold for the case its own test covers. The test puts the spec dir at `state/specs/<branch>`. The copy goes to `state/unsaved.staging/<branch>`, which isn't inside the source, and the source isn't inside the copy. The real hazards are a spec dir under `unsaved/` or `unsaved.staging/`, which the save renames aside or deletes with `rmtree`, and a state dir inside the spec dir, where `copytree` walks into its own output. A later reader who trusts the stated reason could narrow the rule and reach one of those cases. → Name those two cases in the docstring and in the test's docstring.

NIT  tests/test_worktree_remove.py — Only half of the overlap rule is tested. No test puts the state dir inside the spec dir, so deleting `or _archive.is_inside(spec_dir, state)` leaves the suite green. → Add one test with `WFCTL_STATE_DIR` under the spec dir.

NIT  wfctl/cli.py:L1612 — "a copy is saved with the unsaved work" prints before the save runs. When the copy fails, the next line is "✗ couldn't save unsaved files", which contradicts it. → Use "a copy goes into `unsaved/` with the unsaved work", or similar wording that doesn't claim the save already happened.

NIT  wfctl/cli.py:L1750 — `lines[0], extra = _plain_spec_dir_backup(...)` assigns to a list item and a local in one tuple unpack. It also relies on `report_lines` returning exactly one line for `not_applicable`. → Use `line, extra = ...` and then `lines = [line, *lines[1:]]`, or two plain statements.

NIT  wfctl/_archive.py:L3-L11 — The module docstring still says `save` copies the untracked files and the `save_on_remove` folders, and that spec files are the store's job. A plain spec folder now goes through `save` as well. → Add one sentence about it.

NIT  wfctl/_archive.py:L382 — shrink: `name` is always a single path component, so `p in name.parents` is true only when `p == Path(".")`. → Drop that clause.

NIT  wfctl/_archive.py:L366 — yagni: the `outside` dict is keyed by folder name, so two outside folders with the same name would silently keep one. That is the loss the clash check exists to prevent, although no caller passes two today. → Use a list of `(name, src)` pairs, or extend the clash check to compare outside folders with each other.
