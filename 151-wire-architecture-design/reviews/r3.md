## Findings

**WARNING** `wfctl/agents/commands/speckit.implement.md:4` — the change's own
stated reason for the mirror is a route whose tool ceiling it does not open.
`cli.py:2363-2366` justifies membership by "a boundary that may be moving …
surfaces mid-implementation as readily as inside a design pass", and the new
test docstring (`tests/test_skill_cross_references.py:123-125`) repeats it: "the
mirror reaches one that did not [descend through `design-levels`], which is how
a boundary question arriving mid-implementation gets answered by the method".
`speckit.implement.md`'s `allowed-tools` is `Read Glob
Bash(.specify/scripts/bash/check-prerequisites.sh*) Bash(git rev-parse*)
Bash(wfctl feature-paths*)`. So an agent that discovers the skill through the
mirror mid-implementation is refused at *Authority* ("Read the in-force set
through `wfctl arch context` … A record found any other way is not in force")
and refused again at step 6's handoff, which needs `wfctl arch-root`, `wfctl
arch check`, `Write` and `git add`/`git commit`. This is exactly the principle
the same commit's docstring states — "a step added to the prose without its
command is a step that reads correctly and cannot run" — applied to only one of
the two routes it opened. → Either grant the method's commands in
`speckit.implement.md` too, or drop "mid-implementation" from the cli.py comment
and the test docstring and justify the mirror on the free-session route (no
command, no ceiling), which is the one that actually works.

**WARNING** `wfctl/agents/skills/architecture-design/SKILL.md:3` — the mirror
puts the skill on Claude's discovery path, and discovery matches the
*description*, which scopes both of its triggers to level 2: "Use **during
design-levels level 2** when a feature may draw or move a component boundary …,
or when it must preserve a quality under stated conditions." An agent
mid-implementation is not in `design-levels` level 2, so the description
actively argues against the match the mirror was added to produce. Both siblings
in `_MIRRORED_SKILLS` write the unscoped form for precisely this case —
`architecture-decisions`: "Use when a decision that is expensive to reverse has
just been made in conversation"; `software-design-decisions`: "Use when a
structural choice was settled in conversation". → Add an unscoped trigger
sentence to the description, e.g. "Use when a boundary, ownership rule or public
contract is about to be drawn or moved and no accepted record settles it —
including mid-implementation, when the question arrives outside a design pass."
Without it, the second route is declared in a Python frozenset and denied in the
file the route reads.

**WARNING** `wfctl/agents/skills/design-levels/SKILL.md:128-129` — "Skip it
**only** when the boundary is already settled in an accepted record or an
existing spec" is a closed set of one, and it omits the two cheaper exits the
surrounding text already grants. Nine lines further down the same section says
"If the level introduced no boundary, declare that — 'no boundary drawn, no
record' — and descend", and `speckit.brainstorm.md:137` makes that an actual
command (`wfctl arch none --reason`). `architecture-design`'s own *When to use*
goes further still: "**Not for**: bug fixes, copy edits, dependency bumps,
naming, refactors that move no boundary … running this method over one costs
more than the change." An agent reading `design-levels` top-down meets the
"only" before it meets either escape, and with #161 still open there is no cheap
route to fall back on — so the literal reading taxes every level-2 pass with a
driver-ranking iteration to discover there was nothing to rank. → Widen to name
the discriminator rather than one artifact, e.g.: "Skip it when an accepted
record or an existing spec already settles the boundary — name the one that does
— or when nothing about the change moves a boundary, which is the declared
absence below. The test is whether a boundary moves, not how large the change
is."

**WARNING** `wfctl/agents/skills/design-levels/SKILL.md:127` — "hands back one
proposed boundary — which the skill below turns into a record" is wrong twice.
(1) It is one of three outcomes `architecture-design` §6 defines; the other two
are "declare **no record** and return to `design-levels`" and "name what must be
checked and stop. Ask the human rather than proceeding on the weaker evidence."
The stop-for-evidence outcome is the one that matters most under
`auto_approve`, and a reader of `design-levels` alone never learns it exists.
(2) It contradicts who performs the handoff: `architecture-design`'s diagram
(`SKILL.md:18-22`) and §6 both have that skill invoking
`.agents/skills/architecture-decisions` itself ("invoke
`.agents/skills/architecture-decisions` and hand it one proposed ownership
decision"), while this sentence has it handing back to `design-levels`, whose
next paragraph then invokes the record skill. Both accounts followed literally
is two invocations for one boundary. → State the three outcomes and pin the
handoff to one owner, e.g.: "It ends in exactly one of three ways — no boundary
(declare the absence below), missing evidence (name it and stop), or one
proposed boundary, which it hands to `.agents/skills/architecture-decisions`
itself. The next paragraph is what that skill then does." Also name the skill by
path rather than as "the skill below": the positional pointer breaks on reorder,
and `_REFERENCE` cannot see it.
