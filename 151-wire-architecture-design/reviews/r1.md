### WARNING — `cli.py:2360`: the mirror entry's justification is undone by the skill's own description

The comment justifies the entry this way:

> Its description triggers on a boundary that may be moving, which surfaces
> mid-implementation as readily as inside a design pass — and an agent that
> arrives there without having read the gate has no other route.

The test docstring makes the same claim (`test_the_design_method_skill_is_model_invocable`,
"the mirror reaches one that did not [descend through design-levels], which is
how a boundary question arriving mid-implementation gets answered by the method").

`.claude/skills/` discovery matches on the `description` frontmatter. That
description reads:

> Run one driver-to-structure architecture design iteration and hand a proposed
> boundary decision to architecture-decisions. **Use during design-levels level 2**
> when a feature may draw or move a component boundary…

and the body reinforces it: *When to use* opens "Use this skill **when level 2 is
active** and the change may:". So the agent the mirror exists to reach — one
mid-implementation who never read `design-levels` — reads a trigger that scopes
the skill to a pass it is not in, and self-excludes. The mirror puts the file on
the discovery path; the description takes it back off.

This is exactly why the precedent cited does work. `software-design-decisions`'
description is deliberately unscoped — "Use when a structural choice was settled
in conversation and only the resulting code would record it" — it names the
*moment*, not the pipeline stage. `fanning-out-code-review` and
`conversation-response-shape` are the same shape. `architecture-design` is the
first mirrored entry whose description gates on a stage.

Two honest fixes, either closes it:

- **(a)** Add one unscoped trigger to the description, e.g. "Use when a boundary
  question surfaces outside a design pass and the answer forming is a structure
  rather than a driver." Then the comment's claim is true and the entry earns its
  keep. Note this widens a description that ships to every repo, so it is the
  larger change.
- **(b)** Keep the entry and narrow the justification to the route it actually
  opens — an agent that read `design-levels` and reaches for `Skill(architecture-design)`
  rather than a path, which is the `start-session`/#204 failure and is enough on
  its own. Then delete the mid-implementation sentence from the comment and from
  the test docstring.

The entry itself is right either way. It is the stated reason that is not yet
true, and CLAUDE.md is explicit that comments here carry rationale — a rationale
that does not hold is worse than none, because the next reader will rely on it
when deciding whether the entry may be dropped.
